# 团队工作台

Windows 本地 Agent 工作台与独立的团队管理应用。远端使用 Linux 账号、SSH/SFTP 和文件系统，无常驻业务服务。当前版本 **0.3.0**。

## 两个应用

| 应用 | 当前功能 | 本机数据目录 |
| --- | --- | --- |
| Team Agent User 用户版 | 必填工作路径与远端权限验证、子管理员创建项目、Cursor / Codex 会话、共享文件、成果提交和会话归档 | `%APPDATA%\TeamAgentUser` |
| Team Agent Admin 管理员版 | 用户创建、密码重置、启停账号、用户组、工作目录准备、项目子管理员任命 | `%APPDATA%\TeamAgentAdmin` |

两个应用可同时运行，拥有不同的安装标识、快捷方式、入口、IPC 接口和配置目录。用户版不包含管理员 Python 程序、用户管理接口或“切换管理员”按钮。

管理员版识别两种身份：

- **总管理员**：以服务器已有 root 或 sudo 账号登录，经远端实际权限验证后进行用户管理。
- **项目子管理员**：以总管理员创建的个人账号登录，从服务器 root 拥有且普通用户不可修改的任命记录中读取所属项目。可以在用户版的授权工作路径下创建项目，不能调用用户管理接口；管理员版会提示其使用用户版进行项目操作。

**本版已实现子管理员创建项目及轨迹目录，完整的内容编辑、整理与权限编辑界面仍未开放。** 总管理员创建用户组时会准备该组工作目录及基础 Linux ACL。成员可进入该工作目录，只有内容子管理员组可在其中创建项目。

## 安装与迁移

产物位于 `release/admin` 和 `release/user`：

- `TeamAgent-admin-0.3.0-x64.exe`：管理员版安装程序。
- `TeamAgent-user-0.3.0-x64.exe`：用户版安装程序。
- 同名 `.zip`：免安装目录压缩包，**解压全部文件**后运行 `Team Agent Admin.exe` 或 `Team Agent User.exe`。

支持 Windows x64；当前在 Windows 11 验证。安装包未配置企业代码签名证书。安装程序可选择安装位置，卸载默认保留用户数据。两版运行都无需预先安装 Node.js；用户版包含 Cursor Agent 与 Codex CLI 运行文件，管理员版不包含模型运行文件。

迁移到其他电脑只需复制对应安装包或完整的免安装压缩包，重新配置服务器并登录个人模型账号。不会把开发者的账号、密码、工作记录打进安装包。

## 第一次连接

两个应用首次启动时打开连接对话框。用户版必须同时填写已存在的 Windows 本机工作路径和 Linux 工作路径；后台使用登录账号实际检查远端目录是否存在、是否为目录、能否进入及打开。验证失败或取消配置时停留在设置页面，主进程也拒绝创建会话等工作操作。首次成功验证后，本地使用资格随本机工作路径保存；以后可离线启动并使用会话、交接文件和草稿，重新连接失败也不会锁住本地工作。远端文件操作仍需重新连接并由 Linux 实际校验权限，本地记录不替代远端授权。地址、端口、Linux 账号、工作路径和服务器指纹可保存；登录密码和 sudo 密码只保留在本次连接的内存中，不落盘，不进入模型 prompt。修改信息后重新连接即可生效。

管理员版通过左下角 **连接设置** 修改，用户版通过右上角服务器按钮修改连接及两个工作路径。首次连接需要与运维核对 SSH SHA256 主机指纹；已有指纹不匹配时拒绝连接。换服务器后重新核对。

总管理员需要服务器已经存在的 root 或 sudo 管理账号。Windows 的管理员身份、安装顺序、应用名称都不能赋予 Linux 管理权限。普通成员仅需要服务器分配的个人账号。

## 总管理员操作

1. 输入 SSH 地址、端口、管理账号、密码和团队根路径，例如 `/srv/teamspace`。sudo 密码与登录密码相同则留空。
2. 首次点击 **初始化账号管理**：要求指定路径不存在或为空，创建账号登记、专用成员组和 root 保护的元数据目录。已有团队使用原路径，不重新初始化。
3. **配置接入规则**：明确确认后，将本团队成员组限定为密码认证的 `internal-sftp`，以团队根路径为 chroot，禁止终端和端口转发。工具先执行 `sshd -t`，再重载 SSH 服务；校验/重载失败恢复原配置文件。
4. **创建用户**：填写 Linux 账号、姓名和初始密码。密码至少 8 位，不能有冒号、换行或空字符。工具不接管已有 Linux 账号，不自动创建 root/sudo 管理员。将初始凭据通过公司的既有渠道交给本人。
5. **创建用户组**：例如 `ocr`，生成带团队前缀的普通成员组和内容子管理员组，并准备 `/srv/teamspace/projects/ocr` 工作目录。需要服务器安装 acl 软件包。对于旧版本创建的组，在组卡片点击 **准备工作目录**；不会接管已有非空目录。界面显示提供给成员的 SFTP 路径 `/projects/ocr`。
6. 在用户行点击 **组与子管理员**：选择成员所属组，并按项目任命内容子管理员。
7. 成员开通状态会显示缺少的步骤。创建时也可一次选定用户组与子管理员角色；开通完成后点击 **导出连接配置**，选择项目组，向成员交付不含密码的 JSON。成员在用户版导入后选择本机路径并输入单独获得的初始密码。
8. 重置密码、停用账号或调整组成员时，旧的远端会话/进程会被终止，以便新密码、禁用和组权限立即生效。这些账号应专用于团队共享；本地 CLI 会话不因此结束。

每个管理操作都经 SSH 发送固定程序与结构化输入，调用 `useradd`、`usermod`、`groupadd`、`gpasswd`、`chpasswd` 等系统命令。密码经加密连接的 stdin 传递，不插入远端命令参数。服务器上的操作以锁串行执行，登记文件以替换方式写入。Linux 多步操作不是事务；工具会记录不含密码的操作意图、预留 UID/GID 和已完成步骤，失败后刷新实际状态并显示“待恢复操作”。点击“继续完成”按登记身份恢复；密码相关操作需重新输入密码，身份发生变化则拒绝接管。初始化在 /var/lib/team-agent-workbench/bootstrap 中保留受保护的早期恢复记录。

账号登记：`<团队根路径>/.workbench/admin/state.json`；操作日志：同目录 `audit.jsonl`；子管理员入口任命：`<团队根路径>/.workbench/roles.json`。后者没有密码，root 拥有、成员只读；客户端还检查它及父目录的属主、写权限和符号链接。各项目实际读写仍由 Linux 文件权限控制。

服务器要求：Linux、Python **3.9+**、OpenSSH、shadow/passwd 用户管理命令、procps、acl（setfacl）。SSH 规则自动配置另外需要 systemd，以及主 sshd_config 中已启用 `/etc/ssh/sshd_config.d/*.conf` 的 Include。需要输入 TTY 的 sudo 策略暂不支持。不同发行版的 SSH/PAM 策略请由运维确认。

## 共享目录和用户版入口

总管理员准备项目组工作目录并分配组成员/子管理员。用户在首次连接时填写该工作路径，例如 `/projects/ocr`，通过 Linux 访问验证后进入工作台。项目子管理员会看到“创建第一个项目”或团队文件标题旁的加号，普通成员没有创建入口；后台每次创建时重读受保护的任命记录，SFTP 目录权限仍独立执行。

输入项目名（支持中文）后，目录结构例如：

```text
/projects/ocr/实体抽取/
├── .workbench-project.json
├── trajectories/                 # 会话轨迹
│   └── alice/                    # 首次上传时按账号自动创建
└── submissions/                  # 用户确认提交的成果
    └── alice/
```

创建时排他地保留项目目录名；同名目录不覆盖。轨迹与成果子目录准备完成、元数据写好后才发布项目。失败时只尝试删除本次创建的空目录，不删除已有项目内容。成果账号目录为 2750、成果文件为 0640，同组可读且不可覆盖；轨迹账号目录为 0700、轨迹文件为 0600。上传默认使用固定项目的个人路径。原作者重新连接时自动修复自己的旧成果目录和普通文件权限，轨迹隐私不变。

其他成员进入相同工作路径时会发现新项目；可点击“刷新项目入口”，或重新连接。输入某个已创建项目的路径也可直接使用该项目，此时没有在项目内部继续创建项目的入口。新建项目中的共享内容按组协作，Linux root 保留系统权限；本版不是不可变/防篡改轨迹存储。

旧版手动配置项目仍可使用，但入口必须位于本次验证的 Linux 工作路径内。自定义存量目录和更复杂 ACL 策略可由运维按 `examples/README.md` 配置。

新项目无需手填项目 JSON。用户版也可导入 `examples/member-connection.json` 格式的旧目录配置，或者在连接对话框的高级区域填写项目入口。配置只有路径提示，不赋予文件权限。

启用本工具的 chroot 规则后，服务器 `/srv/teamspace/projects/ocr` 在成员 SFTP 中显示为 **`/projects/ocr`**。不能把 chroot 外部的服务器绝对路径直接用作 SFTP 路径。

用户版连接后，左侧按项目显示目录。文本、Markdown 和常见图片可预览，其他格式下载查看；手动刷新或每 30 秒刷新当前目录。**加入当前会话**会下载选中文件快照，下一次发送时把来源、快照路径和 SHA256 加入 prompt。不会自动把整个共享空间喂给模型。

## CLI 登录状态（0.2.1）

新建会话时选择 **Codex · GPT** 或 **Cursor**，会自动检测该 CLI 在所选工作目录下的登录状态。CLI 设置中也分别显示程序是否存在和账号状态：

- **已登录**：CLI 返回个人登录；**凭据已配置**：沿用 API Key 等已有配置，未宣称已验证模型服务或额度。
- **未登录**：未检测到凭据或明确返回登录过期。点击 **登录个人账号**，在 CLI 打开的浏览器里授权；完成后工作台自动重新检测，再创建会话。
- **检测失败**：网络、代理、证书、CLI 版本或配置异常。不会因此认定账号未登录；修复后点击 **重新检测**。
- **无需 OpenAI 登录**：Codex 当前服务配置明确不要求 OpenAI 认证，保留其既有行为。

登录可取消，重复点击不会创建多个登录进程；五分钟未完成会停止等待。浏览器未自动打开时，可点击检测到的官方 **打开登录网页**。工作台不保存登录命令的原始输出或令牌；登录链接仅在内存中暂存。凭据仍由各家 CLI 自行管理。

新建会话和发送任务前，主进程也会检查认证；认证失败时不发送任务，并保留输入框内容。已运行会话若返回明确认证过期错误，会出现登录入口；重新登录后用户可再次发送任务，不自动重放之前的模型操作。网络问题与认证失效分开处理，不影响其他 CLI 的会话。

检测不发送模型任务。Codex 使用 `account/read` 并请求刷新托管凭据，Cursor 使用 `status --format json`；部分 CLI 状态只能证明本机已有凭据，不能保证模型服务、订阅、额度和网络全部可用。Cursor 返回已有凭据但无法查询在线信息时会明确说明。更换 CLI 路径会使旧检测结果失效；认证状态不写入会话轨迹或远端共享空间。

## Agent、成果与会话

- 用户在 CLI 设置中登录自己的 Cursor 或 Codex。服务器密码与模型账号无关。也可指定自己安装的 CLI 路径；Cursor 必须是 Agent CLI，而不是编辑器的 `cursor` 命令。
- 每个会话绑定本地工作目录、提供方和可选的远端项目。切换左侧项目不会改变已有会话的上传目标。CLI 权限请求和补充问题显示在会话中；不支持的请求会明确拒绝或报错。
- 可以创建多个 session，每个 session 的输入、引用选择和问题答案独立保存在本机。其 `.workbench/sessions/<id>/handoff.md` 是独立交接文件。首次发送提示 CLI 在形成阶段性结果时更新它；用户也可点击 **交接文件** 编辑。CLI 是否充分填写仍取决于其执行结果。
- 点击 **整理成果**后，工作台复制交接文件和已选择的参考材料，启动一个独立的同提供方会话提炼草稿。采用 CLI 的只读/Ask 模式；原工作会话可继续。生成内容不会自动覆盖用户编辑的草稿正文。标题、链接、说明和目标目录自动保存；切换页面保留编辑，保存失败显示错误与重试。交接窗口关闭前等待保存，保存失败保留窗口；退出应用也会检查待保存内容。
- 用户填写 **GitHub 仓库链接和修改说明**，再确认上传。代码、参考文件与旧版附件均不进入成果包；不会自动提交或推送业务代码。需要定位版本时，在说明中填写 commit、分支或 PR 链接。
- 成果 ZIP 只包含 `README.md` 与 `manifest.json`，保存仓库链接、修改说明和提交标识。每个上传使用唯一包名，经临时文件上传完成后重命名，失败可在传输记录重试。
- 会话历史单独归档，默认手动；可在每个工作会话中开启“每轮结束后自动上传”。归档包括规范化对话、工具/协议事件、原生 session ID，以及 Codex 返回时提供的原生记录路径。
- 会话归档仅覆盖本工作台启动/接续并采集的事件，**不冒充厂商完整原生数据库，也不包含不可访问的隐藏推理**。独立运行在工作台外的历史不会自动导入。Cursor 的 ACP 使用原生 session ID 关联，不依赖扫描猜测数据库文件。
- 轨迹包与成果包分开；`trainingConsent: false` 明确不表示已经授权用于训练。后续训练数据粒度与用途另行设计。

`.workbench/` 含本地工作记录与临时资料，建议加入业务仓库的 `.gitignore`。程序不会擅自修改业务仓库忽略规则。程序退出或网络中断后，未完成的传输保留为待处理状态，不会自动切换到当前项目继续上传。

## 开发与构建

```powershell
npm ci
powershell -ExecutionPolicy Bypass -File scripts/prepare-runtimes.ps1
npm run check
python -m unittest discover -s tests -p test_admin.py
npm run test:ui
npm run start           # 用户版
npm run start:admin     # 管理员版
npm run package
```

`scripts/build.mjs` 分别编译两个入口，只将所需文件放入 `dist/user`、`dist/admin`。安装包脚本读取这两个目录并使用不同的应用 ID。`scripts/check-providers.ts` 对真实 CLI 做初始化握手，不发送模型任务。

当前验证：TypeScript 编译；SSH/SFTP 回环协议集成测试（管理员验证、子管理员隔离、主机身份绑定、中文传输、权限拒绝、临时上传与路径边界）；CLI 模拟协议测试；Python 命令与身份边界测试；两个真实 Electron 窗口并行启动、首次必填路径、远端拒绝访问、子管理员建项目、按人归档轨迹与用户界面流程；官方 CLI 原生初始化。

尚未完成的外部验证：在公司的目标 Linux 发行版上执行账号创建/停用、实际 sudo/PAM/sshd 配置与目录 ACL；登录个人模型账号后的真实业务任务；另一台电脑安装迁移。请勿将回环协议测试理解为生产服务器已部署。

实现参考：[Codex App Server](https://developers.openai.com/codex/app-server)、[Cursor ACP](https://cursor.com/docs/cli/acp)、[OpenSSH sshd_config](https://man.openbsd.org/sshd_config)、[Linux ACL](https://man7.org/linux/man-pages/man5/acl.5.html)。
