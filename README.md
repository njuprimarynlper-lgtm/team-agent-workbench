# 团队工作台

Windows 本地 Agent 工作台与独立的团队管理应用。远端使用 Linux 账号、SSH/SFTP 和文件系统，受限文件操作器统一执行公共内容写入权限。当前开发版 **0.7.0**（未生成新安装包）。

0.7.0 实现单一 SSH 身份、多组工作台、限时离线授权、公共成果修订/整理/合并、项目资料版本与引用、可选代码版本快照、轨迹去重和缓存清理。操作与验证边界见 [身份与协作说明](docs/identity-content.md)。

0.6.2 本地管理员免账号密码：首次只选共享目录，后续启动自动进入。保留原有用户、组、密码和资料。正式 Linux 连接仍验证账号密码。

成员账号继续使用放宽后的账号和密码规则，并将输入校验错误改为中文提示。具体规则及兼容方式见 [账号使用说明](docs/accounts.md)。

0.6.3 成果仓库链接改为可选。方向性判断、结果性结论和方案建议可以只提交成果说明及人的补充，不需要代码或仓库地址。

当前开发版增加 CLI 权限检测、按会话选择权限和跨会话授权提醒。新建会话或「检测与修改权限」可选择沿用设置、人工审批、完全权限；沙盒失败不会自动提权。详见 [CLI 权限与人工授权](docs/cli-permissions.md)。此项已更新开发启动入口，尚未生成新安装包。

当前开发版还增加空组首次使用引导：无论新建账号还是添加已有账号，组内首位成员默认设为子管理员，管理员可调整。子管理员登录空组后填写项目背景、目标和验收标准，创建首个项目并生成团队可见的《项目说明.md》；可稍后填写，本机保留草稿。详见 [首位成员与项目初始化](docs/project-onboarding.md)。

## 本地文件系统联调

支持 **本地文件系统（模拟权限）**。管理员在专用空目录初始化模拟账号，创建组和成员，再导出连接配置；用户版导入后使用同一共享区，无需另选共享根目录。项目资料、成果和轨迹都写入真实本地文件。本地模式不需要 Linux、SSH 或对象服务。

操作步骤见 [本地模式使用说明](docs/local-filesystem.md)。正式 Linux 模式继续使用下文的系统账号和 SFTP 流程。权限桩仅用于功能验证，不替代 Windows/Linux ACL；直接使用资源管理器或终端仍受当前系统用户本身的权限控制。

## 两个应用

| 应用 | 当前功能 | 本机数据目录 |
| --- | --- | --- |
| Team Agent User 用户版 | 本机工作目录、按账号自动发现工作组、子管理员创建项目、Cursor / Codex 会话、共享文件、成果提交和轨迹上传 | `%APPDATA%\TeamAgentUser` |
| Team Agent Admin 管理员版 | 用户创建、密码重置、启停账号、用户组、工作目录准备、项目子管理员任命 | `%APPDATA%\TeamAgentAdmin` |

两个应用可同时运行，拥有不同的安装标识、快捷方式、入口、IPC 接口和配置目录。用户版不包含管理员 Python 程序、用户管理接口或“切换管理员”按钮。

管理员版识别两种身份：

- **总管理员**：以服务器已有 root 或 sudo 账号登录，经远端实际权限验证后进行用户管理。
- **项目子管理员**：以总管理员创建的个人账号登录，从服务器 root 拥有且普通用户不可修改的任命记录中读取所属项目。可以在用户版的授权工作路径下创建项目，不能调用用户管理接口；管理员版会提示其使用用户版进行项目操作。

**用户版子管理员已可创建项目、维护项目资料，以及整理、合并、替换、删除公共内容。** 总管理员负责系统账号、组、子管理员任命和离线有效期；公共文件写入由受限文件操作器按当前组身份执行。

0.6.3 安装包已包含登录身份、模型选择与额度、后台成果整理、关闭会话和轨迹上传的新交互。成果由 AI 自动生成说明并识别上传位置，人只需可选补充和确认上传；等待期间可继续工作。操作与验收见 [会话体验更新](docs/session-experience.md)。

## 安装与迁移

0.6.3 产物位于 `release/0.6.3/admin` 和 `release/0.6.3/user`（按版本分目录，打包新版本不会覆盖正在运行的旧版）：

- `TeamAgent-admin-0.6.3-x64.exe`：管理员版安装程序。
- `TeamAgent-user-0.6.3-x64.exe`：用户版安装程序。
- 同名 `.zip`：免安装目录压缩包，**解压全部文件**后运行 `Team Agent Admin.exe` 或 `Team Agent User.exe`。

支持 Windows x64；当前在 Windows 11 验证。安装包未配置企业代码签名证书。安装程序可选择安装位置，卸载默认保留用户数据。两版运行都无需预先安装 Node.js；用户版包含 Cursor Agent 与 Codex CLI 运行文件，管理员版不包含模型运行文件。

迁移到其他电脑只需复制对应安装包或完整的免安装压缩包，重新配置服务器并登录个人模型账号。不会把开发者的账号、密码、工作记录打进安装包。

## 第一次连接

两个应用首次启动时打开连接对话框。管理员配置共享区，向成员导出连接配置；用户版首次导入后，只需选择已存在的 Windows 本机工作目录，使用管理员分配的账号登录。已有配置会自动沿用，本地联调的共享区根目录也从管理员配置读取，不向用户提供输入或选择入口。本机工作目录与共享区仍独立存储。只有一个连接时显示说明卡片；多个连接时显示带用途说明的“团队连接（已保存）”选择器，它与工作组选择不同。SSH 连接也可手动设置，服务器字段默认收起。

共享工作路径由工作组自动分配，用户不填写。一个账号可以加入多个组，一次登录即可发现全部授权组和项目，无需按组建立连接。未分组账号可完成登录，但没有工作台，只显示联系管理员和刷新入口。某个组目录不可访问时在该组显示错误，不影响其他组。账号认证或成员信息读取失败会给出错误，不能误报成未分组。

加入工作组并成功核验后，保存有有效期的本地授权；默认 8 小时，管理员可设置 1–24 小时。有效期内可离线工作，过期后只读。共享文件操作仍需重新连接并校验权限，本地记录不替代远端授权。地址、端口、账号、本机目录和服务器指纹可保存；登录密码和 sudo 密码只保留在本次连接的内存中，不落盘，不进入模型 prompt。

管理员版通过左下角 **连接设置** 修改，用户版通过右上角服务器按钮修改连接和本机目录。首次连接需要与运维核对 SSH SHA256 主机指纹；已有指纹不匹配时拒绝连接。换服务器后重新核对。

总管理员需要服务器已经存在的 root 或 sudo 管理账号。Windows 的管理员身份、安装顺序、应用名称都不能赋予 Linux 管理权限。普通成员仅需要服务器分配的个人账号。

## 用户与组管理（0.5.0）

管理员可切换 **全部用户** 与 **按组查看**。两个视图共用同一份账号、成员关系和角色记录。

- 全部用户：平铺账号，展示全部所属组；子管理员标记出现在对应组旁边。可按账号、姓名或组搜索，筛选未分组、子管理员、启用和停用成员。
- 按组查看：展开或收起组，查看工作路径、成员数、子管理员数和本组成员。多组用户会出现在各自所属组中，底部单列未分组用户。
- 全局 **创建用户**：可以不选择组，也可以选择多个已有组并设置各组子管理员。即使当前没有任何组，也能先创建账号。
- 组内 **组内创建用户**：默认勾选当前组，可调整并选择其他已有组。
- 从用户添加：点击 **加入用户组**，选择尚未加入的已有组和本组身份。
- 从组添加：点击 **添加已有用户**，搜索并选择已有账号，设置普通成员或本组子管理员。已在组内的账号不重复列出。
- 点击姓名打开用户资料和组编辑；点击用户行的组标签可修改这个组的身份或移出此组。组内行也提供 **设为子管理员 / 取消子管理员 / 移出本组**。
- **移出组** 同时撤销该组子管理员身份，保留用户账号、其他组关系和已上传文件；账号整体禁用仍使用 **停用**。本版本不删除系统账号或项目组目录。

单组增删和角色变更由后端在锁内读取最新成员关系后执行，保留其他组及外部系统组；失败后支持既有的操作恢复流程。本地模式在下次共享操作重新校验权限，Linux 模式终止旧连接后按新的系统组权限登录。详见 [用户管理说明与验收](docs/admin-management.md)。

## 总管理员操作

1. 输入 SSH 地址、端口、管理账号、密码和团队根路径，例如 `/srv/teamspace`。sudo 密码与登录密码相同则留空。
2. 首次点击 **初始化账号管理**：要求指定路径不存在或为空，创建账号登记、专用成员组和 root 保护的元数据目录。已有团队使用原路径，不重新初始化。
3. **配置接入规则**：明确确认后，将本团队成员组限定为密码认证的 `internal-sftp`，以团队根路径为 chroot，禁止终端和端口转发。工具先执行 `sshd -t`，再重载 SSH 服务；校验/重载失败恢复原配置文件。
4. **创建用户**：填写登录账号（支持中文姓名、纯数字工号及大小写字母）、姓名和初始密码。密码非空即可，不要求至少 8 位或字符组合；不能有冒号、换行或空字符。扩展账号由程序自动映射到兼容的 Linux 系统用户名，成员登录时仍填写原账号。工具不接管已有 Linux 账号，不自动创建 root/sudo 管理员。将初始凭据通过公司的既有渠道交给本人。
5. **创建用户组**：例如 `ocr`，生成带团队前缀的普通成员组和内容子管理员组，并准备 `/srv/teamspace/projects/ocr` 工作目录。需要服务器安装 acl 软件包。对于旧版本创建的组，在组卡片点击 **准备工作目录**；不会接管已有非空目录。界面显示提供给成员的 SFTP 路径 `/projects/ocr`。
6. 在用户行点击 **组与子管理员**：选择成员所属组，并按项目任命内容子管理员。
7. 成员开通状态会显示缺少的步骤。创建时也可一次选定用户组与子管理员角色；开通完成后点击 **导出连接配置**，选择项目组，向成员交付不含密码的 JSON。成员在用户版导入后选择本机路径并输入单独获得的初始密码。
8. 重置密码、停用账号或调整组成员时，旧的远端会话/进程会被终止，以便新密码、禁用和组权限立即生效。这些账号应专用于团队共享；本地 CLI 会话不因此结束。

每个管理操作都经 SSH 发送固定程序与结构化输入，调用 `useradd`、`usermod`、`groupadd`、`gpasswd`、`chpasswd` 等系统命令。密码经加密连接的 stdin 传递，不插入远端命令参数。服务器上的操作以锁串行执行，登记文件以替换方式写入。Linux 多步操作不是事务；工具会记录不含密码的操作意图、预留 UID/GID 和已完成步骤，失败后刷新实际状态并显示“待恢复操作”。点击“继续完成”按登记身份恢复；密码相关操作需重新输入密码，身份发生变化则拒绝接管。初始化在 /var/lib/team-agent-workbench/bootstrap 中保留受保护的早期恢复记录。

账号登记：`<团队根路径>/.workbench/admin/state.json`；操作日志：同目录 `audit.jsonl`；子管理员入口任命：`<团队根路径>/.workbench/roles.json`。后者没有密码，root 拥有、成员只读；客户端还检查它及父目录的属主、写权限和符号链接。各项目实际读写仍由 Linux 文件权限控制。

服务器要求：Linux、Python **3.9+**、OpenSSH、shadow/passwd 用户管理命令、procps、acl（setfacl）。SSH 规则自动配置另外需要 systemd，以及主 sshd_config 中已启用 `/etc/ssh/sshd_config.d/*.conf` 的 Include。需要输入 TTY 的 sudo 策略暂不支持。不同发行版的 SSH/PAM 策略请由运维确认。

## 共享目录和用户版入口

总管理员创建工作组并分配成员和子管理员。用户登录后，左侧“我的工作组”按组分区展示项目，未加入的组不出现。子管理员在对应组标题旁看到加号；创建项目时只能选择具有子管理员权限的工作组。后台每次创建时重读成员和角色信息，SFTP 目录权限仍独立执行。多个组可以有同名项目，以独立项目 ID 和目录区分。

输入项目名（支持中文）后，目录结构例如：

```text
/projects/ocr/实体抽取/
├── .workbench-project.json
├── trajectories/                 # 会话轨迹
│   └── alice/                    # 首次上传时按账号自动创建
└── submissions/                  # 用户确认提交的成果
    └── alice/
```

创建时排他地保留项目目录名；同名目录不覆盖。轨迹与成果子目录准备完成、元数据写好后才发布项目。失败时只尝试删除本次创建的空目录，不删除已有项目内容。公共目录为 root 所有、2750，文件为 root 所有、0640；所属组可读，成员无法直接写、chmod 或删除。轨迹上传后同组可读。自己的待整理成果可通过工作台修订；子管理员整理后只能由子管理员继续维护。

同组成员登录后自动发现项目。点击“刷新工作组与项目”立即更新；窗口可见时每 30 秒自动刷新。Linux 管理员变更成员权限会断开旧连接，需要重新登录以应用操作系统的新组身份；本地打桩模式保持连接，刷新即可更新。会话在创建时绑定项目，浏览其他组不会更改旧会话、草稿或上传任务的目标。移出组后保留本地会话，原组上传会报权限或项目入口错误，不会转投其他组。

Linux 成员通过 chroot 内 root 拥有、普通成员不可修改的 `/.workbench/roles.json` 获取组分配。本版管理员写入 `membershipVersion: 1`，包括普通成员和未分组账号；旧服务器先使用新版管理员端连接并点击“刷新”，更新成员记录后再使用新版用户端。Linux ACL 继续负责实际文件权限。

导出连接配置以账号为单位，一份配置自动发现所有授权组，不含密码或项目路径。旧连接配置仍可导入地址、账号和指纹，但其中手工配置的 `workPath`、`manifestPath`、`projects` 不再作为共享入口；旧自定义目录须先由管理员纳入工作组项目布局。项目仍通过组目录下的 `.workbench-project.json` 标记发现。

启用本工具的 chroot 规则后，服务器 `/srv/teamspace/projects/ocr` 在成员 SFTP 中显示为 **`/projects/ocr`**。不能把 chroot 外部的服务器绝对路径直接用作 SFTP 路径。

用户版连接后，左侧按项目显示目录。文本、Markdown 和常见图片可预览，其他格式下载查看；手动刷新或每 30 秒刷新当前目录。**加入当前会话**会下载选中文件快照，下一次发送时把来源、快照路径和 SHA256 加入 prompt。不会自动把整个共享空间喂给模型。

## CLI 登录状态（0.2.1）

新建会话时选择 **Codex · GPT** 或 **Cursor**，会自动检测该 CLI 在所选工作目录下的登录状态。CLI 设置中也分别显示程序是否存在和账号状态：

- **已登录**：CLI 返回个人登录；**凭据已配置**：沿用 API Key 等已有配置，未宣称已验证模型服务或额度。
- **未登录**：未检测到凭据或明确返回登录过期。点击 **登录个人账号**，在 CLI 打开的浏览器里授权；完成后工作台自动重新检测，再创建会话。
- **检测失败**：网络、代理、证书、CLI 版本或配置异常。不会因此认定账号未登录；修复后点击 **重新检测**。
- **无需 OpenAI 登录**：Codex 当前服务配置明确不要求 OpenAI 认证，保留其既有行为。

登录可取消，重复点击不会创建多个登录进程；五分钟未完成会停止等待。浏览器未自动打开时，可点击检测到的官方 **打开登录网页**。工作台不保存登录命令的原始输出或令牌；登录链接仅在内存中暂存。凭据仍由各家 CLI 自行管理。

新建会话和发送任务前，主进程也会检查认证；认证失败时不发送任务，并保留输入框内容。已运行会话若返回明确认证过期错误，会出现登录入口；重新登录后用户可再次发送任务，不自动重放之前的模型操作。网络问题与认证失效分开处理，不影响其他 CLI 的会话。

检测不发送模型任务。Codex 使用 `account/read` 并请求刷新托管凭据，Cursor 使用 `status --format json`；部分 CLI 状态只能证明本机已有凭据，不能保证模型服务、订阅、额度和网络全部可用。Cursor 返回已有凭据但无法查询在线信息时会明确说明。更换 CLI 路径会使旧检测结果失效；认证状态不写入会话轨迹或远端共享空间。

## Agent、成果与会话

- 用户在 CLI 设置中登录自己的 Cursor 或 Codex。服务器密码与模型账号无关。也可指定自己安装的 CLI 路径；Cursor 必须是 Agent CLI，而不是编辑器的 `cursor` 命令。
- 每个会话绑定本地工作目录、提供方和可选的远端项目。切换左侧项目不会改变已有会话的上传目标。CLI 权限请求和补充问题显示在会话中；不支持的请求会明确拒绝或报错。
- 可以创建多个 session，每个 session 的输入、引用选择和问题答案独立保存在本机。其 `.workbench/sessions/<id>/handoff.md` 是 Agent 的独立工作记录。首次发送提示 CLI 在形成阶段性结果时更新它；会话工具栏下的 **会话资料** 默认收起，可点击 **查看 Agent 工作记录** 只读预览，必要时选择 **更正记录（可选）**。它是本地过程资料，通常无需用户填写；CLI 是否充分填写仍取决于其执行结果。
- 点击 **整理成果**后，工作台冻结当时的对话、Agent 工作记录和参考材料，在后台启动同提供方整理任务提炼草稿（不出现在工作会话列表）。采用 CLI 的只读/Ask 模式；原工作会话可继续。AI 自动生成标题、链接和说明，并从当前项目目录中识别上传位置；没有合适分类时使用默认成果目录。整理面板明确区分本地工作记录与供团队阅读的成果草稿，并显示状态和用时。顶部始终有 **取消**：运行中停止本次整理并返回来源会话；完成或失败后保留草稿、返回会话，不会上传。普通页面切换仍允许后台继续整理；人的补充独立自动保存，重试不会覆盖。切换页面保留内容，保存失败显示错误与重试。工作记录窗口关闭前等待保存，保存失败保留窗口；退出应用也会检查待保存内容。
- 用户查看 AI 生成的**成果说明**，可补充后确认上传。方向性判断、结果性结论、方案建议等无需仓库链接；涉及代码时可附带 GitHub 仓库链接。链接留空不会阻止上传；填写链接时仍检查格式。代码、参考文件与旧版附件均不进入成果包；不会自动提交或推送业务代码。可选择附带整理时的 Git 分支、commit 与未提交改动状态；不要求存在 Git 仓库。
- 成果 ZIP 只包含 `README.md` 与 `manifest.json`，保存成果说明、可选仓库链接和提交标识。新成果清单为 `schemaVersion: 3`、`kind: project-contribution`；无链接时省略 `repoUrl`，已上传的旧包保持不变。每个上传使用固定任务目标名和 SHA256，文件操作器返回成功后才显示“已上传”；回执丢失后重试不会重复创建。
- 会话轨迹单独上传，默认手动；可在每个工作会话中开启“每轮结束后自动上传”。轨迹包包括规范化对话、工具/协议事件、原生 session ID，以及 Codex 返回时提供的原生记录路径。
- 轨迹上传仅覆盖本工作台启动/接续并采集的事件，**不冒充厂商完整原生数据库，也不包含不可访问的隐藏推理**。独立运行在工作台外的历史不会自动导入。Cursor 的 ACP 使用原生 session ID 关联，不依赖扫描猜测数据库文件。
- 轨迹包与成果包分开；`trainingConsent: false` 明确不表示已经授权用于训练。后续训练数据粒度与用途另行设计。

`.workbench/` 含本地工作记录与临时资料，建议加入业务仓库的 `.gitignore`。程序不会擅自修改业务仓库忽略规则。程序退出或网络中断后，未完成的传输保留为待处理状态，不会自动切换到当前项目继续上传。

## 开发与构建

```powershell
npm ci
powershell -ExecutionPolicy Bypass -File scripts/prepare-runtimes.ps1
npm run check
python -m unittest discover -s tests -p test_admin.py
npm run test:ui
npm run start           # 用户版
npm run start:admin     # 管理员版
npm run package
```

`scripts/build.mjs` 分别编译两个入口，只将所需文件放入 `dist/user`、`dist/admin`。安装包脚本读取这两个目录并使用不同的应用 ID。`scripts/check-providers.ts` 对真实 CLI 做初始化握手，不发送模型任务。

当前验证：TypeScript 编译；SSH/SFTP 回环协议集成测试（管理员验证、子管理员隔离、主机身份绑定、中文传输、权限拒绝、临时上传与路径边界）；CLI 模拟协议测试；Python 命令与身份边界测试；两个真实 Electron 窗口并行启动、首次必填路径、远端拒绝访问、子管理员建项目、按人归档轨迹与用户界面流程；官方 CLI 原生初始化。

尚未完成的外部验证：在公司的目标 Linux 发行版上执行账号创建/停用、实际 sudo/PAM/sshd 配置与目录 ACL；登录个人模型账号后的真实业务任务；另一台电脑安装迁移。请勿将回环协议测试理解为生产服务器已部署。

实现参考：[Codex App Server](https://developers.openai.com/codex/app-server)、[Cursor ACP](https://cursor.com/docs/cli/acp)、[OpenSSH sshd_config](https://man.openbsd.org/sshd_config)、[Linux ACL](https://man7.org/linux/man-pages/man5/acl.5.html)。
