# Cursor CLI 会话切换回归

范围：工作台创建的普通 Cursor CLI 会话。Cursor 桌面联动仍使用原生后台及其网络设置，不通过这套 CLI 切换逻辑。

## 使用行为

- Agent、Plan、Ask 的选择只保存会话设置；下一轮发送前核对 CLI 支持情况。不再为打开模式菜单创建会话、验证登录或查询模型。
- 输入 `/plan`、`/agent`、`/ask` 和打开加号菜单不触发 Skill 查询。选择 Skills 或搜索具体 Skill 时再读取；重复选择当前模式不会重启 CLI。
- 模式菜单区分“读取模式”和“正在切换”，等待时仍可再次点击入口、点击外部、按 Esc 或使用关闭按钮收起。保存失败留在菜单内，保留原模式、当前会话和草稿。
- 输入栏的“本机网络／管理端出口 · 登录”可修改当前会话的连接方式。点击“应用连接方式”后显示保存结果；从下一轮生效，当前回复继续运行。发送时仍核验所选出口的登录状态。
- 已保存的管理端连接可以复用；更换接入码等全局配置仍需等待使用该连接的任务结束。
- 网络、模型或权限切换保留已有对话、未发送草稿和原生会话标识。尚未发送任何消息的临时 Cursor 会话由工作台自动清理，避免恢复一个 Cursor 尚未保存的标识。
- 启动失败会退出“启动中”，允许改设置和重试。旧版本留下的空会话标识仅在 Cursor 明确返回“不存在”、且本地没有用户对话时自动修复；已有对话不会静默重建。
- 模型列表优先读取 Cursor 会话接口提供的基础模型标识，发送时声明对应的参数化模型协议。旧版 CLI 仅在明确不支持该查询接口时回退到 `models` 命令。读取列表不新建会话、不触发登录；空列表或网络失败不回退到另一套可能无法发送的模型列表。
- `Invalid params` 会区分模型不被接受、原生会话不存在、发送参数被拒绝等原因，保留已有对话；不把完整错误数据或请求正文展示到界面。旧版保存的显式参数变体（如 `model[fast=false]`）仍使用对应的变体协议。

## 基础回归用例

| 场景 | 验证结果要求 |
| --- | --- |
| 离线打开模式菜单并选择 Agent／Plan／Ask | 不创建 CLI 进程、不需要登录、不锁住输入栏 |
| 逐字输入 `/plan`、`/ask`、`/agent` | 不查询 Skill、不启动 CLI、不把命令发送为用户消息 |
| 重复选择当前模式 | 保留已准备的原生会话，不新增下轮设置变更 |
| 模式读取缓慢、保存缓慢或失败 | 可关闭菜单，状态文字准确，失败保留原模式、页面和草稿 |
| 查询 Skill 创建空会话，随后切换设置 | 不再恢复尚未持久化的空标识，第一次发送正常 |
| 恢复旧版本留下的空标识 | 仅明确不存在时重建；已有用户消息时禁止自动重建 |
| 认证、加载、模型设置、模式设置失败 | 状态变为失败，允许切换网络／模式后重试 |
| 连续切换模式、模型、权限、网络 | 继续原生会话，已有记录和草稿保持不变 |
| Cursor 加载时重放历史 | 不追加旧回复、工具结果或重复轨迹事件 |
| CLI 恢复时返回另一会话标识 | 停止发送并保留原标识 |
| 回复期间切换设置并排队下一条输入 | 当前轮次不中断，队列下一轮采用新设置 |
| Plan 待确认期间选择下一轮 Ask | 本轮审批保留，接受计划不会覆盖下一轮 Ask |
| 启动等待时停止，再切换网络 | 能取消等待并重新发送，不产生重复消息 |
| 当前 CLI 不支持 Plan | 发送前明确失败，可切回 Agent 继续 |
| 两个 Cursor 会话并行 | 设置、网络、上下文和回复相互独立 |
| 原出口请求失败，同时已选择下一轮出口 | 错误归属于实际执行的出口 |
| 网络、账号或模型查询缓慢 | 保存会话出口、返回对话不等待可选查询 |
| 管理端接入码无效、面板已切换 | 不错误保存另一会话或失败的全局连接配置 |
| 管理端出口、新会话、选择 Grok 4.7 | 模型列表与发送使用同一基础模型协议，第一条消息正常完成 |
| 模型设置返回 `Invalid params`，原因在 `error.data.message` | 提示刷新模型后重选，不发送用户消息，可修改模型重试 |
| 原生会话不存在，原因在 `error.data.message` | 无历史空标识自动修复，有历史时保留且明确报错 |
| 模型列表为空、异常、查询取消、未登录 | 不制造可用模型、不启动登录、不创建空会话，取消后退出查询进程 |
| 旧版 CLI 不支持会话模型查询接口 | 仅此情形回退旧查询命令，并遵守同一个查询时限 |

## 执行方式

```powershell
node scripts/test-background.mjs tests/cursor-models.test.ts tests/cursor-session-settings.test.ts tests/provider-connection.test.ts tests/new-session-network.test.ts tests/session-mode.test.ts tests/session-settings.test.ts tests/provider-auth.test.ts tests/session-input-queue.test.ts tests/cursor-egress.test.ts
npm run test:cursor-session-ui
npm run typecheck
npm run build:check
```

界面测试运行无头浏览器、真实工作台后端和隔离的 ACP 测试进程。临时数据及截图写入已忽略的 `.test-data`，不读取或改变个人对话、账户或配置。

另有可选的本机真实 Cursor CLI 合约验证：通过真实管理端转发组件连接本地 HTTP/1.1 服务桩，使用合成凭据验证账号、模型、ACP 模式切换、空会话不持久化以及工作台恢复逻辑。模型服务桩分别返回基础模型 `grok-4.7` 与变体 `grok-4.7[fast=false]`，真实 CLI 的旧调用方式返回 `Invalid model value: grok-4.7`，新调用方式设置成功。它验证的是协议兼容性，不代表该账号实际获得 Grok 服务权限。没有发送模型提示词，也不消耗真实账号额度。

```powershell
$env:RUN_CURSOR_NATIVE_CLI='1'
node --import tsx --test tests/cursor-egress.test.ts
```

真实 CLI 用例需要 `.tools/cursor/dist-package/cursor-agent.cmd`。本地服务桩验证不等于用户故障电脑经过实际管理端和公司网关的在线对话验收；后者仍需在对应环境复核。
