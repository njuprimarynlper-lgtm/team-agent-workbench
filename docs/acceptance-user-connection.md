# 用户版连接配置与多工作组验收

日期：2026-09-17。

## 交互约定

- 共享区由管理员配置。管理员导出不含密码的连接 JSON，用户首次导入；已有配置直接使用。
- 用户只选择本机工作路径。用户版不显示共享根目录输入、共享目录选择按钮、连接名称编辑或存储类型切换。
- 本机工作路径不会替换管理员配置中的共享根目录，二者继续独立存储。
- 只有一份连接配置时显示带账号的连接说明；多份配置显示“团队连接（已保存）”，说明它用于选择服务，工作组在登录后自动发现。
- SSH 地址、端口和指纹仍可手动设置或在折叠区修改；改地址、端口时清除旧指纹，连接时重新核验。
- 本地配置缺失共享根目录时要求重新导入管理员配置；不会让用户补填第二处路径。

## 用例

| 用例 | 验证内容 |
| --- | --- |
| 首次打开 | 提示导入管理员配置；没有配置时不能登录；取消导入保持原状态 |
| 旧配置 | `competition.xxx` 单配置不再显示无说明下拉框；共享根目录继续使用原值 |
| 路径选择 | 只选择本机工作路径；不会把工作目录变成共享目录 |
| 多连接 | 显示连接用途、服务、账号；切换或导入清空密码；未保存的 SSH 连接不冒充已保存配置 |
| 配置更换 | 不完整本地配置提示联系管理员；重新导入完整配置恢复；重启保留配置，不保存密码 |
| 管理员与两用户 | 管理员创建组、成员，导出配置；两用户导入、登录并共享文件、成果、轨迹 |
| 同一账号加入两个组 | 一份配置、一次登录发现 OCR 与 NLP 两个组；同名项目独立显示；不显示未授权组 |
| 各组不同身份 | OCR 子管理员与 NLP 普通成员同时生效；NLP 越权创建在后端被拒绝 |
| 切换工作组 | 原会话保留原项目绑定，不随导航切换改变上传目标 |
| 撤销组权限 | 刷新后移除对应组入口；原会话不能继续向该组上传 |
| 空组与未分组 | 未分组用户无工作台；首次子管理员项目引导、草稿恢复及成员身份隔离 |
| SSH 回归 | 回环 SSH/SFTP 测试服务验证错误密码、正常登录、会话建立和重启恢复 |

执行命令：`npm run typecheck`、`npm run build`、`npm run test:connection-ui`、`npm run test:local-ui`、`npm run test:workgroups-ui`、`npm run test:onboarding-ui`、`npm run test:ui`。

本次结果：上述检查全部通过。SSH 流程同时完成保存失败重试、会话输入隔离及离线授权内重启恢复。更新了旧附件用例，使其区分固定引用的项目资料与用户手动选择的附件。

本地用例在独立 `.test-data` 子目录创建真实文件和权限桩；CLI 使用测试夹具。这些用例验证应用行为，不代表真实 Linux 系统权限验收。结果与截图保存在对应测试目录；多工作组额外保存 `two-groups.png` 和 `independent-roles.png`。
