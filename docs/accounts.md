# 账号与密码

0.6.2 起，本地管理员免登录：只选择共享目录，重启自动进入。下面的姓名、工号和密码规则用于成员账号；正式 Linux 管理员仍使用服务器账号密码。

创建成员时，“登录账号”可以填写 `张三`、`10086`、`ZhangSan`。登录用户版时填写同一个账号，无需知道服务器的系统用户名。成员姓名只是展示信息，不会自动变成第二个登录账号。

- 账号支持 1–64 个字符：中文等文字、数字、大小写字母、下划线、短横线和间隔号；以文字或数字开头。去除首尾空格，不允许路径符号和 Windows 保留文件名。
- 账号保留输入大小写，登录时应保持一致；不能创建仅大小写不同的重名账号，避免本地 Windows 共享目录重叠。
- 创建、重置和失败恢复时，密码非空即可，不要求 8 位或字符组合；确认密码须一致。保留 4096 字符上限及冒号、换行、空字符限制，以兼容服务器命令输入格式。不会自动修改已有密码。
- 用户组名称与账号规则一致：1–24 个字符，中文等文字、数字、字母、下划线、短横线和间隔号，以文字或数字开头。它是显示给成员看的本地名称，远端 Linux 组名由工具自动生成，不需要管理员迁就 Linux 命名规则。
- 校验失败会显示字段对应的中文提示，不再直接展示 Zod JSON。

## Linux 和旧数据兼容

原本合法的小写账号继续使用原 Linux 用户名和 UID。中文、工号、大写等扩展账号通过固定 SHA-256 映射生成 32 字符的 `wbu_…` 系统用户名；管理员创建、设置密码、分组、停用、恢复、读取状态和用户版 SSH 登录都使用同一映射。账号记录保存原账号和系统用户名；项目角色、上传目录及界面仍使用原账号。

用户组名沿用同一思路，且名称必须整体一致（同一名称的不同 Unicode 写法会先归一化）。原本合法的组名（小写字母开头、14 位以内）系统组名保持 `wb_<团队ID>_<名称>` 不变；中文、大写或更长的名称生成 `wb_<团队ID>_g<SHA-256 前 13 位>`。界面始终显示本地名称，成员看到的工作路径仍为 `/projects/<本地名称>`（支持中文）；因此 Linux 上 `getent group` 显示的是派生名，不含可读名称，排查时请以管理员版界面显示的名称为准。名称之间不能仅大小写不同，与账号重名规则一致。为已有团队改用中文组名后，成员需要升级到新版用户版才能识别。

映射不赋予权限。服务器仍根据已登录的 Linux 身份和用户组检查目录权限，不接管已有同名系统账号。总管理员继续使用服务器已有 root/sudo 账号，原样验证。管理员版遇到扩展成员账号认证失败时只重试一次映射后的账号，角色仍须由受保护的服务器记录确认。

已有账号、组、密码、项目和会话不迁移、不重置；管理员版和用户版应同时升级到 0.6.1，旧版客户端不认识扩展账号。成员在用户版直接填写服务器地址和自己的账号，中文姓名或工号账号均可登录。

正式 Linux 上既有 PAM/SSH 密码策略仍由服务器控制；如果服务器拒绝某个密码，界面会显示实际失败并保留可恢复操作。本版取消的是工作台自身的长度和组合要求。

## 用例验证

- `tests/accounts.test.ts`：规则和中文报错；Windows/Python 映射一致；本地管理员免登录初始化；姓名、工号和混合大小写成员创建、直接登录；真实本地文件上传、轨迹访问限制；重置、停用、移出组、重新连接；通过 SSH/SFTP 协议验证映射后的认证和原账号角色。
- `tests/test_admin.py`：模拟 Linux 用户/组数据库及命令执行，覆盖映射账号创建、密码 stdin、分组、撤销角色、停用、状态回读、UID 变化拒绝和创建中断恢复。该测试不等同于在真实 Linux 发行版上部署。
- `scripts/admin-management-smoke.mjs`：管理员窗口创建姓名、工号和大小写账号，1 位密码；非法账号、空密码和确认不一致的中文反馈。
- `scripts/local-smoke.mjs --accounts`：免登录管理员与两个用户窗口，用 `张三` / `10086` 和 1 位密码完成项目创建、共享文件、轨迹上传、停用与恢复。共享内容写入隔离的真实本地目录。

以上界面脚本可加 `--packaged` 验证实际打包后的 EXE。
