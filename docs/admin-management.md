# 用户与组管理 0.5.0

管理员在 Windows 管理员版登录后进入“用户管理”。本地模拟模式和 Linux SSH 模式共用界面，实际权限分别由权限桩和服务器系统账号落实。

最新开发版将“创建用户”和“创建用户组”并排放在页面右上角，两种视图下位置一致；组内保留“组内创建用户”和“添加已有用户”。该交互已包含在 0.6.1 管理员版安装包中；开发时仍可双击仓库根目录 `start-admin-dev.cmd`。

已有比赛打桩环境应运行 `node scripts/sync-local-demo.mjs "D:\agent开发\比赛协同联调\run-20260916-02"` 同步三个演练入口，之后仍使用演练目录的“打开管理员 / 打开用户A / 打开用户B”。它们直接读取最新 `dist` 构建，并沿用各自状态目录及原有共享区。后续界面修改完成后构建并同步此环境，便于检查实际联调逻辑。

## 入口与行为

| 操作 | 入口 | 结果 |
| --- | --- | --- |
| 查看全部用户 | 全部用户 | 每人一行，显示状态、所属组及各组子管理员身份 |
| 查看组的成员 | 按组查看 → 点击组名 | 展开成员，显示本组角色；同一人可出现于多个组 |
| 独立创建用户 | 页面右上角创建用户 | 所属组默认空，可选择任意已就绪的组 |
| 创建用户组 | 页面右上角，与创建用户并排 | 新建组并准备对应工作路径 |
| 在组内创建 | 按组查看 → 组内创建用户 | 默认加入当前组，可调整所选组及子管理员身份 |
| 用户加入已有组 | 全部用户 → 加入用户组 | 选择尚未加入的组，设置普通成员或子管理员 |
| 将已有用户加到组 | 按组查看 → 添加已有用户 | 按姓名或账号搜索，选人并设置本组角色 |
| 查看 / 修改用户所属组 | 点击用户姓名，或组与子管理员 | 勾选或取消组；对已选组单独授予子管理员 |
| 修改单组身份 | 点击用户的组标签，或组内设为 / 取消子管理员 | 只更新指定组的角色 |
| 从用户一侧移出组 | 点击用户组标签 → 成员身份选择移出此组 | 解除本组成员关系和子管理员权限 |
| 从组一侧移出成员 | 按组查看 → 移出本组 | 与从用户一侧移出效果相同 |

“全部用户”和“按组查看”同时提供搜索、角色和状态筛选。未分组用户在全局可筛选，在层级视图中有单独区域。无匹配结果、空组、无可添加用户会明确提示。取消对话框不提交变更；重复账号会在对话框显示错误。

## 权限与数据含义

子管理员是一个**组内角色**，可在对应工作路径下创建项目，不是总管理员。用户可以在 NLP 组担任子管理员，同时是 OCR 组的普通成员。

移出组会撤销对应访问资格和本组子管理员角色，保留账号及其他组角色。已上传成果和轨迹仍留在项目目录中。要禁止整个账号登录，使用“停用”；此版不提供永久删除账号、组或目录的操作。

独立创建且未分组的用户已拥有账号，但尚无共享项目组工作路径访问权。管理员为其分组后才能导出可用的项目组连接配置。

单组操作的请求只包含账号、目标组和期望身份。后端在团队锁内读取最新成员关系再更新目标组，避免管理员甲在 NLP 组操作时覆盖管理员乙新增的 OCR 身份。Linux 使用固定 Python 程序及系统命令，并沿用操作记录和失败恢复；恢复时也保留其他组的当前状态。

## 可重复验证

```powershell
npm run check
python -m unittest discover -s tests -p test_admin.py
node scripts/admin-management-smoke.mjs
node scripts/admin-management-smoke.mjs --packaged
node scripts/local-smoke.mjs --packaged
node scripts/smoke.mjs --packaged
```

用户管理界面用例使用独立的临时共享目录和模拟账户，不修改演练中的 Alice、Bob。结果及截图保存在 `.test-data/admin-management-*/`。用例覆盖两个视图、两种创建入口、双向加入和移出、子管理员授予与撤销、跨组权限保留、未分组用户、搜索筛选、重复账号、取消操作及重启保存。

底层还覆盖在线成员撤权、文件保留、两个管理员使用不同新旧快照、无效用户/组/角色及 Linux 部分执行后的恢复。Linux 系统命令测试采用替身，部署公司服务器前仍需实际环境验证。

账号现在支持中文姓名、数字工号和大小写字母，密码非空即可。正式模式的账号映射、旧账号兼容及测试范围见 [账号使用说明](accounts.md)。
