# CLI 查询响应优化

模型与能力菜单的等待包含工作台查询、CLI 启动和上游网络三个部分。本次减少工作台重复调用及无关等待，不改变个人账号、执行权限或原生 Skill 调用方式。

| 环节 | 之前 | 当前行为 |
| --- | --- | --- |
| 模型菜单 | 每次打开都启动一个查询进程；同提供方的新查询取消旧查询 | 两分钟内复用显示结果；相同范围的并发请求共用一次查询，不同目录和出口互不取消 |
| 模型与额度 | 模型列表已返回，仍可能等待额度查询二十秒 | 额度单次读取最多等三秒；未获取时保留可用模型并显示额度暂不可用 |
| Skill 与插件菜单 | Codex 串行读取，两者全部完成才显示 | 两个区域独立、并行读取和显示，插件未返回不阻塞 Skill 的选择 |
| 发送已选能力 | 即使只选 Skill，也重新等待完整插件目录 | 只解析本轮选择的能力类型；同一会话一分钟内复用目录，刷新可重新读取 |
| 浏览 Codex 能力 | 初始化完整会话并执行命令自检 | 只建立鉴权后的元数据连接，发送第一条消息时才创建或恢复对话并自检 |
| 并发启动 | 同时读取能力可能建立多个运行实例或重复初始化 | 同会话共用创建和初始化请求；完成后继续复用该 CLI 连接 |
| 登录核验 | 指定网络出口的会话不能利用已有十秒缓存 | 目录、网络出口匹配且登录状态有效时短时复用；登录错误或配置变化仍需重新验证 |

模型缓存按团队账号代次、提供方、CLI 配置路径、工作目录、网络出口、出口配置摘要及已知的 CLI 账号身份区分，最多保留 32 个显示快照，只在内存存储。手动点击刷新绕过结果缓存，不重复启动正在执行的相同查询。模型读取失败只暂存一秒，便于重新尝试。

能力缓存属于当前会话的运行实例，目录或网络设置变更后新实例重新读取。Cursor 的原生命令更新会使 Skill 缓存失效；返回空命令列表也视为已返回，不再反复等待。Claude Code 的 Skill 从本地原生目录读取，只选 Skill 时不会运行无关的插件列表命令。

缓存用于菜单显示与原生调用参数，不授予权限；发送仍校验项目权限和登录状态，CLI 继续执行自身鉴权、批准和 Skill 加载。模型推理、Skill 内容读取和调用外部服务的耗时不受此次缓存保证。

验证使用本地协议替身，不访问真实模型或共享服务器。新增 `tests/cli-query-performance.test.ts` 验证进程及 RPC 请求数量、并发初始化、缓存刷新与隔离、慢插件独立返回、鉴权失效和额度等待上限；`scripts/cli-query-ui-smoke.mjs` 验证局部加载、选项可用及迟到结果处理。正式网络上的首次响应时间仍需实测。
