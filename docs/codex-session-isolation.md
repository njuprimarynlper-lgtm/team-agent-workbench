# Codex 会话存储与上下文续接

工作台新建的 Codex 会话保存在当前用户数据目录的 `codex-home/` 下，与个人 Codex 默认会话目录分开。新会话、成果整理会话、原生记录及 SQLite 索引均写入独立目录；不以临时会话或丢弃历史的方式隐藏会话。

## 登录与配置

- 登录入口、账号身份、模型与额度查询继续使用个人 CLI。
- 独立运行进程通过原 CLI 获取访问凭据，并以仅内存方式使用；刷新由原 CLI 负责。不复制 `auth.json` 或刷新令牌，不将访问凭据写入会话、事件或轨迹。
- 沿用个人 CLI 配置、规则、技能和插件。个人配置移除后，不继续保留旧配置；配置更新在下次启动会话运行进程时采用。
- 管理策略禁止独立数据库或仅内存登录时，明确停止启动，不回退到个人会话目录，不修改管理策略。
- 接入版本按本机 Codex 0.154.0 的生成协议和真实 CLI 验证；升级 CLI 后应执行下列原生回归。登录桥接使用 `getAuthStatus` 与实验性 `chatgptAuthTokens`，不支持时不静默降级。

## 修改权限与旧会话

修改权限只停止当前运行进程并更新权限选择，保留原生会话 ID、已保存对话、模型及项目绑定。下次发送时以 `thread/resume` 加载原生历史。正在执行的操作可能中断，不承诺恢复尚未保存的中间状态，也不会自动重试。

旧版工作台创建的会话首次继续时，仅复制该会话的完整原生记录到独立目录后续接。保留上下文和会话 ID，后续消息写入新目录。找不到原生记录时明确提示，不以新建空会话冒充恢复成功。

已经存在于 Codex 客户端的旧条目不会自动删除，原记录保留；迁移后的工作台不会继续更新那份记录。当前已运行的旧工作台进程需关闭后重新打开，才能使用新的存储方式。

- `tests/codex-auth-bridge.test.ts`：沿用个人登录、仅内存刷新、账号变化拒绝、凭据不进入轨迹。
- `npm run test:codex-isolation`：真实 Codex CLI，配合本机回环模拟模型接口。验证默认会话列表没有新条目、默认目录无法读取隔离 ID、修改权限和重启后原用户及助手消息仍进入下一次模型请求、旧会话迁移后保留上下文且不改动旧记录。测试不调用付费模型。
- 本机个人账号另行验证：独立运行进程沿用同一 ChatGPT 身份、不复制登录文件、默认客户端无法加载隔离会话；未调用模型。
