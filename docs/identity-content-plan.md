# 身份、公共内容与协作能力（本轮实现依据）

每位成员使用独立 SSH/Linux 账号，密码即 SSH 密码；一个账号可加入多个项目组，各组子管理员角色独立。个人会话、工作记录、草稿仅在本机；上传的成果及轨迹对所属组共享。不同 Windows 账号使用独立数据目录，相同资料目录重复启动需激活现有窗口。

普通成员只能更新、删除自己尚未整理的提交。子管理员可以整理、改写、合并、删除本组所有公共内容；一旦整理，原作者不能覆盖正式内容，可另提补充。正式内容及其作者/状态/版本记录必须在服务器受保护，不能依赖客户端按钮或用户可修改的 JSON。

服务器保留 SSH/SFTP 身份验证和文件存储。新增受限的文件操作器，经各账号的专属请求目录接收操作；不新增网络端口、应用密码、模型或项目 Agent。公共文件由受控操作器维护，成员 SFTP 对正式内容只读，避免上传者通过 chmod、删除再上传等方式绕过管理。请求执行时校验实际账号、当前组角色、内容版本和路径。旧服务器未配置此能力时明确提示管理员升级，不降级为不安全写入。

离线授权建议默认 8 小时；在有效期内可继续已授权组的本地工作，过期后工作台只读；重新连接成功才续期，远端写入始终在线重新鉴权。离线期间不能即时得知撤权，已下载资料不能远程撤回。此为产品行为边界，不声称能约束用户离开产品后对自己的本地文件操作。

本轮包含此前确认修复：对话快照进入成果整理、上传真实状态与幂等重试、每个项目的资料生命周期、末位子管理员变更提醒及交接；无组没有工作台。

另外补齐四项：项目资料默认引用及更新提醒；成果搜索/阅读/加入会话；可选 Git 分支、commit、脏状态；轨迹成功时间、去重、自动频率及成功缓存清理。Git worktree 不在本轮接入，训练轨迹粒度另议。

验收需覆盖两位成员、两个组、跨组角色差异、同目录重复进程、断网授权、并发编辑版本冲突、子管理员整理后禁止原作者覆盖、上传回执丢失、无组账号、项目资料更新、最后一位子管理员变更。真实 Linux ACL 与独立 SFTP 绕过测试单独记录；本地权限桩不能代替系统安全验证。
