# 0.7.0 身份、内容维护与协作

本版为开发构建，两个桌面窗口可直接启动，未制作新安装包。

## 登录与身份

- 总管理员仍用服务器已有 root/sudo 账号进入管理员版；创建的成员各有独立 Linux 账号。
- 用户版只输入该成员的 SSH 账号和密码；没有第二套产品密码。姓名/工号由客户端映射到专用 Linux 登录名，密码就是该系统账号的密码。输入界面接受非空密码，实际设置仍须通过服务器的 PAM/密码策略。
- 一个账号可加入多个组，在不同组可分别是成员或子管理员。权限从受保护的服务器登记和实际组关系读取。
- 没有加入组的账号没有工作台；加入后刷新即可。多个 Windows 账号各使用自己的 `%APPDATA%`，不会共享本地会话。联调用 `WORKBENCH_DATA_DIR` 分开目录；相同数据目录由一个用户版进程持有，重复启动会在该进程中新开窗口，所有窗口共享账号和会话状态并统一保存。
- 本地个人记录始终留在本机。远端没有个人工作区；只有用户主动或按其自动上传设置共享的资料。
- 成员电脑与服务器断开后，仍可继续已授权项目的本地工作，没有时间限制；重新连接时再核验权限。已下载的本地文件不能远程收回，本产品也不约束产品外的本地工具。

## 公共内容怎么使用

项目侧栏点击“公共成果”，可按标题、说明、作者、日期、仓库搜索，按成果/文件/轨迹筛选。

| 动作 | 普通成员 | 本组子管理员 |
| --- | --- | --- |
| 阅读与下载组内内容 | 可以 | 可以 |
| 修改、替换、删除自己未整理的提交 | 可以 | 可以 |
| 修改其他成员内容 | 不可以 | 可以 |
| 合并文字成果 | 不可以 | 可以，保存后替代所选原件 |
| 修改已整理内容 | 不可以，可另提补充 | 可以 |
| 维护项目背景、目标、验收等资料 | 只读 | 可以 |
| 管理账号与组角色 | 不可以 | 不可以，须总管理员操作 |

文字成果可直接编辑；普通文件可编辑说明或选择文件替换。保存使用预期修订号，遇到别人已更新会提示冲突，保留本地输入，不静默覆盖。子管理员的保存会标为“已整理”，原作者不能再改写或删除。合并不是回收站：被合并原件被移除，结果保留来源 ID，应在确认保存前核对合并后的正文。

旧版文件仍在文件区。子管理员预览普通文件后，点击“纳入公共成果管理”，即可统一编辑说明、替换、删除。纳入的旧文件会标为已整理；项目说明与管理元数据须用对应入口维护。

“加入当前会话”会冻结所选成果的文字说明及作者、修订、路径为本地参考快照；后续远端编辑不会悄悄修改本地引用。需要原附件时可在文件区下载并加入会话。

## 四项补充能力

1. **项目资料进入会话**：新会话默认引用项目资料。各项目可独立创建、补充和更新资料，`.keep` 等文件不影响初始化。项目子管理员在“设置 → 项目设置”修改背景、目标、验收标准、范围、交付物、资料、约束和协作约定；保存会更新元数据、版本快照及共享根目录的 `项目说明.md`。更新后显示新版本提示，由成员点击“采用当前项目资料”；运行中的轮次不被打断。窗口可见时每 30 秒检查工作组与项目，也可手动刷新。
2. **成果搜索与复用**：公共成果页检索、阅读、带来源加入会话；原始过程记录不混入成果目录。
3. **可选代码版本记录**：整理时读取 Git 分支、commit、是否有未提交改动。用户可取消附带，无仓库也可上传结论。不会提交、推送或上传业务代码；dirty 状态表示该 commit 不能代表全部本地改动。
4. **轨迹去重及缓存维护**：对话和工具事件共同决定快照是否变化；重复点击复用同一上传。自动上传默认间隔 15 分钟，可设置频率，间隔内新进展延后上传。只有服务器确认成功才更新最近成功时间。“传输记录”可清理已成功上传的本地缓存，不清理原会话、工作记录、草稿输入或失败待重试文件。

成果整理同时冻结当时的对话与工作记录，显示取材时间/消息数；缺少或陈旧的工作记录不再成为唯一来源。新的对话进展须显式重新整理才采用。排队、上传中、上传失败、已上传分别显示；失败可重试原包，也可复制为新草稿补充后提交。回执丢失重试使用相同目标和哈希，不重复创建文件。

总管理员移除、降级、停用最后一位子管理员时，需选择本组接任人或明确保留空缺。不会自动提升任意成员。

## Linux 服务端配置和升级

成员只需要 SSH/SFTP；不新增产品账号、HTTP 端口或项目 Agent。要保证原作者无法绕过客户端按钮，正式公共文件统一由 root 持有（目录 2750、文件 0640），所属组只读。不能只依赖普通文件属主权限，否则原作者可以 chmod 或删除后再上传。

管理员版创建首个成员用户时会在同一次可恢复操作中配置 internal-sftp，并安装 `server/content.py` 为受限 systemd 文件操作器，服务名 `team-agent-storage-<teamId>`；不会留下“账号已创建但成员无法登录”的正常状态，也不提供单独的成员接入配置入口。后续创建用户会先校验该配置，缺失或变化时自动补齐。依赖 Linux、Python 3.10+、OpenSSH、systemd、acl 工具以及管理账号 sudo 权限。操作器无模型调用，只处理固定的创建项目、资料保存、上传、内容修订/替换/合并/删除/纳入操作。

```text
<团队根路径>/
  .workbench/
    admin/                  root 独占：账号登记、操作器、上传回执
    roles.json              成员只读：组关系、角色
    inbox/<Linux登录名>/    该账号可提交暂存文件与请求
    outbox/<Linux登录名>/   该账号只读：操作结果
  projects/<组>/<项目>/
    .workbench-project.json
    .workbench-content.json
    .brief-versions/
    项目说明.md
    submissions/<账号>/
    trajectories/<账号>/
    curated/
```

文件操作器读取操作系统 UID、账号标记与当前组，和管理员变更共用锁，再检查项目、作者、整理状态、版本和路径。请求文件不允许符号链接/硬链接；单文件最大 2 GB。正式公共内容不能经其他 SFTP 客户端直接写、chmod 或删除，合法修改均通过操作器。

升级会保护现有公共树、终止成员旧连接，成员需重新登录。存在符号链接、硬链接或特殊文件会拒绝迁移，需要管理员先处理。服务器未升级时新版用户端明确提示，保留读取能力，不降级为直接写入。首次上线前应备份共享根目录，并在公司的目标发行版完成下面的真实环境验收。

排查服务：`systemctl status team-agent-storage-<teamId>`、`journalctl -u team-agent-storage-<teamId>`。请求超时不意味着服务端一定没有执行：上传可重试同一任务；创建项目先刷新查看是否已创建。

## 验证范围

- Node 用例覆盖本地真实文件、回环 SSH/SFTP、双账号/多组、版本冲突、整理锁定、回执丢失、Git 状态、轨迹与缓存。
- Python 用例直接测试正式服务器业务规则；Windows 测试仅模拟 chown/chmod/系统账号命令，不能证明 Linux 内核权限。
- Electron 界面验证管理员、两个独立用户并行、同数据目录锁、资料版本采纳、成果编辑/合并/搜索/引用、后续项目初始化，以及 Codex/Cursor 的会话、模型、权限提示和输入体验。
- **尚未在真实 Linux 服务器验证** systemd 安装、sshd/PAM 和 ACL 绕过；本机无 WSL/Docker。`sudo python3 -m unittest discover -s tests -p test_content.py` 可运行附带的 Linux 内核权限用例（需 acl；通过 fork 降权，不创建系统账号）。还需在目标环境验证完整管理员安装、独立 SSH 登录、跨组访问、直接 SFTP 写入/chmod/删除拒绝、撤权与服务重启。
- 本轮未重新运行真实模型业务任务或另一台电脑安装迁移。轨迹仍是工作台采集的可见对话与工具事件，训练粒度和后续训练授权另议。
