# 项目与自动同步

项目同时是成员权限边界和资料容器。成员直接加入项目，项目内管理说明、会话、成果和任务；界面不再区分工作组与项目。

## 创建与连接

1. 点击用户端顶部的**创建项目**，输入项目名称，填写中央节点的 SSH 连接，或复用已登录的连接。
2. 连接成功后填写项目背景、目标和验收标准，也可以稍后完善资料。
3. 点击**创建项目**。中央节点建立目录、成员权限和轨迹目录；当前账号成为创建者。中央节点确认成功后，项目出现在左侧列表。
4. 从项目设置的**成员与权限**添加已有账号。用户账号仍由总管理员创建。

不同中央节点使用不同窗口。同一节点、同一账号可复用连接；每个项目分别控制连接和同步，创建或连接一个项目不会自动接通其他项目。

新项目必须连接中央节点后创建。旧版本的本机项目保留资料与会话；可新建中央节点项目，再通过会话的**管理会话归属**迁移会话，不再提供仅本机创建或关联工作组的入口。

## 同步与冲突

- 已有项目的资料编辑先在本机保存，连接后后台同步。离线授权有效期内可继续已有工作；新建项目和成员权限变更需在线完成。
- 创建请求使用固定标识。同一创建窗口内重试相同内容，会继续原请求，避免响应丢失造成重复项目。关闭窗口后可刷新项目列表确认是否已经创建；若仅完成权限与目录准备，项目会提示完善资料。
- 项目说明和账号资料按上次同步版本、本机版本和中央版本比较。不同字段自动合并；同字段有分歧时，只暂停对应资料的同步。
- 项目说明冲突从**项目设置 → 项目资料**处理；账号成果冲突从**自动同步**处理。AI 提供合并稿与需要人判断的分歧，不替用户决定事实、数值、删除或归属问题。
- 采用前重新核对双方版本，旧建议不能覆盖新修改。处理前的内容保存在本机合并记录中；没有后续修改时可恢复。
- 自动同步不会把会话全文或代码目录发布给其他成员；成果共享和轨迹上传继续由各自入口控制。

## 部署与验证

中央节点需更新 `server/group_ops.py` 和 `server/content.py`，分别支持成员范围和项目目录的幂等创建。已有服务器通过管理端的**更新服务端功能**升级。旧节点不支持必要接口时显示升级提示，不宣称创建成功。

`project-sync.json` 按账号保存项目缓存、同步基础与旧版待处理请求；`sync-conflicts.json` 保存合并建议和恢复记录。完整会话继续保存在本机。

后台回归覆盖零成员关系账号创建项目、响应丢失重试、创建者权限、邀请与跨项目隔离、离线创建拒绝，以及旧资料兼容、并发编辑、迁移和冲突恢复。构建使用 `node scripts/build.mjs --check`，不覆盖运行中的客户端。
