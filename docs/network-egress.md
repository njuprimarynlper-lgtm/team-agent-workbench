# 管理端网络出口

管理端网络出口用于这样一种部署：成员电脑能访问团队内网，但部分电脑不能直接访问 Codex、Cursor 或 Claude Code；管理端电脑具备可用外网或已有代理。它是可选通路，不改变成员账号和项目权限；成员可直接连接管理端，也可通过已登录的共享服务器中转。

## 先判断是否需要

管理端可同时打开多个中央节点窗口。各窗口的网络出口独立，新出口自动分配不同本机端口；用户端按所填接入码连接指定出口。已有端口和接入码会保留，停止其中一个出口不影响其他出口。操作方式见[管理多个中央节点](admin-management.md#同时管理多个中央节点)。

成员 A 能正常登录团队项目，也能直接连接所选模型服务，保持默认设置即可。成员 B 能打开团队项目，却因所在网络无法连接模型服务；如果 B 能访问管理员电脑的内网地址，管理员可以开启网络转发并给 B 一段接入码。B 把接入码填入用户版后，工作台启动的模型 CLI 经管理员电脑连接模型服务。B 仍用自己的模型账号和额度，团队项目继续走原来的 SSH/SFTP 连接。

“网络出口”指管理员电脑提供的**模型连接中转**，不需要成员把代码、模型账号或团队 SSH 密码交给管理员。接入码只用于连接中转，不能当作成员账号或模型账号。管理员版需保持运行；成员恢复直连后可关闭该选项。

## 从用户看到的连接过程

1. 管理员在管理员版开启出口，确认它自己能够访问所需的 Codex、Cursor 或 Claude Code 服务，再把接入码交给需要转发的成员。
2. 成员在用户版勾选“通过管理端访问模型服务”，粘贴接入码，仍用自己的 SSH 账号登录团队项目。
3. 成员核对自己的模型 CLI 登录状态，创建会话并发送一次请求。收到模型回复才说明成员端整条连接可用。
4. 若团队项目打不开，检查 SSH、组成员关系和共享权限；若项目能打开而模型不能回复，分别检查成员到管理端、管理端到模型服务和成员的模型账号。

以下是实现层面的连接路径；普通成员按上述界面步骤操作即可。

```text
用户版启动的 Codex/Cursor/Claude Code CLI
    ↓ 仅该 CLI 的 HTTP_PROXY / HTTPS_PROXY
127.0.0.1 随机端口（用户版进程）
    ↓ TLS 加密、证书指纹固定、接入码校验
管理端电脑:18443
    ↓ 本机直连 / HTTP CONNECT / SOCKS5
Codex、Cursor 或 Claude Code 服务
```

模型服务的 TLS 连接穿过隧道，仍由本机 CLI 与厂商建立。管理端不解密提问、回答或个人模型账号凭据，只能看到用户端上报的成员账号标识、产品、目标域名、连接状态和流量。这个账号标识便于排查连接，不作为权限认证；网络出口的访问控制来自接入码。成员继续使用自己的 Codex/Cursor/Claude Code 账号和额度；本功能不提供共享模型账号。

## 查看代理监控与 CLI 异常

管理端 **网络出口 → 运行监控** 每 2 秒更新在线成员与隧道数、上下行速率及累计流量、最近两分钟趋势、连接失败与接入拒绝次数。在线成员列表显示来源地址、目标域名和当前连接流量；“最近连接”默认收起，展开后查看历史记录与失败原因。数字统计的是当前这台管理端承接的流量；多个管理端分别统计自己的出口。

代理运行在独立后台进程中。面板里的 CPU 是该代理进程占整机 CPU 总容量的比例；内存是该进程的驻留内存，不包含管理界面、共享空间操作或本机其他 Codex 会话。关闭出口会释放代理进程，重新应用设置或启动管理端会重新开始累计。最近连接保留 100 条，累计流量不因旧记录被移出而减少；短暂的连接检测和状态上报不计入模型隧道流量。

**用户端 CLI 状态** 单独显示等待服务响应、重连次数、HTTP 401/403/429/5xx 等失败及恢复状态。工作会话和成果整理页面也会立即显示重连或失败提示；真正收到服务输出后才清除异常。403 表示访问被拒绝，不能仅凭它认定是密码错误或网络不通。

模型 HTTP 状态位于加密隧道内部，代理不会解密读取。更新后的用户端会通过已验证的出口连接上报状态类别、错误码和重试次数，每 30 秒补报最新状态；不上传提示词、回复、完整诊断文本或凭据。超过 90 秒没有更新会标记状态过期。旧用户端仍可转发流量，但没有这项 CLI 状态上报；工作台之外启动的 CLI 也不在监控范围内。出口断开期间无法即时上报，用户端仍显示本地异常，恢复后继续补报。

“连接成功”“正在收发”只说明隧道状态；需同时查看 CLI 状态，不能把它当成模型请求成功。更新此功能需两端获取新代码并在现有任务结束后重新启动；不要在成员使用过程中重启出口。

### Cursor 在本机网络正常，切到管理端后失败

在用户版当前会话或创建会话的 **网络连接** 中，点击 **重新检测连接与登录**。选择 Cursor 时，检测会经过当前管理端连接到 Cursor 服务并校验证书，再分别检查个人账号和模型列表；仅能连上管理端，不算 Cursor 检测通过。

- **管理端尚未允许 Cursor 转发**：管理员在 **网络出口 → 出口设置 → 成员可通过出口访问** 中启用 Cursor 并保存。
- **上游代理拒绝连接（HTTP 403／407）**：检查管理端上游代理对 Cursor 的访问权限或代理认证。Codex 可用不代表 Cursor 域名也被允许。
- **本机无法验证模型服务证书**：工作台启动的 Cursor CLI 会自动补充本机 Windows 系统已信任的证书，并保留 CLI 原有证书配置。企业证书尚未被本机信任时，仍需正确配置；不会跳过证书验证。如果 CLI 运行环境过旧，按提示升级 Cursor Agent CLI 或为其配置企业证书。
- **已保存登录，但在线账号查询失败**：表示本机有登录凭据，当前出口尚未验证成功；不会再显示成“CLI 未提供账号名称”，也不会据此放行管理端会话创建。缺少可选的账号名称本身并不算连接失败。

管理端模式只保留本机回环地址的代理例外，防止电脑原有的 `NO_PROXY=*` 或 Cursor 域名例外绕过所选管理端。账号检测、模型查询和工作台启动的 Cursor 会话使用相同的网络与证书设置；不会更改已运行的 Cursor 原生桌面进程。连接检测不调用模型；完整验收还需用自己的账号发送一条消息并收到回复。

HTTP/1.1 专项用例位于 `tests/cursor-egress.test.ts`，强制测试服务仅提供 HTTP/1.1，覆盖二进制 POST、分块上传、连接复用、分块流式响应、服务返回 403，以及传输中断后重新连接。设置 `RUN_CURSOR_NATIVE_CLI=1` 后运行该测试文件，还会调用本机测试用 Cursor CLI，以临时假账号查询模拟服务，断言账号与模型接口实际收到的协议为 HTTP/1.1；不会使用个人模型额度。HTTP/2 流式测试同时保留。这些是本地模拟管理端验证，不替代故障电脑的真实出口验收。

## 管理端配置

网络出口分为 **运行监控、成员接入、出口设置、连接诊断** 四个页签。首次未启用时默认打开设置；已启用时默认打开监控。切换页签保留未保存设置，后台刷新不会因监控数据变化重置输入；设置页签的小圆点提示有未保存修改，可保存应用或放弃修改。

1. 打开管理员版左侧 **网络出口 → 出口设置**。此页不依赖共享空间是否已经登录。
2. 开启 **启用管理端出口**。程序首次启动时已经自动生成自签名 TLS 证书、证书指纹和随机接入码，不需要手工运行证书命令。
3. 核对“提供给成员的地址”。默认使用管理端电脑名；成员电脑无法解析时改成管理端固定内网 IP。
4. 监听端口默认 `18443`。监听地址默认 `0.0.0.0`，允许内网网卡接入；需要限制网卡时在折叠区修改。
5. 选择管理端访问外网的方式：
   - **本机直接访问**：管理端本身可以访问模型服务。
   - **HTTP 代理**：填写上游代理地址、端口及可选账号密码。
   - **SOCKS5 代理**：填写上游代理地址、端口及可选账号密码。
6. 在 **成员可通过出口访问** 中勾选允许转发的服务。这是成员访问权限，不要求管理端电脑安装、启动或登录对应 CLI。点击 **保存并应用** 后生效；下次打开管理员版会自动恢复。
7. 切换到 **连接诊断**，分别测试 Codex、Cursor、Claude Code。三个测试不受成员转发权限或出口启停影响，使用已保存的上游设置；未保存修改会在界面提示。测试只检查管理端到目标服务地址的网络连接，不验证成员模型账号或配额，也不会开放转发权限、重启出口或计入成员模型流量。

出口关闭时，测试使用临时后台进程，不打开成员监听端口，测试结束或失败后释放；出口运行中直接复用现有进程，保留连接与监控记录。确认网络和成员访问范围后，再复制用户端接入码。

在 **成员接入** 选择“直连管理端”或“经共享服务器”，只显示所选路线的操作。管理员需要提供的信息只有一段接入码。它已经包含管理端地址、端口、TLS 证书指纹和随机访问密钥，不需要再让成员分别填写这些字段。接入码等同于本出口的访问凭据，只发给需要转发的成员。证书指纹和“更新接入码”位于折叠的 **接入凭据与安全** 中；更新会让两种路线的旧接入码立即失效，所有使用者需要重新粘贴。

启用出口后，关闭管理员端窗口会转入系统托盘，继续保留出口和本次登录的反向隧道；双击托盘图标或再次运行入口可重新打开。选择托盘菜单“关闭此节点并停止其转发”、注销或关机会停止；系统托盘不可用时，界面会明确提示关闭窗口将停止转发。普通驻留模式不要求本机管理员权限。防火墙规则仍需运维配置，只对公司内网来源开放所选 TCP 端口，不应暴露到公网。

上游代理密码、出口访问密钥和用户端保存的接入密钥在 Windows 支持时使用 Electron `safeStorage` 加密后写入各自应用数据目录。普通配置文件不包含这些明文。TLS 证书和私钥只保存在管理端本机数据目录。

## 经共享服务器中转

成员能连接共享服务器，却无法直接连接管理端电脑时，使用此选项。

```text
用户端 → 共享服务器的 SSH 端口（如 2202）→ 服务器内部中转端口
                                                  ↓ 管理端主动建立的 SSH 反向隧道
                                             管理端出口 → 模型服务
```

1. 更新管理端与用户端。管理端用已有的 Linux root / sudo 账号登录共享服务器，进入 **网络出口 → 成员接入 → 经共享服务器**。
2. 确认出口已保存并运行，点击 **启用反向隧道**。程序使用本次已验证的 SSH 登录信息，分配仅限服务器内部访问的端口，并允许团队成员连接该端口；其他管理员的出口会保留。
3. 点击 **检测完整隧道**，验证本机 → 共享服务器 → 本机出口的连接、证书指纹和接入码，再 **复制中转接入码**。直连管理端使用的普通接入码在另一条接入路线中。
4. 首次使用的成员应断开共享连接后重新登录，勾选 **通过管理端访问模型服务** 并粘贴中转接入码，界面会自动选中 **经共享服务器中转**。已在使用的会话也可在网络与登录设置中切换；运行中的任务需先结束。
5. 在用户端重新检测连接与模型登录，再发送一次请求。当前共享服务器必须与接入码中的地址、SSH 端口和已验证身份一致。断开或不允许转发时会显示原因，不会自动改成直连。

共享服务器已有 SSH `2202` 即可作为外部入口，内部端口仅监听 `127.0.0.1`，不需要额外申请对外端口。成员电脑和管理端电脑均需能主动连接这个 SSH 入口；共享服务器不必直接连接管理端的 IP 或 `18443`。实际网络验证中，共享服务器连接管理端的 `80、443、2202、18443` 都超时，而生产代码使用反向隧道完成了 TLS 握手及证书校验。

SSH 密码仅在管理端本次运行的内存中保留，用于隧道重连，不写入配置文件。短暂断网按递增间隔重试，最长间隔 30 秒，保持原内部端口和接入码；账号认证失败或服务器身份变化会停止自动重试，需重新登录。关闭管理端窗口会保留后台转发；主动断开管理连接或选择托盘菜单“关闭此节点并停止其转发”，才会关闭隧道并清除内存中的登录信息。再次启动并登录原服务器后自动恢复已启用的隧道。关闭网络出口会暂停隧道，重新开启后恢复。

后台驻留的启动、恢复窗口和退出步骤见[后台转发说明](background-egress.md)，统一使用管理端入口。

多个管理端分别分配内部端口，停用某一台只关闭它自己的隧道。端口占用时显示连接失败并重试，不会自动换端口使已分发的接入码失效。**停用中转** 保留成员允许地址，便于下次恢复；如需彻底撤销地址，使用下方“管理允许的出口”。隧道连接数、重连次数和内部端口在本页单独显示；反向 SSH 转发在管理端主进程中运行，不计入“代理监控”中独立代理进程的 CPU/内存。

服务器能够直接连接管理端 IP 时，仍可展开 **高级：服务器直接连接本机**，使用 **测试服务器到出口** 和 **允许此出口中转**，再切换到“直连管理端”复制普通接入码，成员另行勾选“经共享服务器中转”。这项 TCP 测试不代表模型账号可用；若此直接模式受出站端口限制，可调整管理端出口端口或优先使用反向隧道。

只有服务器 root / sudo 管理员可以修改中转规则；项目组管理员和普通成员只能选择已允许的路线。服务器保留 SFTP 专用登录、目录隔离和无终端权限，通过 OpenSSH 的 `AllowTcpForwarding local` 与精确 `PermitOpen` 地址列表限制转发，代理、X11、Unix socket 和网络设备转发仍关闭。配置经过 `sshd -t` 检查后重载，失败恢复原配置。反向隧道会在每次连接后核对 Linux 实际监听地址；若 SSH `GatewayPorts` 将监听扩大到非回环地址，程序会关闭该隧道。指令含义见 [OpenSSH 官方说明](https://man.openbsd.org/sshd_config#PermitOpen)。

新增权限在新的 SSH 连接生效；已经登录的成员应先断开再登录。**管理允许的出口 → 移除并断开成员连接** 会关闭全体成员现有的 SSH 连接，包括共享文件传输和模型中转，防止旧连接继续保留已撤销权限；管理端出口本身继续运行。再次登录后按新的地址列表限制转发。

中转只搬运加密流量，用户端仍验证管理端证书指纹和接入码。反向隧道下管理端监控的来源 IP 为本机回环地址，直接中转时为共享服务器地址；成员账号标识、CLI 状态与流量统计保持可见。本地文件夹模拟共享区不支持中转。中转接入码使用 `TAE2` 格式，旧用户端会拒绝该格式，需要更新；原 `TAE1` 直连接入码仍兼容。

## 用户端配置

1. 本机能直接访问模型服务时保持选项关闭，按原方式登录团队共享空间。
2. 本机不能直连时，在用户版登录窗口勾选 **通过管理端访问模型服务**。
3. 首次粘贴管理员提供的接入码；之后工作台会记住接入信息和密钥，除非管理员更新接入码。
4. 无法直接连接管理端时勾选 **经共享服务器中转**；管理员须先按上节允许该出口。
5. 继续填写团队 SSH 账号密码并登录。出口选项只在认证成功后应用到该账号，登录失败不会改动之前账号的网络设置。中转需保持共享服务器在线，出口异常不会改变项目权限。

启用后，用户版自动在 `127.0.0.1` 上选择空闲端口，并向工作台启动的 Codex/Cursor/Claude Code 进程注入 `HTTP_PROXY`、`HTTPS_PROXY`、小写兼容变量、`NO_PROXY` 和 `NODE_USE_ENV_PROXY`。关闭选项会停止本机代理且不注入这些变量。系统代理、浏览器和工作台之外启动的 CLI 不会被修改。

出口设置改变时，工作台会关闭空闲的 CLI 运行时并重新检测账号。正在运行或等待授权的会话不会在中途切换网络，需等待任务结束后再修改。

## 固定边界

- 管理端只接受接入码正确且证书指纹匹配的 TLS 连接。
- 目标仅允许配置中启用的 Codex/Cursor/Claude Code 官方域名后缀和 TCP 443；任意域名、任意端口及普通 HTTP 请求会被拒绝。
- 用户端不会信任系统中任意证书；它固定校验接入码携带的管理端证书 SHA-256 指纹。
- 管理端不记录报文正文。界面中的最近连接记录只保留当前进程内的目标域名、状态和字节数。
- 接入码用于控制网络出口，不替代 SSH 成员身份，也不授予任何共享空间权限。

若厂商今后新增必需域名，旧版白名单可能导致该请求被拒绝。先确认域名属于官方服务，再由开发者更新 `src/core/egress.ts` 的产品白名单并重新发布客户端；不要把出口改成任意目标的通用代理。

## 验收

### Cursor CLI 请求保护与自动摘要

与 Codex 共用 **agent管理 → Codex / Cursor 请求大小保护（1 MB）** 开关（兼容保留 `codexRequestGuard` 设置键）。仅覆盖新启动或重新连接的本机 Cursor CLI 工作会话，不覆盖 Cursor IDE 同步及一次性后台任务。

Cursor 使用原生 gzip、Protobuf 和按 Blob 引用的会话状态，不能复用 Codex 的 JSON Responses 修复器。适配器在当前模型上下文的 Blob 正文累计达到 1,000,000 字节时调用原生 `summarizeAction`：已有大上下文在下一轮发出前处理，本轮新增内容使上下文变大则在该轮结束后处理。归档历史不纳入触发统计。摘要在同一会话中由 Cursor 原生 checkpoint writer 保存；下一轮读取保存后的状态，不修改原生数据库、Blob ID、历史记录或用户 CLI 配置。原生自动摘要已完成时不再重复执行。摘要失败后按 1～30 分钟退避；成功后回落到 80% 以下或增长 20% 才重新触发。

工作台仅在该 ACP 子进程中选择原生 HTTP/1.1 BidiAppend/SSE 传输，沿用 Cursor 的认证、gzip、代理、证书和端点选择。每个模型、Blob 和摘要请求在 HTTP 写出正文前核对实际编码后的大小，必须严格小于 1,000,000 字节；不是把 Token 数、上下文总量或单个 HTTP chunk 当作上传正文。不能把任意二进制 Blob 分片或截断后冒充原文。单条消息、图片或工具结果 gzip 后仍达到上限时，本地阻止该上传并取消这次原生操作，避免重连重试循环，后续需缩小该内容。Cursor 暂不实现 Codex 那套分段文本交接摘要与旧图片降级修复；因此这类不可压缩的大 Blob 仍可能阻止原生摘要。

压缩不显示为聊天或工具消息，不增加用户轮次、日志、完成通知；后续消息留在原有等待队列。轮后压缩不计入回复生成时间。最多等待 10 分钟，未确认原生任务结束时阻止后续发送，重新连接后再继续。停止会话会取消其原生上下文。

当前私有接口经过项目配套 **Cursor CLI 2026.09.10-fd3934a** 的模块指纹及 Protobuf 验证。ACP 本身未提供 `/summarize` 入口，不能发送一个普通 `/summarize` 提示词充当压缩。适配仅包装内存中的模块导出，不改写安装包；不兼容版本或适配未加载时，在用户任务发送前明确报错，可改用配套 CLI，或关闭大小保护后重新连接。升级配套 CLI 时须更新适配与验证，不能直接放宽指纹检查。

### 本机 Codex 请求大小保护

用户版 **agent管理 → Codex / Cursor 请求大小保护（1 MB）** 首次使用默认开启，此后沿用上次保存的开关状态；旧设置中没有此项时也默认开启，明确保存过的关闭状态不会被覆盖。它针对有上传大小限制的网络场景；1 MB 不是所有模型服务的通用上限。开关保存后只影响新启动或重新连接的本机 Codex 后台（包括成果整理、AI 推荐等后台 Codex 任务），已连接后台沿用原设置。原生子会话借用同一后台时也沿用原设置，最后一个借用者关闭才释放保护入口。桌面同步、远程 Codex、Claude 不接入本次保护；Cursor CLI 的适配范围和机制见下节。

**设计参考：** Codex 请求大小保护参考了 [Codex Request Optimizer](https://github.com/qzz1008-glitch/codex-request-optimizer) 的 1,000,000 字节正文预算、zstd 无损压缩与超限历史交接摘要设计（参考版本 [`26840b6`](https://github.com/qzz1008-glitch/codex-request-optimizer/commit/26840b6e15d495dbe52e37070fb45fbf8c931f8)，[MIT 许可证](https://github.com/qzz1008-glitch/codex-request-optimizer/blob/26840b6e15d495dbe52e37070fb45fbf8c931f8/LICENSE)）。下文记录本项目的具体处理规则；Cursor CLI 使用上节所述独立适配。

本机中转仅监听回环地址，采用随机入口路径和线程级 provider 覆盖，不修改个人 Codex 配置、认证文件，也不直接重写原始历史文件。每次发送都核对 **最终上传正文 < 1,000,000 字节**（最多 999,999 字节），不含 HTTP 头和 TLS 开销。按当前需求，此限制以压缩后的正文计算。等于 1,000,000 字节也必须先处理；摘要、原生 compact 与最终推理请求执行相同边界。符合预算的原包保持字节不变；超限时，内置 OpenAI 或明确配置 `supports_request_compression = true` 的自定义 Responses 连接可尝试 zstd。其他上游不假定支持请求压缩。

已有会话在启用保护、重新连接本机后台后，下次发送会自动检查当前完整请求，累计历史已经超限也能进入同一修复流程，无须新建会话。此前已失败的消息不会擅自重发，需用户重试；处理完成的当前请求会自动继续发送。

压缩仍超限时，先按保守规则对安全闭合的已完成历史生成交接摘要；若仍不能达标，再将已完成旧轮次中无可读摘要的加密 reasoning 与纯文本数组工具结果纳入可替换历史，最后才允许省略已完成旧工具结果中结构可核对的图片，保留其文字和图片省略标记。加密 reasoning 密文与省略的图片不发给摘要模型；其他未知原生项继续保留。最近一条用户消息起的整个活动轮次、系统/开发者指令、工具目录、环境、内部通知及未闭合工具组始终原样保留。摘要请求同样受预算限制，不携带可执行工具；只有完整文本结果可进入最终请求。各级合计最多 16 次摘要，为较宽的处理级别保留余量；每次摘要等待最多 240 秒。修复后的正文优先控制在上限的 80% 以下，为后续输入留余量；固定内容占用较多时可以退回严格小于 1 MB，不为凑余量额外扩大有损处理范围。任何失败都不能降级为上传超限原包。拒发信息只给出固定内容、最新轮次和候选请求编码后的字节数，不包含正文或凭据。摘要是有损转换，额外消耗的模型用量与最终推理用量分开统计，原响应的真实用量不被改写。

摘要遇到上游 `server_is_overloaded` 或 HTTP 502/503/504 时最多尝试 3 次，每次使用新的请求标识；持续失败会显示安全的错误码、上传字节数和尝试次数，不上传超限的原推理请求。其他摘要结构错误仍直接拒发。

摘要缓存仅在内存中存在，按账号、会话、模型、指令、工具、上游与精确前缀核对；最多 128 项、32 MiB，闲置 1 小时失效，原请求回到预算内时清除。程序结束不保存摘要映射。用户原始会话仍由原有存储管理。

工作会话的普通推理请求原始正文达到预算的 **80%** 且成功接入上游时，就会为对应原生线程标记一次自动 compact，不必等到超限。同一轮多个请求只合并为一次：当前用户轮次正常结束后，工作台调用 `thread/compact/start`，下一轮消息留在现有等待队列。只收到 RPC 的空确认不算完成，必须收到同一压缩轮次的 `contextCompaction` 完成与 `turn/completed`；这些内部事件不显示成工具消息，不增加用户轮次、日志或完成通知。Codex 自行保存原生压缩状态，后续请求使用新上下文；工作台不自行拼接或裁剪 compact 返回的加密状态。若 Codex 已在本轮完成自动压缩，则取消待执行的重复 compact。成果整理、推荐等一次性后台任务仅执行请求大小保护，不额外启动维护轮次。

分层历史处理后仍超限而在本地拒发时，HTTP 保护层只标记拒发，不在请求回调里启动 compact。工作台等待原轮次的失败完成事件，再读取原生历史核对空闲状态、失败轮次和已保留的完整用户文本；仅有错误通知而没有完成事件时，不启动恢复，也不放行新轮次。确认本轮尚未输出、执行工具、切换模型或接受引导后，最多尝试一次原生 compact。完整完成后再核对历史和状态，以空 `input` 续跑原生历史中已接受的输入，不追加第二条用户消息，不改变本轮模型、权限和指令，也不让后续排队消息抢先发送。无法核对、已执行工具、停止/关闭或重试仍超限时，保留输入并明确提示，不循环重放。

线程关联同时兼容新版 `thread-id` / `session-id` 和旧版 `session_id` / `x-codex-session-id` / `x-session-id` 请求头，优先使用线程身份；独立摘要请求移除这些原生身份字段。新版 CLI 通过 `/responses` 流式执行的原生 compact（元数据 `request_kind=compaction`）也受相同保护，并且不会再次安排 compact。

本机 Codex 的后台进程与界面会话分别管理。根会话停止或关闭后，只要原生子会话仍在使用后台，工作台就保留该后台及其认证连接、请求保护器；根会话重开和已知子会话重连时，按工作台会话 ID、原生 thread ID 及账号存储目录核对并复用原 writer。各会话仍独立接收消息、处理授权和停止任务。最后一个使用者关闭后才释放共享后台；重开若遇到后台退出中，会等待清理完成，再创建替代进程。原生上一轮尚在运行或停止时，保留新输入并提示稍后重试。相关行为覆盖 #23 的根会话重开场景。

`/responses/compact` 的输入也会先经过大小保护，必要的交接摘要仍通过 `/responses` 生成，不会递归调用 compact。compact 自身仍超限时不上传，提示明确区分“分层处理失败”“原生 compact 未启动”和“原生 compact 失败”。压缩成功后，原生请求降到 **60%** 以下会重新启用 80% 触发；若仍在边界附近，则须比上次触发时至少增长 20% 才再次安排，避免每轮重复压缩。明确失败后继续使用请求保护，后续请求按 1 分钟起步、最多 30 分钟的指数退避再尝试；CLI 明确不支持该方法时，本连接停止自动尝试。维护最多等待 10 分钟，超时会尝试中断已知压缩轮次；无法确认原生任务结束时暂停后续发送，不能把超时当作取消成功。原生完成事件或已确认启动后的空闲状态可解除发送屏障，断开、停止或关闭会话会清理监听与等待任务。父会话、子会话、临时侧聊按各自的原生线程隔离标记和压缩。

访问上游沿用原环境代理；Windows 未提供环境代理时读取系统固定代理及排除列表，不更改系统设置。自动代理脚本（PAC）和 SOCKS 暂不支持，需配置 HTTP 代理或关闭本功能。证书仍需有效，代理失败不会改走直连。本机入口显式排除于代理，避免本机 Codex 的模型请求被绕到外部代理。当前版本通过真实 CLI 核对 provider；未确认保护通路时停止发送。

请求保护的 TLS 连接合并运行环境默认 CA 与 Windows 系统信任 CA，同时读取 `CODEX_CA_CERTIFICATE`（优先于 `SSL_CERT_FILE`）及 `NODE_EXTRA_CA_CERTS`。**agent管理 → Codex / Cursor 请求大小保护 → 企业证书与连接检测** 可额外选择 PEM 证书包或 DER 格式的 CA 证书（`.pem`、`.crt`、`.cer`，最多 4 MiB）。不会导入 Windows 证书库、修改个人 Codex 配置或关闭证书校验；目标域名、有效期和证书链仍须通过验证。经 HTTPS 代理时，代理自身和 CONNECT 后的模型服务都使用这套信任配置。证书路径保存到本机设置，内容不上传；保存后下一次请求连接生效，正在传输的回复不被打断。已配置但无法读取或无效的证书文件会明确报错，需要检查工作台设置及上述环境变量。

连接检测使用当前 Codex 的模型服务地址及所选网络出口，仅建立代理隧道和 TLS 握手，不发送认证令牌、会话材料或模型请求；通过检测只代表网络和证书验证通过，不代表账号、模型权限和推理请求已验收。对话错误旁的“重新检测”沿用该会话的网络出口；不会自动重新发送消息。公司代理的 TLS 错误、CONNECT 403/407、超时等会显示明确原因，“查看详情”仅包含阶段和允许公开的错误码，不包含代理密码、令牌、证书内容或原始异常。失败后不切换网络出口。
