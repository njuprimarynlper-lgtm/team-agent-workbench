# 管理端网络出口

管理端网络出口用于这样一种部署：成员电脑能访问团队内网，但部分电脑不能直接访问 Codex、Cursor 或 Claude Code；管理端电脑具备可用外网或已有代理。它是可选通路，与 SSH/SFTP 共享空间、团队账号和项目权限相互独立。

## 先判断是否需要

成员 A 能正常登录团队项目，也能直接连接所选模型服务，保持默认设置即可。成员 B 能打开团队项目，却因所在网络无法连接模型服务；如果 B 能访问管理员电脑的内网地址，管理员可以开启网络转发并给 B 一段接入码。B 把接入码填入用户版后，工作台启动的模型 CLI 经管理员电脑连接模型服务。B 仍用自己的模型账号和额度，团队项目继续走原来的 SSH/SFTP 连接。

“网络出口”指管理员电脑提供的**模型连接中转**，不需要成员把代码、模型账号或团队 SSH 密码交给管理员。接入码只用于连接中转，不能当作团队账号或模型账号。管理员版需保持运行；成员恢复直连后可关闭该选项。

## 从用户看到的连接过程

1. 管理员在管理员版开启出口，确认它自己能够访问所需的 Codex、Cursor 或 Claude Code 服务，再把接入码交给需要转发的成员。
2. 成员在用户版勾选“通过管理端访问模型服务”，粘贴接入码，仍用自己的 SSH 账号登录团队项目。
3. 成员核对自己的模型 CLI 登录状态，创建会话并发送一次请求。收到模型回复才说明成员端整条连接可用。
4. 若团队项目打不开，检查 SSH、组成员关系和共享权限；若项目能打开而模型不能回复，分别检查成员到管理端、管理端到模型服务和成员的模型账号。

以下是实现层面的连接路径；普通成员按上述界面步骤操作即可。

```text
用户版启动的 Codex/Cursor/Claude Code CLI
    ↓ 仅该 CLI 的 HTTP_PROXY / HTTPS_PROXY
127.0.0.1 随机端口（用户版进程）
    ↓ TLS 加密、证书指纹固定、接入码校验
管理端电脑:18443
    ↓ 本机直连 / HTTP CONNECT / SOCKS5
Codex、Cursor 或 Claude Code 服务
```

模型服务的 TLS 连接穿过隧道，仍由本机 CLI 与厂商建立。管理端不解密提问、回答或个人模型账号凭据，只能看到用户端上报的团队账号标识、产品、目标域名、连接状态和流量。这个账号标识便于排查连接，不作为权限认证；网络出口的访问控制来自接入码。成员继续使用自己的 Codex/Cursor/Claude Code 账号和额度；本功能不提供共享模型账号。

## 管理端配置

1. 打开管理员版左侧 **网络出口**。此页不依赖共享空间是否已经登录。
2. 开启 **启用管理端出口**。程序首次启动时已经自动生成自签名 TLS 证书、证书指纹和随机接入码，不需要手工运行证书命令。
3. 核对“提供给成员的地址”。默认使用管理端电脑名；成员电脑无法解析时改成管理端固定内网 IP。
4. 监听端口默认 `18443`。监听地址默认 `0.0.0.0`，允许内网网卡接入；需要限制网卡时在折叠区修改。
5. 选择管理端访问外网的方式：
   - **本机直接访问**：管理端本身可以访问模型服务。
   - **HTTP 代理**：填写上游代理地址、端口及可选账号密码。
   - **SOCKS5 代理**：填写上游代理地址、端口及可选账号密码。
6. 点击 **保存并应用**。设置立即生效；下次打开管理员版会自动恢复并启动。
7. 用 **测试 Codex**、**测试 Cursor**、**测试 Claude Code** 验证管理端到目标服务的连通性，再复制用户端接入码。

管理员需要提供的信息只有一段接入码。它已经包含管理端地址、端口、TLS 证书指纹和随机访问密钥，不需要再让成员分别填写这些字段。接入码等同于本出口的访问凭据，只发给需要转发的成员。点击“更新接入码”会让旧接入码立即失效，所有使用者需要重新粘贴。

管理端程序必须保持运行。关闭管理员版会停止出口；再次打开后按已保存配置自动启动。当前版本没有安装独立 Windows 服务，也不会自动添加防火墙规则，因为这些动作需要系统管理员权限。部署时由运维只对公司内网来源开放所选 TCP 端口，不应暴露到公网。

上游代理密码、出口访问密钥和用户端保存的接入密钥在 Windows 支持时使用 Electron `safeStorage` 加密后写入各自应用数据目录。普通配置文件不包含这些明文。TLS 证书和私钥只保存在管理端本机数据目录。

## 用户端配置

1. 本机能直接访问模型服务时保持选项关闭，按原方式登录团队共享空间。
2. 本机不能直连时，在用户版登录窗口勾选 **通过管理端访问模型服务**。
3. 首次粘贴管理员提供的接入码；之后工作台会记住接入信息和密钥，除非管理员更新接入码。
4. 继续填写团队 SSH 账号密码并登录。共享空间登录与出口配置彼此独立，出口异常不会改变项目权限。

启用后，用户版自动在 `127.0.0.1` 上选择空闲端口，并向工作台启动的 Codex/Cursor/Claude Code 进程注入 `HTTP_PROXY`、`HTTPS_PROXY`、小写兼容变量、`NO_PROXY` 和 `NODE_USE_ENV_PROXY`。关闭选项会停止本机代理且不注入这些变量。系统代理、浏览器和工作台之外启动的 CLI 不会被修改。

出口设置改变时，工作台会关闭空闲的 CLI 运行时并重新检测账号。正在运行或等待授权的会话不会在中途切换网络，需等待任务结束后再修改。

## 固定边界

- 管理端只接受接入码正确且证书指纹匹配的 TLS 连接。
- 目标仅允许配置中启用的 Codex/Cursor/Claude Code 官方域名后缀和 TCP 443；任意域名、任意端口及普通 HTTP 请求会被拒绝。
- 用户端不会信任系统中任意证书；它固定校验接入码携带的管理端证书 SHA-256 指纹。
- 管理端不记录报文正文。界面中的最近连接记录只保留当前进程内的目标域名、状态和字节数。
- 接入码用于控制网络出口，不替代 SSH 成员身份，也不授予任何共享空间权限。

若厂商今后新增必需域名，旧版白名单可能导致该请求被拒绝。先确认域名属于官方服务，再由开发者更新 `src/core/egress.ts` 的产品白名单并重新发布客户端；不要把出口改成任意目标的通用代理。

## 验收

开发环境执行：

```powershell
npm run check
npm run test:egress-ui
npm run test:connection-ui
```

自动化用例覆盖接入码解析、域名与端口白名单、TLS 指纹不匹配、错误密钥、管理端经 HTTP CONNECT 上游的完整字节往返、关闭后恢复直连、CLI 登录检测继承代理环境，以及两端图形界面的启停和可选入口。正式部署还需要从一台无外网成员电脑使用真实个人账号分别完成 Codex/Cursor/Claude Code 登录检测和一次模型请求。
