# 动态、成果、整理记录的独立生命周期

2026-09-22；本次实现范围：整理记录删除与增量进度解耦。项目分类自定义、引导交互不在本次提交中。

## 这些对象分别是什么

| 对象 | 标识与归属 | 用途 | 是否决定增量起点 |
| --- | --- | --- | --- |
| 原 Session | 本机 Session ID、消息 ID | 原始对话和已引用的冻结资料 | 是，进度独立保存在这里 |
| 整理进度 | Session 上最后成功整理的快照边界 | 记录已经处理到哪条消息 | 是，不依赖整理记录/成果是否保留 |
| 整理记录 | Draft ID、冻结输入、运行状态、结果 | 审阅、重试、上传的工作记录 | 否；有成果时完成即推进，空结果确认后推进，删除不回退 |
| 本地项目成果 | 独立成果 ID、正文、来源快照、删除标记 | 个人编辑、查找和供 Session 引用；个人账号同步 | 否 |
| 团队项目成果 | 远端 ID + revision | 团队共享的成果及附件 | 否 |
| 动态 | 账号/项目/远端 ID/变更类型/版本 | 通知变化、记录个人处理结果 | 否 |
| 上传任务 | Transfer ID、冻结上传包 | 上传状态与失败重试 | 否 |

增量是“原 Session 的消息增量”，不是“在旧结论正文上补写”，也不是“未读动态增量”。更新已有正文、合并多个成果仍须用户明确操作。

## 删除正交矩阵

| 操作 | 整理记录 | 本地成果 | 团队成果 | 动态 | 已引用的 Session 内容 | 增量进度 |
| --- | --- | --- | --- | --- | --- | --- |
| 单条/批量删除整理记录 | 删除，先停止所选正在运行的整理；批量部分失败可单独重试 | 保留正文、来源与人工修改 | 保留 | 不改变 | 保留冻结快照 | 保留 |
| 删除本地成果 | 保留 | 删除标记，防止重启重新生成同一项 | 保留 | 已有关联处理记录可记载删除；不产生团队变更 | 保留冻结快照 | 保留 |
| 删除团队成果 | 保留 | 保留，用户可在删除动态里另行选择删除 | 删除，由服务端校验权限和版本 | 无处理历史的待处理旧动态移除；已处理或有处理历史的旧动态标记来源不可用；增加删除动态 | 保留冻结快照 | 保留 |
| 归档/删除动态 | 保留 | 保留 | 保留 | 只改个人通知记录；保留已扫描版本，避免重复通知 | 保留 | 保留 |

“记录在/不在 × 成果在/不在”四种组合全部从同一个 Session 整理进度继续：

- 想只处理后来发生的内容：增量整理。
- 想重新提炼被删成果所依据的旧内容：主动选全量整理；不会在普通增量中悄悄恢复旧成果。
- 只有摘要或参考附件变化，没有新增/续写消息：使用全量整理。本轮没有把文件系统变化偷偷扩大为消息增量。
- 没有进度，或进度对应的原消息无法定位：拒绝增量并提示全量，不猜起点。
- 原 Session 不在本机（例如换电脑）：账号恢复的成果/整理记录仍可阅读、删除；不能凭整理记录重建原对话或推断增量。

## 本次发现并修正

1. 删除整理记录原先剥离本地成果来源并归档自动成果。现在只删记录，不再修改成果。
2. 已上传/已保存的记录原先禁止删除。现在也能删除，列表和详情均有确认入口；上传包与重试记录保留。
3. 增量原先依赖仍然存在的某条 Draft。现在独立保存最近成功快照，旧记录删除、跨电脑同步删除、重启都不回退。
4. 从历史整理记录进入“再次整理”可能重复整理已被更新记录覆盖的范围。现在以 Session 最近成功进度为准。
5. 流式回复追加文字但消息 ID 不变时，原先会漏掉追加部分。现在保存末条消息长度；长度变化时重读该边界消息。旧数据缺长度时保守重读一次。当前协议按追加流处理；这不是任意历史文本编辑的 diff 引擎。
6. 对已完成增量任务使用旧版重试入口会刷新成全量输入却保留增量标识。现在标识和输入同步改为全量。失败重试仍沿用冻结输入。
7. 旧版“复制为新版本”可能引用原记录的输入文件。清理原记录时检查其他记录/传输是否仍引用，不能误删这些共享快照。

失败、取消、运行中、合并处理、跨机恢复记录不推进消息进度；成功但没有新成果时，须由用户确认本次无需保留后才推进。按输入捕获时间而不是完成时间推进，避免晚完成的旧任务回退进度。

## 尚需产品决策的耦合/差异（未在本次擅改）

1. **上传勾选兼作本地成果开关。** `selectDraftArtifact → syncDraftConclusions` 会在取消上传勾选时归档对应自动本地成果。建议将“是否上传”与“是否保留本地成果”分开。
2. **本地成果是整理后自动加入，不是上传后才加入。** 这满足“本地总结也要在成果库中”的要求，但上传待确认不等于本地尚未入库。界面不能把这两种状态混称为“未处理”。
3. **远端删除规则与早期要求不完全一致。** 当前保留已处理或有处理历史的动态并标记来源不可用，只移除无处理历史的待处理旧动态；本地副本需要用户另行选择。早期曾要求旧已读/未读动态全部移除。建议按“变化通知”和“个人处理历史”分开理解，确认后再决定是否清除历史；本轮没有删除用户真实数据。
4. **手改本地正文后，再接收远端更新只更新来源，不覆盖人工正文。** 有意保护人工内容，但还需要清楚区分“来源已更新”和“正文已更新”。
5. **项目动态数、远端成果数、本地成果数本来就不能相等。** 一个成果可以有多次动态，多个成果可以合并，个人副本可以删除或保留，首次同步默认只建最近 24 小时动态。
6. **超过 100 条自动成果会归档旧项。** 归档不删除，但默认匹配和去重只查看当前未归档成果，可能影响旧知识的召回。是否采用不同上限/历史检索应另行确定。
7. **账号同步与 Session 本地保存有明确边界。** 删除整理记录会同步到同账号其他电脑；Session 和进度不会迁移。跨电脑并发编辑/删除可能进入已有的账号冲突处理，不能自动覆盖一端的修改。
