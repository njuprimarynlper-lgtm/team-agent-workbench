# 项目与角色

## 选择入口

系统管理员使用**管理端**，以 Linux root/sudo 账号登录，创建和维护用户账号，查看全部项目、成员与共享空间。

所有项目参与者使用**用户端**，以自己的 SSH 账号连接中央节点。任意已启用账号都可以创建独立项目；一个账号可加入多个项目，在各项目中担任不同角色。项目直接承载成员权限、说明、成果和任务，没有工作组下面再建项目的步骤。

| 操作 | 成员 | 管理者 | 创建者 | 系统管理员（管理端） |
| --- | --- | --- | --- | --- |
| 查看项目资料、上传成果、开展会话 | 可以 | 可以 | 可以 | 全局查看与管理 |
| 完善项目资料、整理成员成果、派发和审核任务 | 不可以 | 可以 | 可以 | 全局管理 |
| 添加或移除已有账号、任命管理者 | 不可以 | 不可以 | 可以 | 可以 |
| 移交创建者、删除项目 | 不可以 | 不可以 | 可以 | 可以 |
| 从回收站恢复或彻底清理项目 | 不可以 | 不可以 | 不可以 | 可以 |
| 创建、停用用户或重置密码 | 不可以 | 不可以 | 不可以 | 可以 |

创建者只有一位，管理者可以有多位。创建者具备管理者能力；项目角色不授予系统管理员身份。旧版“组管理员”对应管理者。

## 用户创建并协作

1. 点击用户端顶部**创建项目**，输入名称，填写中央节点 SSH 连接或复用已登录连接。
2. 连接后填写项目资料并创建。服务器按当前登录身份登记创建者，同时准备成员权限和项目目录。
3. 点击项目名称右侧的齿轮，进入**成员与权限**，添加已有账号并选择成员或管理者。新账号由系统管理员先创建。
4. 其他成员连接该节点、刷新项目列表，即可进入获授权的项目。

例如 Alice 创建“量化转换”，加入 Bob 为管理者、Carol 为成员。Bob 可维护验收指标、整理团队成果、派发任务；Carol 可读取资料和提交实验记录。Bob 和 Carol 均不能调整成员资格或删除项目。Carol 仍可另行创建自己的独立项目，成为该项目的创建者。

管理端也可先准备项目及成员权限。此时用户端显示同名项目，创建者或管理者点击**完善项目资料**填写说明，不再另起一个项目名称。

## 移交与删除

在项目设置的**成员与权限 → 移交创建者权限**中选择已有成员并确认。原创建者保留管理者权限；必须先移交，才能移出或降级原创建者。

只有创建者或系统管理员可以删除项目。确认窗口显示成员数及占用空间；成员或内容已变化时需重新确认。删除后共享内容进入系统回收站，成员无法继续访问；本机代码、会话和已有副本保留。

管理端的**项目管理 → 项目回收站**可恢复项目及内容，或彻底清理。彻底清理不能撤销。创建者离职或账号停用时，由系统管理员指定新的创建者。

## 旧组与升级

现有一一对应的成员范围和项目资料按一个项目展示，保留原有 ID、目录、成员和会话关系。旧记录没有创建者时显示**待指定**，由系统管理员指定，不擅自提升已有成员。

正式环境更新两端源码后，由管理端执行**更新服务端功能**。成员重新连接或刷新项目。创建中断时，管理端可在**创建未完成**记录中继续操作；目录或 Linux 组身份不符时拒绝接管。

## 验证与边界

服务器使用实际 Linux UID、账号标记和当前成员关系验证操作。Linux 用户组和 ACL 是项目权限的内部实现，客户端不要求成员再选择一层用户组。移出成员会撤销相应权限及旧连接，不删除本机副本。

后台测试使用临时目录和本地文件系统替身，包括 `tests/managed-project.test.ts`、`tests/team-groups.test.ts` 与 `tests/test_team_groups.py`。Windows 上的服务器用例模拟 Linux 账号命令；真实 UID/GID、ACL 和 SSH 撤权仍需在 Linux 部署环境验证。
