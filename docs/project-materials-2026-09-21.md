# 项目笔记与附件：实现和验收

## 用户侧变化

- 左侧“我的项目笔记”显示当前账号在所选项目下的项目笔记，包括个人整理、手工记录和从共享区加入的内容；不是整个项目的公共资料管理入口，组管理员和普通成员使用相同名称。类别为项目结论、项目标准、方法探索、问题与风险、改进建议；旧成果类别与目录继续兼容。
- 新整理不再先选类别，最多 3 项，允许没有新内容；提示词要求去重、合并同主题、区分已确认规则与探索建议，标题面向未读原会话的成员。技术细节放默认收起的来源详情。旧内容不批量改写。
- 会话输入区可随时引用项目笔记，已加入的条目保持勾选且不可取消。首次提问仍用 BM25 与规则推荐，不调用 AI 匹配。手工创建、编辑及人工确认的 AI 处理入口保留。
- 保存时按来源 ID 区分资料：不同共享成果或整理条目独立保存，即使标题、正文相似或相同也不自动归并。同一来源 ID 的新版本可更新对应资料；手工修改的正文不被覆盖。BM25 仅用于检索推荐，合并需用户选中并确认。
- 从旧动态加入已经更新的成果，先确认当前标题和版本；处理记录区分动态原版本与实际加入版本。旧版误归并记录会从保存的来源快照恢复独立资料，保留原综合结论、手工别名和 Session 引用；修复前备份在本机数据目录的 `migrations/import-links-*.json`。
- 代码目录选填。留空使用应用数据目录下独立、持久的工作目录，不把整个应用数据目录交给模型。既有 Session、引用和目录不迁移、不删除。

## 附件

- 从冻结的参考材料和工作目录中已记录的产出文件识别候选，不遍历目录；不自动加入会话全文、阶段记录、隐藏目录或密钥文件。模型只能推荐已有文件 ID，建议默认不勾选。
- 每项成果可手工添加、勾选和预览附件。每项最多 30 个文件，单文件最多 2 GB；自动候选只读取不超过 10 MB 的普通文件，大文件需手工添加。
- 选择时保存副本，提交时再次固定并验证哈希。同批相同内容只上传一次，各条成果引用同一份文件。成果等待其附件全部上传成功才发布；失败可重试，成功附件不重复发送。
- 列表显示附件数，详情提供附件预览、下载；结论自身不增加下载入口。文字成果合并保留附件引用。

## 账号同步与范围

- 自动同步个人项目笔记、别名、整理结果、明确选中的附件、动态已读/处理/关闭状态；本地为持久缓存，离线修改保留，登录后恢复。应用开启期间每分钟检查远端变化，保存后短暂合并再同步。
- 不同步 Session、完整对话、输入框、原生模型状态、代码目录、CLI 登录凭据。既有明确授权的“轨迹上传”是独立功能，不属于账号同步。
- 整理任务恢复的是结果，不恢复原 Session，也不自动重跑 AI。原会话不存在时不能继续做原会话的增量整理。
- 个人数据通过已认证账号的受限请求存入服务器 root 私有目录，不写入公共项目目录。附件只有明确提交成果后才复制到项目组可读的附件存储。
- 采用版本校验和三方比较；同一资料被两台电脑分别修改时，显示两个版本由用户选择，不直接覆盖。账号切换不把旧账号资料上传给新账号。丢失组成员资格不删除已有项目笔记。
- 单个账号的 JSON 元数据快照目前上限 2 MB，附件单独存储不计入此限额；超限或不支持新协议时显示失败并保留本机内容。共享附件和私有附件的无引用文件暂不自动回收，避免删除正在提交或其他记录引用的文件。

## 部署

必须同时更新用户端及服务端。用新版管理端连接既有空间，在用户管理页点击“更新服务端功能”，安装新版文件操作器；不要重新初始化已有团队空间。本次代码修改没有对真实服务器执行部署，没有恢复 GitHub 对端定时任务。

## 验证边界

- 已有 Session/草稿保留、后台协议回归、双本机目录模拟换机恢复、账号隔离、版本冲突、附件依赖重试、去重及恢复有自动测试覆盖。
- 服务端业务规则覆盖私有记录版本校验、越权拒绝、附件哈希/路径校验及私有文件隔离。Windows 上不能代替 Linux ACL 实机验收。
- 用户反馈测试闪屏后停止全量启动器测试。后续使用不含启动器的后台回归与服务端测试；React 静态渲染检查不会启动窗口。测试启动器的 Node 替身已改为显式隐藏启动，但本轮未重新执行该套启动器测试。
- 未重新跑真实模型整理或可见 Electron 界面。生成文字的实际可读性仍需用真实成果由项目成员确认。
