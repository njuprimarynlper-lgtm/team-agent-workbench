# 首位成员与项目初始化

## 管理员分配成员

只要目标组还没有成员，首次在组内创建用户、将已有用户加入该组，或者全局创建用户时勾选该组，界面都会默认选择“项目子管理员”。管理员可以在提交前改为普通成员。

该默认值按每个组独立计算。后续成员默认普通成员；已有成员但没有子管理员的组不会自动提升新成员，停用成员仍计入成员数。已有账号和组不做角色迁移。子管理员只管理本组项目内容，不能管理账号或任命其他子管理员。保存沿用已有的本地权限桩或 Linux 用户组/ACL 操作，不依赖用户版自选身份。

## 子管理员首次使用

登录并发现工作组后，如果具有子管理员权限的组内没有已登记项目，自动显示“建立第一个项目”。填写：

| 内容 | 要求 | 用途 |
| --- | --- | --- |
| 项目名称 | 必填 | 创建项目目录 |
| 项目背景 | 必填 | 问题、服务对象与业务场景 |
| 项目目标 | 必填 | 预期结果与当前阶段优先级 |
| 验收标准 | 必填 | 完成标准、验证方式、验收人 |
| 范围与非目标 | 可选 | 本阶段边界与暂不开展的工作 |
| 交付物与里程碑 | 可选 | 交付形式和关键时间节点 |
| 现有资料与入口 | 可选 | 文档、仓库、样例、环境说明等；没有仓库也可提交 |
| 约束与风险 | 可选 | 技术、时间、数据使用边界与待确认问题 |
| 协作约定 | 可选 | 分工、评审、沟通节奏和决策记录 |

未确定的必填事项可以注明待确认。每项说明最多 6000 字；可选项默认折叠，保存按钮固定在弹窗底部。界面明确显示当前账号、组和共享路径。

点击“保存并创建项目”，使用当前成员权限在共享区写入：

```text
工作组目录/
└─ 项目名称/
   ├─ 项目说明.md
   ├─ .workbench-project.json
   ├─ submissions/
   └─ trajectories/
```

项目标识最后写入，资料写入失败会尝试清理本次创建的文件和空目录，不覆盖已有项目。同组成员刷新后即可在共享文件区预览说明；已有“加入当前会话”操作可以把说明快照作为 Agent 参考。这里收集的是团队项目资料，与个人会话的 Agent 工作记录、成果整理和轨迹上传分开。

## 稍后填写与隔离

“稍后填写”或右上角关闭不会创建目录，也不影响本地会话。草稿按服务器/共享区、账号、用户组分别保存在本机；重新打开界面、重启后登录同一共享区可继续填写。重新导入同一共享区的连接配置不会丢失草稿。保存成功后删除对应本机草稿。

同一轮登录只自动提示一个空组，其他空组在侧栏提供“完善项目资料”。选择稍后填写后不持续弹窗；下次登录仍为空则再次提示。普通成员不显示引导。是否需要初始化按有效项目记录判断，`.keep` 等杂项不会阻止初始化；访问失败单独报告，不误判为空。

提交时后端重新读取成员身份和目录状态，拒绝撤权、切换账号/共享区、项目身份已改变的旧表单。不会因为页面上有创建按钮就跳过权限校验。

## 验证

- `npm run typecheck`、`npm test`：首位成员默认值、本地/SFTP 初始化、必填校验、身份隔离、撤权拒绝、成员读取、写入中断清理、既有工作区回归。
- `npm run test:onboarding-ui`：管理员两种视图的默认身份、显式改回普通成员、首次登录、稍后填写、重启恢复、全字段写入、多账号隔离和 1100 像素窗口布局。
- `npm run test:admin-ui`、`npm run test:workgroups-ui`、`npm run test:local-ui`、`npm run test:ui`：管理员、多组、本地双用户和 SFTP 原有使用流程。

开发版通过 `dist/admin`、`dist/user` 启动。此项未重新生成安装包。

已有组里创建第二个及后续项目，同样填写资料或明确选择稍后完善；在项目侧栏“项目资料”查看/修改，更新生成版本，成员自行采用。
