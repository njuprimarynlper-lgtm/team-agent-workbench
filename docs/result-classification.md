# 个人成果分类与任务入口

## 设置和使用

“设置 → 整理分类组合”维护自己的分类组合，也可在整理范围窗口点击“调整分类组合”。每个账号独立维护、每个项目选择一个组合；保存后通过个人账号资料同步。预设为算法研究、软件开发、调研分析，各预设可复用同一类别。在顶部下拉菜单选择“新建组合…”即可命名并勾选类别，不需要重新定义类别或生成规则。选择已有自建组合后点“编辑组合”可改名或修改类别；展开“管理我的组合”可删除未使用的组合。

整理窗口的分类下拉菜单另有“临时组合（仅本次，不保存）”：无需命名，可从全部类别中勾选，点击“用于本次整理”返回整理选项。临时组合仅保留在当前窗口内，不写入个人组合、不修改项目默认选择，也不作为个人设置同步。关闭窗口后丢弃；创建整理任务后，仅任务记录保留本次类别供重试和成果校验使用。重新发起整理默认回到项目已保存的组合，仍可再次选择临时组合。

修改自建组合会影响自己所有使用它的项目，仅对后续整理和手动新建生效。进行中的整理保存当时的组合，重试沿用该组合；再次整理使用当前组合。不能删除仍被项目使用的组合，须先切换并保存。修改设置不重写旧成果、原 Session、已带入会话的内容或增量进度。

## 整理入口与空结果确认

首次整理与“再次整理”使用同一窗口：展示当前分类组合和本次类别勾选，独立的“调整分类组合”按钮可修改个人组合。取消某个类别仅影响本次；组合设置影响后续整理。再次整理明确显示增量消息数或完整会话消息数，避免把增量误当成全量。

类别纵向排列，勾选后在下方展开占满行宽的多行“整理方向”输入框，每类独立填写（最多 4000 字）。首尾空白会被去除；仅空格、Tab、换行等空白视为留空，使用该类别的默认提示词。取消勾选时收起输入框并保留当前窗口内的文字，但未勾选类别的方向不会进入任务。方向只影响本次任务的对应类别，不改变个人组合；与任务一起保存及同步，重试沿用，再次整理时预填供修改或清空，仍须遵守材料证据与原有输出规则。

未生成新成果时，页面展示本次范围、类别及原因；因已存在而省略时列出可打开核对的已有成果。用户可以“确认本次无需保留”，也可调整分类或全量重做。确认会保存记录并推进这次消息边界，不创建空成果、不上传、不自动确认其他记录；确认状态随个人账号同步。旧记录没有原因时明确说明，不补造模型判断。

工作台在调用整理前，将冻结对话、索引转为 ASCII JSON 转义格式，并把 UTF-8 / 带 BOM 的 UTF-16 文本资料按块转换成同一格式；模型按索引读取。此转换由程序执行，原附件字节和哈希不变；旧快照重试也经过此步骤，消除 Windows PowerShell 默认代码页误读中文的问题。读取回执及空结果原因用于校验材料范围，不代表模型的语义判断已经得到事实验证。全部候选被环境规则过滤与模型主动返回空结果分别展示。

旧快照缺少最后一条消息长度时，程序从哈希一致的冻结对话恢复边界；不会把原消息误计为新增。找不到可核实的旧快照时仍保守重读边界。旧版自动推进的空结果在记录仍存在且尚未确认时，回到之前有效进度；已经确认的进度不因删除整理记录而回退。

## 四类成果与展示

| 类别 | 放什么 | 怎么处理 |
| --- | --- | --- |
| 项目目标 | 目标、范围、验收标准及约束 | AI 整理后待确认，由人确认；修改保留历史 |
| 已有能力 | 已实现的能力、使用条件及限制 | 同一条目只展示当前版本，历史版本从侧栏查看 |
| 探索记录 | 方案、尝试、观察、取舍及依据 | 保留适用条件、失败尝试和未验证部分，不自动变成已实现能力 |
| 待办事项 | 待完成动作、缺陷、风险及待确认问题 | 独立事项逐条保存；完成后保留并置灰，可重新打开 |

个人成果库与团队成果库使用相同四类页签，分类以记录本身为准，不根据关键词或本地别名猜测。团队成果默认显示所有当前条目，可选仅查看与个人库有差异的内容。会话轨迹不进入成果列表。

旧类别继续可读：项目标准、需求说明归入项目目标；问题与风险、改进建议归入待办事项；其他旧成果归入探索记录。只映射显示和筛选，不批量改写原内容、路径和会话快照。原类别信息仍在历史版本中。

## 整理、复核与保存

点击整理时冻结当时对话副本。之后继续对话，不会改变这次整理的输入。模型只填有实际材料的类别，同一主题可以形成能力、探索和待办，但各条承担不同信息，不重复正文。

预览左侧选择条目，右侧直接修改标题和正文；来源收在“查看依据”中。修改分类保留正文和来源，清除不再适用的能力更新目标，并采用新类别的初始状态。上传路径随类别自动选择，不要求提供 Git 仓库链接。顶部“关闭”返回原界面，正在整理时另有“停止整理”。

已有能力可以另存为新条目，或选择更新本项目的个人能力。只有用户保存时才更新，保留原 ID、旧版本和来源；若目标期间被修改则拒绝覆盖，要求重新核对。模型只能建议已有条目的真实 ID，不能根据相似名称直接覆盖。不同环境或适用范围应另存。此选择作用于个人库；提交团队仍是新提交，团队原件由有权限的成员或组管理员维护。

个人保存和团队提交独立。上传成功前保留草稿和传输状态，失败可重试。普通成员只能修改自己的、尚未由组管理员整理的团队提交；组管理员可以维护组内内容。状态或正文更新保留版本记录，旧版本不会与当前版本混排。

## 合并与任务边界

只能处理同一分类的文字成果。选择首条后，其他分类的勾选和切换入口置灰；后台和 Linux 文件操作器也校验分类与来源版本。合并结果不能在预览中改类，需先返回修改来源分类。旧客户端绕过界面提交也会被拒绝。

合并先生成可编辑预览，再由用户保存。待办的多条合并还须勾选确认这些是同一事项的重复记录，独立动作分别保留。勾选的来源移入历史，未勾选的来源继续可用；新成果保留来源及版本。来源期间更新或删除时，本次结果不能覆盖它。

普通待办可标记完成、取消或重新打开；“已完成”筛选和默认列表都能查看完成项。已经关联项目任务的待办显示任务进度，由任务的提交、验收流程处理，不能在成果库直接完成、改类或合并；全部关联任务结束后才显示结束状态。无权查看关联任务详情的成员只看到“跟随项目任务”，不推测其完成情况，任务私有内容也不会因此公开。

## 生成规则与兼容

- 新整理每次最多 50 条，用于容纳独立待办；超过范围或材料读取不全时返回失败说明，不静默截断。合并仍最多生成一条。
- 标题说明实际对象；正文保留依据、适用条件和未验证边界。来源详情默认收起，不把完整对话或凭据上传为成果。
- 本机安装、登录、依赖等排查日志不进入成果；项目产品自身的权限、网络或代理缺陷仍应保留，不因关键词相同而误删。
- 校验来源 ID、读取回执、重复内容、类别及状态。来源 ID 有效不代表内容已经事实验证，仍需审阅。
- 已经开始的旧整理沿用当时规则；新整理采用四类。历史自定义组合映射到新分类，保留个人设置与换机同步能力。

## 任务入口

组管理员可以“分配给自己”。“我负责的”只看自己要做的，“我派发的”只看自己创建的；自派任务在两个视角出现，但只有一个任务 ID 和状态。另保留“全组任务”供管理员检查其他管理员派发的工作；归属在同一排分段按钮中切换，数量用独立徽标显示；右侧状态下拉选择待办、全部或已删除，避免两排重复标签。普通成员仅查看自己的任务。

关联成果的候选和任务详情与共享成果库共用 `【类别】 标题` 显示规则，别名只替换主题，不丢掉类别。派发时保存类别、内容及版本快照，后续共享成果改名、改类或删除不改写该快照。历史任务没有类别字段时沿用标题里已知的类别；确无类别时显示 `【项目成果】`，不猜测内容归属。

## 任务文件

任务可关联独立共享文件、成果自带的附件，以及派发人选择的本地文件。勾选成果时默认包含其附件，可逐个取消；本地文件选取时先冻结副本，确认派发才上传。最多关联 30 个文件，每个不超过 2 GB；名称和内容均相同的文件在同一任务内只列一次。任务详情可下载，开始工作时自动下载到会话的独立文件快照，不自动发送模型请求。

任务附件只允许当前负责人及本组管理员读取，成员资格和账号状态每次重新检查。不会因为派发附件而新增公开成果。已关联共享文件原有的共享权限不变；任务另外保存私有快照，原共享成果被删或修改不影响任务及已开始的 Session。

任务文件后台按“项目 ID、负责人、当前组管理员访问策略”划分去重范围；同一范围内计算 MD5、SHA-256 和大小，以 MD5 为索引再用 SHA-256/大小隔离碰撞。同内容仅保存一个不可变数据文件，各任务各自持有稳定路径的软链接。权限策略不同不复用同一数据文件。仅专用的受控任务文件读取逻辑可解析这些 root 所有的链接，并核对目标范围与文件摘要；通用文件 API 仍拒绝符号链接。

Linux 使用软链接，Windows 本地权限模拟使用硬链接，不要求开启开发者模式或授予软链接权限。此改动仅涉及新的任务附件链路，不迁移旧共享文件。上传暂存文件在任务保存成功后清理；失败保留以便重试。未完成的本机选择快照、失败任务的暂存或无引用数据暂不自动回收，不通过猜测删除文件。

## 任务验收、取消和删除

- 正常流程为“待开始 → 进行中 → 待验收 → 已完成”。负责人提交简短结果说明，可关联最多 20 项成果/文件和 30 个附件；内容及附件冻结为本次验收快照，不上传完整 Session。以任务目标和验收要求为准，有依据的否定结论可以完成探索任务。
- 组管理员验收通过或填写原因退回“进行中”，记录实际操作人。退回后再次提交保留历次结果、证据和意见。只有组管理员自己派给自己的任务可以在填写结果后二次确认直接完成；其他任务不能跳过提交验收。
- 待验收仍属于待办。模型回复结束、关闭会话、上传成果不触发任何任务状态变更。待验收期间不从任务入口新建会话，已存在的 Session 不关闭、不停止；退回后复用原会话。
- 组管理员填写原因后可取消任何未结束任务，不计为完成。已完成/已取消为结束状态；验收、取消后都保留附件和已有成果。
- 仅组管理员可以删除已结束任务，先移入“已删除”，普通成员的正常列表同步移除；管理员可恢复，恢复后仍是原来的结束状态，历次验收和附件不丢失。日常查看历史记录无需删除任务。
- “已删除”内可彻底删除，需再次确认并输入任务标题。服务端清除任务正文、关联及验收记录，仅保留防止旧请求复活任务的最小路由/状态墓碑；无法恢复。不删除共享成果、本地成果、Session、对话及已进入 Session 的独立文件快照。
- 彻底删除先持久化墓碑，再移除此任务的受控文件链接。相同权限分区中，只有不再被任何任务（包含可恢复任务与历史验收提交）引用的专属数据文件才能回收。通用共享附件不参与任务回收。清理中断或文件损坏时宁可暂留无引用文件，不冒险删除；不做全盘扫描或自动删除本地缓存。
- 所有流转按当前组权限和修订号检查，过期操作不能覆盖他人处理。旧客户端直接“标记完成”的请求不再绕过验收。新客户端使用专门的生命周期协议，旧服务器明确提示升级，不静默退回旧完成逻辑。

## 更新与验证范围

客户端和 Linux 服务端都需要更新。已有空间使用新版管理端的“更新服务端功能”，不重新初始化空间；本次修改没有部署真实服务器。旧服务端尚不接受新增类别及个人分类配置记录时，上传或账号同步会失败并保留本机数据。

后台测试覆盖配置的个人隔离、换机恢复和冲突处理、冻结规则、类别校验、重复/环境过滤、上传及接收类别保留、自派任务和权限、任务状态矩阵、验收退回及证据保留、删除恢复和去重引用安全回收、无窗口静态渲染。Windows 不验证 Linux 内核 ACL；未在正在使用的桌面启动 Electron 或进行键鼠自动化，也未发送真实模型整理请求。
