# 成果库管理

个人与团队成果库使用相同的目录选择方式。五个固定一级目录同时决定成果分类；各自的子目录独立管理。

## 标题与编辑

- 标题旁的铅笔用于修改本地别名，个人和团队成果均可使用。Enter 保存，Esc 取消，留空保存可恢复原名。团队别名仅作用于当前账号，不修改公开标题。
- 个人成果的“编辑”与“删除成果”直接显示在卡片操作区；“移入历史”位于“更多”菜单。
- 团队成果由提交者维护标题、正文、状态及附件。管理员不能编辑他人的这些内容，但可更改路径、删除成果或整理成一份新的管理员成果。既有的“已整理”标记不会剥夺原提交者的控制权。
- 自己提交的团队成果也支持直接编辑、替换文件、批量管理与删除；工作台、本地共享服务和中央节点均校验权限。

## 目录与分类

“更改个人目录”与“更改团队路径”打开目录树。初始只展示五个一级目录，箭头展开或收起当前分支，点击目录名称选择目标；选择不会展开其他分支。面板底部保留目标位置，即使其所在分支已收起也能确认。

不再提供独立的“修改分类”操作。跨一级目录移动时，分类随目标一级目录变化，状态重置为新分类的默认值；移动前版本仍可查看。同一级目录内移动只改变目录位置，不产生正文新版本。正文、附件及成果 ID 均保留。

已关联项目任务的待办不能移出“待办事项”，以免绕过任务进度和验收规则。

## 分享至团队

个人成果的“更多”菜单只保留一个分享入口：

1. 首次显示“分享至团队”，选择团队目录后提交。
2. 已分享时显示“更改团队路径”。默认只移动原团队成果，不上传本地未分享的修改。
3. 本地与已分享内容有差异时，可勾选“同时更新团队内容”。确认后使用同一团队成果 ID 更新正文及附件。

明确更新会校验用户在窗口中看到的团队版本；窗口打开期间如有其他修改，本次更新会被拒绝。原团队成果已不存在时给出提示，不悄悄新建替代条目。

## 验证入口

- `node scripts/result-directories-smoke.mjs`：目录层级、新建、移动、个人与团队目录独立以及整理结果保存。
- `node scripts/result-library-actions-smoke.mjs`：别名、提交者与管理员操作、分享路径与显式更新。
- `tests/result-directories.test.ts`、`tests/result-publication-lifecycle.test.ts` 及 Python 内容服务测试：权限、版本冲突、状态联动和历史保留。
