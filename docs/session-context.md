# 会话资料只增量提供

同一原生会话首次使用项目说明或参考文件时，工作台向 CLI 提供快照路径、来源和哈希。后续对话沿用该会话上下文，不再逐轮拼接同一段资料。采用新版项目说明或添加新资料后，仅补充新增版本一次。各个会话独立记录，不跨会话复用已发送状态。

每条用户消息分别保存原始输入 userText 和实际发送内容 text。聊天气泡只显示原始输入；项目资料版本仍在会话上方显示。轨迹 JSON、Markdown 和工具事件保留实际输入，不删除审计信息。

是否已经提供资料，以 CLI 接受的消息为准。Codex turn/start 返回成功后标记；Cursor session/prompt 正常返回后标记。如果发送前失败，下次重试仍携带资料。恢复原生会话、重启客户端或修改权限后，已接受的引用状态保留；原生会话 ID 改变则重新提供上下文。仅检查本次新增引用的快照完整性。

升级时识别旧消息末尾由工作台生成的完整资料段及工作记录约定：只识别本会话已有快照的精确路径、来源、哈希，不删除用户普通文字或对标记的引用。旧消息原文仍保存在 text 中；生成 userText 用于展示。旧会话已有后续模型或工具响应的资料视为已提供，无响应的旧输入保守地在重试时补充。

验证：

- tests/session-context.test.ts：Codex/Cursor 首次和后续请求、恢复会话与修改权限、新版本、独立会话、未接受请求重试、快照篡改、非法引用、旧记录迁移及轨迹保留。
- scripts/session-context-smoke.mjs：真实桌面界面配合隔离 CLI 桩，检查用户气泡、后续实际请求内容和旧会话展示。
- tests/agents.test.ts、tests/permissions.test.ts、tests/session-experience.test.ts：原生协议、权限及整理/关闭会话回归。

桌面用例使用独立数据和文件系统目录，不改动现有成员账号和共享资料。
