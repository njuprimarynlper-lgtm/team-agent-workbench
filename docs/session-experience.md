# 会话、成果整理与轨迹上传

本页描述当前源码与开发构建。已有安装包保存在 release/版本号/，本次工作记录说明与取消操作调整先同步到本地打桩，不改写已发布安装包。运行仓库根目录 `start-user-dev.cmd` 查看已编译的用户界面；源码修改后先运行 `npm run build`。默认继续使用 `%APPDATA%\TeamAgentUser`；若设置 `WORKBENCH_DATA_DIR`，沿用指定数据目录。不要同时启动两个使用同一数据目录的用户进程。

## 用户操作

1. 新建会话先选择 Codex / Cursor。登录状态展示 CLI 返回的邮箱；Codex 还展示返回的套餐。已经登录时，“登录个人账号”禁用；“重新检测”可刷新外部 CLI 的登录变更。没有账号字段时说明“CLI 未提供账号名称”，不会把 Windows 或共享空间账号当作模型账号。
2. 在同一对话框选择模型，查看账号额度；确认工作目录和远端项目后创建。模型固定在会话上，重启、恢复和后台成果整理都沿用该模型。选择“沿用 CLI 默认模型”则保留 CLI 自己的默认行为。列表读取失败不阻止沿用默认模型。
3. 会话工具栏提供“关闭会话”。运行中先提示停止；关闭后保留历史、未发送输入、原生 session ID 和 Agent 工作记录。左侧“已关闭会话”可以查看并重新打开。重新打开不自动重放任务，需主动发送。进程停止不能撤销已经完成的文件修改。
4. 点击“整理成果”，在同一成果面板显示后台整理状态、已用时间和来源会话，不新增可见会话，不阻塞原会话。可以边等待边填写三行的“补充说明（可选）”，也可以切换到其他页面，让整理在后台继续。面板顶部“取消”始终可见：整理中点击会停止本次整理并返回来源会话，已生成的内容和人工补充保留；完成或失败后点击则保留草稿并返回，不会上传。取消不关闭原工作会话；从“整理成果”可再次打开，已停止的整理需主动重新整理。保存失败时保留面板与待保存内容，重试保存后再返回。入口显示“整理中 / 待确认”；完成后轻提示，不跳转、不自动上传。同一会话未提交的成果重复点击只打开原面板。
5. AI 自动生成标题、Markdown 成果说明和可选仓库链接，直接展示，无需“采用草稿”。长说明可展开。上传位置自动识别并只读展示；用户只需查看、可选补充、点击“确认上传”。仓库链接可留空，不影响上传方向性判断、结果性结论或方案建议；可选链接入口默认收起，涉及代码时可以补充或更正。人的补充和链接更正独立保存，失败、停止、重试不会覆盖。失败立即显示原因与重试入口，最长等待十分钟后显示超时并停止本次整理。失败重试使用原冻结材料；完成后“重新整理”读取当前最新工作记录。应用退出不在后台继续整理，重开显示已中断并保留内容。
6. “轨迹上传”预览采集的会话内容，默认手动。绑定项目的工作会话可开启每轮结束自动上传；上传到项目的 `trajectories/账号/`。移除“会话归档”和本地导出入口。仍保留正常的本地会话记录，以及失败上传重试所需的队列缓存，这不是额外的用户归档操作。

成果只上传成果说明、可选 GitHub 仓库链接和提交元数据，不上传代码或材料快照。无链接时不会生成空的仓库占位行。新包采用 `schemaVersion: 3`、`kind: project-contribution`，`repoUrl` 可缺省；旧包保留原样。

自动目录选择：程序在当前绑定项目中最多扫描 40 个目录、深度 3 层，读取小型 README.md / README.txt 的前 2000 字作为分类说明。排除隐藏目录、轨迹目录、链接和他人的成果目录。AI 只返回已枚举的目录 ID，不能自行构造路径；无法匹配或目录读取不完整时保留默认成果目录兜底。上传使用原项目和账号绑定，仍由本地权限桩或 Linux/SFTP 权限决定是否允许写入。目录可读不代表可写，权限拒绝会显示在传输记录中，不能绕过。

旧草稿保留原来已编辑的正文；未提交草稿迁移到默认成果目录，已提交成果保持冻结。新成果包合并 AI 正文与非空的人类补充，只包含 README.md 和 manifest.json。


## Agent 工作记录与成果草稿

- **Agent 工作记录**：会话内的本地过程资料，记录目标、发现、依据和待办。入口位于默认收起的“会话资料”，打开后先只读预览，通常无需用户填写；有遗漏时通过“更正记录（可选）”编辑，保存并返回。记录本身不随成果上传。
- **成果草稿**：点击“整理成果”后，AI 根据上述记录和参考资料另行提炼、供团队阅读的分享内容。页面展示两类内容的区别，由用户审阅、可选补充、确认上传。修改工作记录不会自动更新已生成的草稿，需要点击“重新整理”。
- 保留已有 `handoff.md` 文件、会话绑定及读写接口，升级无需迁移历史记录；新会话的标题与模型约定改称“Agent 工作记录”。

## 接入来源与边界

| 能力 | Codex | Cursor |
| --- | --- | --- |
| 身份 | App Server `account/read`，白名单提取 `email` / `planType` | `status --format json`，白名单提取 `userInfo.email` |
| 模型列表 | `model/list` 分页，使用 `model` 字段，不使用展示 ID | `agent models`，解析当前 CLI 的模型行；无法识别时显式提示 |
| 模型传递 | `thread/start` / `thread/resume` 与 `turn/start` 的 `model` | ACP 新建/恢复后调用 `session/set_model`，传递 `modelId` |
| 额度 | `account/rateLimits/read`，优先显示所有 `rateLimitsByLimitId`，回退旧字段 | 当前 CLI 没有公开个人套餐额度读取接口；按钮打开官方 Spending 页 |

Codex 百分比是“已用”，界面显示 `100 - usedPercent` 的剩余额度和 Unix 秒重置时间。它是账号/用量池信息，不推断模型独享配额。不支持的认证方式或网络失败显示不可用，绝不显示虚构的 0% 或无限额度。额度查询失败不覆盖可用模型列表，也不改变认证状态。身份和额度只留在内存，不写入成果或轨迹。

参考：[Codex App Server](https://learn.chatgpt.com/docs/app-server)、[Cursor CLI 参数](https://cursor.com/docs/cli/reference/parameters)、[Cursor ACP](https://cursor.com/docs/cli/acp)、[Cursor 官方用量说明](https://cursor.com/help/models-and-usage/usage-limits)。Cursor `session/set_model` 同时核对本仓库随带官方 CLI 的 ACP 实现；升级 CLI 后应执行协议回归。

## 验证入口

- `npm run check`：类型检查、全部 Node 测试、两个开发版构建。覆盖身份、模型与额度、会话生命周期，以及自动目录识别、默认目录回退、权限变化、超时、无效输出、补充保留、旧草稿迁移与成果包内容。
- `npm run test:session-ui`：两种提供方的窗口操作回归，登录按钮禁用、模型与额度、整理等待/离开/返回/完成提示、重复点击、停止/重试、可选补充、缺失链接更正、展开说明、操作确认、关闭/恢复和移除本地轨迹导出。
- `npm run test:ui`：原有用户/管理员隔离、SFTP 共享、成果提交和编辑保存恢复回归。
- `npm run test:local-ui`：管理员与两个成员、本地共享文件系统、项目创建及轨迹实际上传。

真实账号只读联调已验证本机 Codex 的身份、模型列表与额度，不发送付费模型任务。本机 Cursor 尚未登录，Cursor 模型选择与会话交互使用协议模拟 CLI 验证，不能当作真实账号端到端验证。

0.6.3 用例：`tests/usability.test.ts` 覆盖无链接、有链接、非法链接和空说明；`tests/preparation.test.ts` 验证无链接结论的实际上传及同组可见；`scripts/local-smoke.mjs --accounts --packaged` 在两个用户和管理员窗口中验证无链接上传按钮、补充说明、实际 ZIP 内容和同事访问。
