# 团队成果批量删除

- “团队项目成果库”提供“批量删除团队成果”。组管理员可选择当前项目内的成果、文件和轨迹；普通成员只能选择自己尚未被组管理员整理的提交。无权删除的条目不可勾选，服务端仍逐项校验实际权限。
- 选择只作用于当前分组和筛选结果。全选最多 100 项；切换分组、搜索、类型、项目或刷新会清空选择，与语义合并互斥。
- 确认框列出实际选中的标题、提交人和版本，并说明删除不可从共享库恢复。删除团队成果后，正文和历史版本无法从团队成果库恢复。已保存的个人副本、本机整理记录、已发送的对话内容及任务和子会话的固定快照保留；其他尚未发送的成果引用在检测到删除后不再发送给模型。删除合并成果不会自动恢复被它替代的来源成果。清理附件时同时检查其他当前和历史成果的引用；任务使用独立副本。仍被引用的文件继续保留，仅清理本项目内已无引用的文件。
- 提交前校验整个选择的项目、版本和权限；复用现有单条删除接口逐项执行，每项由服务端再次检查。中途出现冲突、权限变化、断线或保存异常时停止后续操作，显示已完成与未完成的数量。已经完成的删除不回滚。
- 丢失应答时只读核对一次：确认团队成果已删除的计入完成，无法核实的明确提示结果不确定。不会自动重试删除，用户刷新核对后可重新选择并确认。
- 客户端以成果 ID 和版本关联动态。旧动态退出待处理但保留历史事实与采用记录；删除通知不授权清除个人副本。文件缺失和恢复单独形成动态；访问失败不视为删除。成果登记文件本身缺失时整次检查失败，保留上次状态。
- 文件可访问状态检查兼容原 SSH 接口，按目录合并读取；Linux 的历史附件保留规则需通过管理端更新服务端功能。分类显示按用户确认保持原样：缺少分类字段时仍使用“项目成果”作为缺省标签。

验证使用临时模拟团队、权限规则、持久化 Session 和静态页面渲染，不连接真实共享空间执行删除，也不在用户桌面运行界面测试。
