# 成果提交与来源查看

## 页面如何显示

| 位置 | 默认显示 | 展开后显示 |
| --- | --- | --- |
| 整理成果 | 来源会话和整理时间；按钮显示“提交到 项目名” | 已有的依据与附件 |
| 个人成果分享 | 成果名称；按钮显示“提交到 项目名” | 用户选择公开的直接来源 |
| 传输记录 | 成果名称、状态、进度；跨项目记录增加项目名 | 账号、来源、完整目标和文件位置 |
| 团队成果 | 标题、作者、版本和内容 | “来源与历史”中的原提交记录及维护人 |
| 团队动态 | “Alice 更新了《误差评估》”；跨项目记录增加项目名 | 原提交人、来源、完整目标和维护人 |

同名项目用“工作组 / 项目”区分。提交按钮使用草稿绑定的项目。点击按钮即可提交，不新增确认窗口。默认页面不重复显示三行提交信息，也不提供打开其他成员私人会话的入口。

## 提交记录

每次新上传记录账号、工作组、项目和时间。账号及实际目标由存储端核验，名称使用服务端接受提交时的值。整理过程中由模型生成的内容不决定这些字段。

来源由本地程序填写：

- 会话整理：整理开始时的会话名、会话 ID、快照时间与摘要标识。
- 个人成果分享：这条成果的名称、ID 和审阅版本。确认窗口打开后发生修改，需刷新后重新确认。
- 个人成果合并后分享：本次选择的个人成果及其版本，不把执行整理的会话当作来源。
- 团队成果合并：存储端核对原成果 ID 和版本，记录对应标题与作者。
- 文件上传：原始文件名；本机绝对路径不作为公共来源信息上传。
- 明确声明为手动编写的提交：记录为手动编写。没有来源字段的旧记录显示“未记录来源”，不会推测为手工提交。

这里只公开当前提交的直接来源。个人成果的私有祖先链仍由用户明确勾选后公开；原始对话不会随成果提交。轨迹上传独立处理，不生成团队成果动态。

## 重试与后续维护

上传排队前固定账号、项目、来源及文件副本。切换工作组、改名或继续对话不会改变已有上传。连接中断或程序重启后，重试复用原目标和请求；收到回执后保存存储端确认的记录。

管理员修改正文或分类时，原提交记录不变，单独更新维护人和版本。合并创建新成果，提交人是执行合并的管理员，来源是经过版本核对的团队成果。替代和删除动态保留原提交记录；删除记录同时保存执行人。

旧记录缺少来源或目标时会明确显示未记录。不会用当前选中的工作组反推历史目标，也不会给旧记录补造来源。

## 验证方式

使用两个本地权限打桩账号、两个同名项目验证多组切换；不调用真实模型、不连接共享服务器。

- `tests/submission.test.ts`：冻结会话来源、重启后恢复队列并重试、个人来源隐私、文件名、管理员整理、精确合并版本和旧记录展示。
- `tests/test_content.py`：Linux 存储 Worker 的身份/目标核验、回执幂等、维护与合并，以及历史兼容。
- `scripts/submission-ui-smoke.mjs`：真实 React 页面中的目标按钮、详情折叠、跨组展示和个人分享；截图保存到 `artifacts/submission-ui-validation/`。

新存储字段需要同步更新客户端和存储 Worker。旧 Worker 的回执仍可供传输使用，但无法提供新版公共来源记录；服务端升级方式见[部署指导](deployment-guide.md)。
