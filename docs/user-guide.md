# 团队工作台使用指导

本文说明管理员和成员如何使用当前 0.7.0 工作台。服务器准备、本地打桩、安装迁移和开发构建见 [部署指导](deployment-guide.md)。

从源码使用时，双击仓库根目录的 `start-user-dev.cmd` 或 `start-admin-dev.cmd`。更新代码后关闭旧窗口，再通过同一入口启动。首次环境准备见[部署指导](deployment-guide.md#新电脑从源码启动)。

## 管理员操作

1. 在“全部用户”或“按组查看”中创建用户、创建用户组和维护成员关系。创建用户组时填写的是显示给成员看的**用户组名称**，支持中文（例如 `实体抽取`）；远端 Linux 组名由工具自动生成，不需要迁就 Linux 命名规则。
2. 组内第一位成员默认成为组管理员，之后可调整。一个成员可加入多个组，每个组的普通成员或组管理员身份独立设置。
3. 将服务器地址、SSH 端口、成员账号和初始密码交付给成员。
4. 组管理员使用用户版进入自己的组，创建项目并填写项目背景、目标、验收标准和限制。

管理员版负责账号、组和组管理员身份。项目内容、项目资料和公共成果由用户版中的项目组管理员维护。

## 子管理员派活与成员开始工作

用户端左侧新增“任务”。子管理员看到“项目派活”，可以选择当前项目所在组的有效成员，填写任务标题、工作目标与范围、验收要求，并勾选最多 20 条共享文字结论。填写任务后，系统按 BM25 和关键词规则优先列出相关候选，也可搜索全部共享结论；任务不会依赖最近 24 小时的动态。个人尚未上传的本地结论需先作为共享成果发布，才能随任务派发。

普通成员只看到分配给自己的任务，首页显示待办提示。展开任务可阅读说明、验收要求和派发时保存的结论版本。点击“开始工作”，选择本机工作目录、模型和权限后，会创建会话、带入任务说明和关联结论、填写输入草稿；用户检查后再发送给 AI。关联结论同时保存到本地库，已有较新版本不会被旧任务覆盖。再次点击“继续工作”打开已有会话。共享区后来修改或移除结论，不会改写已派发任务的依据和会话快照。

任务状态包括待开始、进行中、已完成、已取消。负责人可以开始和标记完成，子管理员可以取消任务并查看进度。完成或取消后不再为此任务创建新会话，已有会话和本地结论继续保留。当前派发内容发布后固定；需要纠正要求时可取消原任务并重新派发。任务按项目和账号检查权限，跨组、普通成员派活、已撤权账号会被后端拒绝。

本地联调和 Linux 共享空间都支持任务。Linux 服务器需要在本次新版管理端的用户管理页点击“更新服务端功能”，以安装新版文件操作器；仅更新用户端不足以启用新的服务端操作。任务不会通过聊天、邮件或外部消息渠道发送，成员通过工作台读取。

## 打开会话生成的文件

会话回复中的本地文件链接现在可以点击，支持 Windows 路径、带空格的路径、`file:` 链接及行号。页面显示文本或图片预览、完整路径、“复制路径”和“打开所在文件夹”；PDF、Office 等格式可通过系统应用打开。脚本和程序不通过这个入口执行。

会话顶部“会话文件”汇总当前会话记录、修改或提到且仍在本机的文件，旧会话中的 Markdown 文件链接也可识别。它按实际文件路径读取，不会自动下载、上传或把临时环境中的文件复制到本机；文件被移动或删除时会明确提示。模型只描述生成成功但没有提供路径、也没有文件变更记录的文件，无法从会话中自动定位。

## 用户首次进入

1. 每次打开用户版都会先显示登录窗口。首次填写团队服务器地址、SSH 端口、成员账号和密码；之后会自动回填地址、端口、账号和本机路径，但密码不会保存，仍需重新输入并登录。
2. 只选择一处“本机工作路径”，用于代码和个人工作文件。Linux 项目路径由登录账号的权限决定，不由用户选择；本地联调共享区由启动器预置。
3. 登录后，左侧按工作组显示有权限的项目。一个账号加入多个组时，各组分别展示；没有加入任何组时不会出现项目工作台。
4. 本机能直接访问 Codex/Cursor 时保持“通过管理端访问 Codex 和 Cursor”关闭。只有本机没有外网通路时才开启并粘贴管理员提供的接入码；模型账号仍在本机 CLI 中登录。
5. 新建会话时选择项目、Codex 或 Cursor、模型和执行权限。已经登录 CLI 时会显示实际账号，登录入口不可重复点击。

需要同时使用不同成员账号时，可以再次启动用户版：程序会打开尚未打开的已有账号数据；已有账号窗口全部打开后，再次启动只会唤回现有窗口，不会进入空账号窗口。确实要增加新账号时点击右上角 **新建账号窗口**。各窗口分别登录、保存会话和连接共享空间，一个窗口切换账号、断线或退出不会改变其他窗口的登录身份。

左侧“项目/文件”区域与“本地会话”之间有可拖动的横向分隔条。上下拖动可调整两块区域的高度，方向键可微调，双击恢复默认比例；项目和文件过多时在各自区域内滚动，不再挤压会话列表。每个多开窗口独立保存自己的比例，在一个账号窗口拖动不会带动其他窗口。

最左侧的“动态”是团队公共内容的集中入口，显示上传、更新、删除和语义合并四类结果、待处理数量、来源项目和来源会话。自己的操作通常直接进入历史；队友的变化，以及自己删除共享成果后仍需处理本地副本的动态，进入待处理；首次同步不再只保留前 5 条。动态可切换“待处理”和“历史动态”；把远端内容整理到本地结论或加入会话后会自动归档，历史中仍可查看已归档和未归档记录。点击“批量删除动态”可逐条勾选或全选当前列表，确认后只删除本机动态记录，不影响共享区内容、本地结论和会话引用；同一修订不会重新出现，后续新变化仍会通知。切换范围或类型筛选会清空勾选。动态记录的是变化；每条“查看结果”只打开这一条成果的当前内容，并提供“返回动态”。刷新仍只查看这一条；成果已删除或被合并时显示不可用提示，不会转而展示其他成果。任何远端 ID 被删除时，该 ID 以前的已读、未读记录都会移除，并只增加一条删除动态。提示条的 × 会收起当前整批提示，不会在多条待处理动态之间轮换弹出；之后检测到新动态时才再次提示。

“项目结论”保存在本机，每条只展示标题、内容、来源和更新时间。来源可以是本地会话整理、共享区内容、本地结论合并或手工记录，不只显示共享区同步内容；本地整理完成后，当前勾选的候选项会自动进入项目结论，不需要先上传。可以手工新建或编辑，也可点击“设置本地别名”保存、修改或清除易读名称。列表、详情、结论推荐和新加入会话的引用名称优先显示别名，同时保留原名；别名不修改原始内容、版本和已有会话快照，重启后仍然保留。暂时不用的结论可“移入历史”，它将不再推荐给新会话，但仍保留并可随时恢复使用。“删除结论”是独立操作：确认后从本地结论库和历史列表中移除，不能通过“恢复使用”找回；共享区内容和已有会话引用保持不变。使用中的结论和历史结论都可删除。点击“批量删除结论”可多选或全选当前列表，确认框会列出所选名称；未显示的历史结论不会被一并选中，切换历史显示会清空勾选。项目结论用于阅读和加入会话，不提供下载；共享区中的普通文件和轨迹仍可下载。

管理员在共享区删除或合并来源后，本地结论不会自动删除或移入历史。“共享区已移除”动态里的“选择是否保留本地结论”允许保留全部，或明确勾选要删除的条目；默认不勾选。含多个来源的结论会列出提醒和来源，只有明确勾选才从本地结论库移除；已有会话的引用快照继续保留。保留与删除的选择在重启后仍生效，删除标记用于防止旧整理草稿重新生成已移除的条目。

新会话第一次提问时，工作台会列出少量可能有帮助的项目结论。只有用户勾选的内容才会带入会话，也可以不带入直接发送。需要把多条结论整理成一条时，点击“整理所选内容”，填写整理要求后生成可编辑草稿；最终确认保存后，原结论才会移入历史。

也可以在结论详情点击“加入会话”，勾选同项目的一个或多个工作会话。已加入的显示勾选且不可取消，关闭的会话不可新增；加入时冻结当时版本，下次提问自动带入，不改动正在运行的任务。结论后来被编辑或移入历史，不会改写已加入会话的快照；同一原生上下文已经接收过的内容不会重复发送。

正常关闭再打开后，本地会话、输入草稿、未处理及历史动态、已关闭的提示、整理任务、本地名称、结论及其历史状态、会话引用快照都会保留；关闭动态提示不等于已读。进行中的 AI 任务和传输会标为中断或可重试，不会在重启后假装仍在运行。远端条目被删除时，仍按同步规则替换为一条删除动态。

普通成员不需要填写或查看 SSH 指纹。本机第一次连接某个服务器地址和端口时，只需确认地址正确；这份服务器身份信任由本机所有用户端窗口共享，换成员账号不会重复询问，即使密码随后输错也不会重复询问。账号、会话和草稿仍按窗口隔离。正常登录页不显示身份校验说明或技术信息。服务器身份发生变化时，客户端停止登录，并在错误旁显示“重新确认”。需要更换服务器时直接修改地址或端口。

管理员调整成员所属组或项目组管理员身份后，用户点击左侧“刷新工作组与项目”即可加载最新身份。Linux 服务器为使新系统组权限立即生效而断开旧连接时，当前运行中的用户版会使用本次登录的内存凭据恢复连接；自动恢复失败则打开登录窗口，要求重新输入密码。密码仍不落盘。传输任务中途断网或变更身份的安全恢复另见 [待修复问题](待修复问题.md)，不能把身份刷新等同于文件传输已经成功。

项目组管理员选择项目后，左侧会显式显示“整理项目文档”。进入后默认只显示“未操作”；通过“项目文档操作状态”切换到“已操作”。保存整理、完成合并或纳入管理的文档属于已操作，仅查看、设置本地别名、加入会话不改变分组；切换分组会清空多选，避免合并隐藏条目。每个条目都有独立的“整理文档”和“删除”按钮，可直接编辑说明、替换文件或在二次确认后删除，不需要先进入“公共成果”并选中条目。删除综合整理结果不会自动恢复之前被融合的来源。需要融合多条文字成果时点击“多选语义合并”，选择来源和同项目工作会话的模型环境；AI 会分别整理综合结论、共识、冲突、证据、适用范围和未决项，组管理员可继续修改。确认前原条目不变；确认时会再次核对全部来源修订，全部一致才保存融合结果并归档原文。需要把文件区中的旧文件纳入管理时，先预览该文件，再点击“纳入项目文档管理”。普通成员仍通过“公共成果”阅读和引用结论；结论不提供下载，普通文件和轨迹保留下载入口。

## 修改项目设置

选择左侧项目后，打开“设置 → 项目设置”。项目背景、项目目标、验收标准、范围与非目标、交付物与里程碑、现有资料与入口、约束与风险、协作约定均对应 `项目说明.md` 的同名章节。项目组管理员点击“保存项目设置”后生成新版本，并同步刷新共享项目根目录中的 `项目说明.md`；普通成员可查看但不能修改。

## 日常会话

- 每个会话固定绑定创建时的项目、工作目录、模型和执行权限。切换左侧项目不会改变已有会话。
- 会话标题旁的铅笔按钮可以重命名会话。名称保存在当前账号窗口；之后从该会话上传的成果和轨迹会携带这个来源会话名，其他成员在公共成果和团队动态中看到重命名后的名称。历史上传内容不会被静默改写。
- 输入框按 `Enter` 发送，`Shift+Enter` 换行。多个会话的输入、对话和阶段摘要分别保存。
- 输入框底部可查看或修改当前会话的模型与执行权限，也可为下一条消息选择 Skill 或插件。选择后会在输入框上方显示标签，发送成功后自动清空；切换会话、关闭窗口或发送失败时保留未发送选择。
- Codex 的 Skill 和已安装插件分别按原生 `$skill` 与 `@plugin` 提及发送；Cursor 的 Skill 按原生 `/skill` 调用，每条消息显式选择一个，已配置的 MCP 工具显示在插件区。插件安装、登录、启停和权限仍由 Codex/Cursor 自己管理。
- “AI 参考内容”包含项目说明和阶段摘要。项目说明有新版本时由用户决定是否更新当前会话使用的快照。
- “阶段摘要”是 AI 在本机维护的阶段性目标、发现、证据和待办，供后续对话及整理成果参考。它不会直接上传；用户通常只需查看，发现遗漏时再更正。

## 整理和上传成果

1. 在工作会话右上角点击“整理成果”。工作台先复制当时的对话、阶段摘要和所选资料，整理任务只读取这份冻结副本；原会话可以继续对话，不会改变本次结果。
2. 点击左侧“整理任务”先进入任务列表，列表展示任务标题、来源会话、项目、任务类型（增量或全量）、创建/完成时间、结果数量及当前状态；点击一项后才进入整理结果详情：
   - **正在整理**：可返回原会话继续工作，后台整理不会停止；需要终止时点击“停止整理”。
   - **整理失败**：页面说明影响和恢复方式；点击“重试”。此时上传位置显示“尚未确定”。
   - **已整理好，请确认后上传**：查看结果、上传位置和可选信息，再决定是否上传。
3. 页面顶部始终提供“返回‘会话名’”。较长的已完成结果底部也提供返回入口。返回不会上传内容。
4. “仓库与代码版本（可选）”用于补充 GitHub 仓库链接，或记录当前分支、commit 和未提交改动状态。记录 Git 状态不会上传代码。
5. AI 先把材料拆成可独立复用的候选成果，并分为“实验结果、未奏效方向、结论与发现、问题与风险、项目基线变更建议”。每个标题自动采用 `【归属类别】具体主题`，语义合并采用 `【综合整理】具体主题`；公共成果列表仍单独显示类别标签，因此旧标题也能看出归属。新生成结果最多三段，通常 150—250 字；实验只写本次变化、验证情况和下一步，保留未验证与不确定性，不再分别罗列重复的目标、环境、依据和限制。旧结果保留原文。每项可点击“修改名称”；上传前修改实际成果标题，上传后只改本机显示名称，不覆盖共享区或已上传包。当前勾选项在整理完成后自动进入本机项目结论，取消勾选会停止使用对应自动结论。未进入上传流程的整理任务可以二次确认后删除；删除会停止正在运行的整理并清理临时文件。已经上传、正在上传或已经保存为合并结果的任务保留为记录，界面不提供删除，后端也会拒绝删除。公共成果还可以设置仅本机可见的别名；别名不会覆盖远端标题，加入会话和查看动态时优先显示别名。
6. “给团队的补充（可选）”只用于人工补充或更正 AI 整理的内容；保存成功后不常驻提示，失败时才显示重试入口。
7. 类别与目录的映射由程序固定，AI 和用户都不能输入任意远端路径。各项分别写入 `submissions/账号/experiments/`、`failed-directions/`、`findings/`、`issues/` 或 `baseline-change-proposals/`。基线变更类是待组管理员判断的建议，不会直接修改项目说明。
8. 点击“确认上传 N 项”后，每项生成独立成果包并进入传输队列，界面逐项显示状态。上传完成后，各项旁边提供“查看上传结果”，可直接跳到公共成果中的对应条目。成果包仅包含该项说明、分类字段、冻结快照标识、可选仓库链接和可选 Git 状态，不包含业务代码、完整对话或参考文件。

会话页的“整理成果”会优先打开该会话最新的未提交任务；从左侧进入“整理任务”时始终先显示完整任务列表，再由用户选择详情。

已完成任务可以点击“再次整理”选择范围。**增量整理**只把上次快照之后新增的会话消息作为本次成果来源，当前阶段摘要和参考资料只用于理解上下文；**全量整理**重新读取发起时的全部会话消息、阶段摘要和参考资料。两者都会生成一条新任务，原任务及已上传内容不覆盖；上次整理后没有新增消息时，增量选项会置灰。

## 轨迹上传

- “轨迹上传”与成果上传分开操作，默认由用户手动确认。
- 轨迹写入当前项目的 `trajectories/账号/`；同组成员可读取已经主动上传的轨迹。
- 轨迹只覆盖工作台采集到的对话和工具事件，不包含不可访问的隐藏推理，也不等同于厂商完整数据库。

## 常见情况

- **当前执行权限限制任务**：在输入框内打开权限选项，查看 Codex 或 Cursor 的原生权限名称及可能影响，再修改权限。修改不会自动重放任务。
- **本机不能访问 Codex/Cursor**：登录团队共享空间时勾选“通过管理端访问 Codex 和 Cursor”，粘贴接入码后登录。工作台会为其启动本机回环代理，并只把本工作台启动的 CLI 进程接入该代理；浏览器和其他程序不受影响。管理员更新接入码后需重新粘贴。
- **本机可以直接访问外网**：保持管理端出口关闭。此时不会创建本机代理，也不会改变 CLI 的网络环境。
- **找不到 Skill 或插件**：先在对应 Codex/Cursor 中安装或启用，再点击能力菜单的刷新。Cursor 插件只有在提供可调用 Skill 或已配置 MCP 工具时才会出现在会话选择中。
- **整理中离开页面**：返回原会话即可，完成后侧栏显示“待确认”并弹出一次提醒；打开整理结果后提醒自动清除。
- **原会话在整理后新增内容**：结果页显示新增消息数；点击“再次整理”后可选只整理新增消息，或基于当前全部内容重新整理。
- **网络中断**：整理结果留在本机，补充内容不会丢失；恢复网络或 CLI 后重试。
- **断网后继续工作**：工作台顶部显示“离线工作中”，本地会话与草稿可继续使用，没有时间限制；上传、公共成果等共享读写需要连接服务器，重新连接时核验权限。
- **团队内容变化**：用户端连接共享空间且窗口可见时，每 15 秒检查一次有权限项目。其他成员上传、更新、删除或合并内容后会出现提示，并持久进入最左侧“动态”；上传、更新和合并可直接查看结果，删除保留题目、项目和检测时间。首次启用此能力会补提示最近 24 小时内每个项目最新的 5 条他人变更，后续同一修订只记录一次。
- **操作提示**：普通顶部提示条几秒后自动消失；队友成果提示保留到查看或关闭。页面内标红的错误信息保留到你处理或重试。
- **没有仓库链接**：方向性判断、结果性结论和方案建议仍可上传，不要求关联代码仓库。
- **关闭会话**：保留对话、未发送输入、阶段摘要和原生会话 ID；重新打开后由用户决定下一步。

更详细的身份与权限边界见 [身份与协作说明](identity-content.md)，CLI 权限见 [CLI 权限与人工授权](cli-permissions.md)。
