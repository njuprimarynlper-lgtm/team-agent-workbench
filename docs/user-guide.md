# 团队工作台使用指导

本文说明管理员和成员如何使用当前 0.7.0 工作台。服务器准备、本地打桩、安装迁移和开发构建见 [部署指导](deployment-guide.md)。

## 管理员操作

1. 在“全部用户”或“按组查看”中创建用户、创建用户组和维护成员关系。创建用户组时填写的是显示给成员看的**用户组名称**，支持中文（例如 `实体抽取`）；远端 Linux 组名由工具自动生成，不需要迁就 Linux 命名规则。
2. 组内第一位成员默认成为子管理员，之后可调整。一个成员可加入多个组，每个组的普通成员或子管理员身份独立设置。
3. 将服务器地址、SSH 端口、成员账号和初始密码交付给成员。
4. 子管理员使用用户版进入自己的组，创建项目并填写项目背景、目标、验收标准和限制。

管理员版负责账号、组和子管理员身份。项目内容、项目资料和公共成果由用户版中的项目子管理员维护。

## 用户首次进入

1. 打开用户版，填写团队服务器地址、SSH 端口、成员账号和密码。点击登录后，本机会记住服务器地址、端口和成员账号，之后自动回填；密码不会保存。
2. 只选择一处“本机工作路径”，用于代码和个人工作文件。Linux 项目路径由登录账号的权限决定，不由用户选择；本地联调共享区由启动器预置。
3. 登录后，左侧按工作组显示有权限的项目。一个账号加入多个组时，各组分别展示；没有加入任何组时不会出现项目工作台。
4. 新建会话时选择项目、Codex 或 Cursor、模型和执行权限。已经登录 CLI 时会显示实际账号，登录入口不可重复点击。

需要同时使用不同成员账号、项目或会话时，可再次启动用户版。每次启动都会增加一个独立账号窗口；各窗口分别登录、保存会话和连接共享空间，一个窗口切换账号、断线或退出不会改变其他窗口的登录身份。

普通成员不需要填写或查看 SSH 指纹。本机第一次连接某个服务器地址和端口时，只需确认地址正确；即使密码随后输错也不会重复询问。正常登录页不显示身份校验说明或技术信息。服务器身份发生变化时，客户端停止登录，并在错误旁显示“重新确认”。需要更换服务器时直接修改地址或端口。

管理员调整成员所属组或项目子管理员身份后，用户点击左侧“刷新工作组与项目”即可加载最新身份。Linux 服务器为使新系统组权限立即生效而断开旧连接时，当前运行中的用户版会使用本次登录的内存凭据恢复连接；自动恢复失败则打开登录窗口，要求重新输入密码。密码仍不落盘。传输任务中途断网或变更身份的安全恢复另见 [待修复问题](待修复问题.md)，不能把身份刷新等同于文件传输已经成功。

## 修改项目设置

选择左侧项目后，打开“设置 → 项目设置”。项目背景、项目目标、验收标准、范围与非目标、交付物与里程碑、现有资料与入口、约束与风险、协作约定均对应 `项目说明.md` 的同名章节。项目子管理员点击“保存项目设置”后生成新版本，并同步刷新共享项目根目录中的 `项目说明.md`；普通成员可查看但不能修改。

## 日常会话

- 每个会话固定绑定创建时的项目、工作目录、模型和执行权限。切换左侧项目不会改变已有会话。
- 输入框按 `Enter` 发送，`Shift+Enter` 换行。多个会话的输入、对话和阶段摘要分别保存。
- 输入框底部可查看或修改当前会话的模型与执行权限。修改后仍保留此前对话上下文，但不会自动重试上一项任务。
- “AI 参考内容”包含项目说明和阶段摘要。项目说明有新版本时由用户决定是否更新当前会话使用的快照。
- “阶段摘要”是 AI 在本机维护的阶段性目标、发现、证据和待办，供后续对话及整理成果参考。它不会直接上传；用户通常只需查看，发现遗漏时再更正。

## 整理和上传成果

1. 在工作会话右上角点击“整理成果”。工作台冻结当时的对话、阶段摘要和所选资料，并启动独立整理任务。
2. “整理结果”页会显示当前状态：
   - **正在整理**：可返回原会话继续工作，后台整理不会停止；需要终止时点击“停止整理”。
   - **整理失败**：页面说明影响和恢复方式；点击“重试”。此时上传位置显示“尚未确定”。
   - **已整理好，请确认后上传**：查看结果、上传位置和可选信息，再决定是否上传。
3. 页面顶部始终提供“返回‘会话名’”。较长的已完成结果底部也提供返回入口。返回不会上传内容。
4. “仓库与代码版本（可选）”用于补充 GitHub 仓库链接，或记录当前分支、commit 和未提交改动状态。记录 Git 状态不会上传代码。
5. “给团队的补充（可选）”只用于人工补充或更正 AI 整理的内容；保存成功后不常驻提示，失败时才显示重试入口。
6. 上传位置由 AI 从当前项目允许的成果目录中选择。界面显示项目和友好目录名；用户不能输入任意远端路径。
7. 点击“确认上传”后，成果进入传输队列。成果包仅包含成果说明、可选仓库链接、可选 Git 状态和提交元数据，不包含业务代码、完整对话或参考文件。

同一会话只有一个未提交的整理结果，重复点击“整理成果”会回到该结果。存在多个会话的结果时，“整理结果”页通过“切换整理结果”选择。

## 轨迹上传

- “轨迹上传”与成果上传分开操作，默认由用户手动确认。
- 轨迹写入当前项目的 `trajectories/账号/`；同组成员可读取已经主动上传的轨迹。
- 轨迹只覆盖工作台采集到的对话和工具事件，不包含不可访问的隐藏推理，也不等同于厂商完整数据库。

## 常见情况

- **当前执行权限限制任务**：在输入框内打开权限选项，查看 Codex 或 Cursor 的原生权限名称及可能影响，再修改权限。修改不会自动重放任务。
- **整理中离开页面**：返回原会话即可，完成后侧栏显示“待确认”并弹出一次提醒；打开整理结果后提醒自动清除。
- **原会话在整理后新增内容**：结果页会说明本次结果未包含新增内容，并提供“重新整理并包含新内容”。
- **网络中断**：整理结果留在本机，补充内容不会丢失；恢复网络或 CLI 后重试。
- **断网后继续工作**：工作台顶部显示“离线工作中”，本地会话与草稿可继续使用，没有时间限制；上传、公共成果等共享读写需要连接服务器，重新连接时核验权限。
- **操作提示**：顶部提示条几秒后自动消失；页面内标红的错误信息保留到你处理或重试。需要重看时重新执行一次刷新即可看到最新状态。
- **没有仓库链接**：方向性判断、结果性结论和方案建议仍可上传，不要求关联代码仓库。
- **关闭会话**：保留对话、未发送输入、阶段摘要和原生会话 ID；重新打开后由用户决定下一步。

更详细的身份与权限边界见 [身份与协作说明](identity-content.md)，CLI 权限见 [CLI 权限与人工授权](cli-permissions.md)。
