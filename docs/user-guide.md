# 团队工作台使用指导

本次更新统一了“项目资料”，增加会话内引用入口、精简自动分类、可选代码目录、账号私有同步与成果附件。使用和服务端升级要求见 [项目资料与附件](project-materials-2026-09-21.md)。Session 仍留在本机。

本文说明管理员和成员如何使用当前 0.7.0 工作台。完整状态转换图、各阶段可编辑/可删除的信息和失败处理边界见 [用户工作流状态与操作边界](workflow-states.md)。服务器准备、本地打桩、安装迁移和开发构建见 [部署指导](deployment-guide.md)。

从源码使用时，双击仓库根目录的 `start-user-dev.cmd` 或 `start-admin-dev.cmd`。更新代码后关闭旧窗口，再通过同一入口启动。首次环境准备见[部署指导](deployment-guide.md#新电脑从源码启动)。

## 管理员操作

Linux 连接后若显示“服务器环境待完善”，可点击“准备运行环境”，选择服务器软件源在线安装，或填写服务器上的离线软件包目录；也可自行补齐组件后点击“重新检查环境”。环境通过后即可继续初始化、创建用户和用户组，无需重输账号密码。已有失败操作在“待恢复操作”中点击“继续完成”。

1. 在“全部用户”或“按组查看”中创建用户、创建用户组和维护成员关系。创建用户组时填写的是显示给成员看的**用户组名称**，支持中文（例如 `实体抽取`）；远端 Linux 组名由工具自动生成，不需要迁就 Linux 命名规则。
2. 组内第一位成员默认成为组管理员，之后可调整。一个成员可加入多个组，每个组的普通成员或组管理员身份独立设置。
3. 将服务器地址、SSH 端口、成员账号和初始密码交付给成员。
4. 组管理员使用用户版进入自己的组，创建项目并填写项目背景、目标、验收标准和限制。

管理员版负责账号、组和组管理员身份。项目内容、项目资料和公共成果由用户版中的项目组管理员维护。

## 组管理员派发任务与成员开始工作

用户端左侧“任务”对组管理员显示“项目任务”，分为“我负责的”“我派发的”“全组任务”。可以选择自己或本组有效成员，填写任务标题、工作目标与范围、验收要求，并关联最多 20 项共享成果或文件；可勾选成果的附件，也可另外选择本地文件，确认派发时上传。填写任务后，系统按 BM25 和关键词规则优先列出相关候选，也可搜索全部共享结论；任务不会依赖最近 24 小时的动态。个人尚未上传的本地结论需先作为共享成果发布，才能随任务派发。

普通成员只看到分配给自己的任务，首页显示待办提示。展开任务可阅读说明、验收要求和派发时保存的结论版本。点击“开始工作”，选择本机工作目录、模型和权限后，会创建会话、带入任务说明和关联结论、填写输入草稿；用户检查后再发送给 AI。关联结论同时保存到本地库，已有较新版本不会被旧任务覆盖。再次点击“继续工作”打开已有会话。共享区后来修改或移除结论，不会改写已派发任务的依据和会话快照。

任务按“待开始 → 进行中 → 待验收 → 已完成”推进。负责人点击“提交验收”，填写结果说明，可关联成果、共享文件或选择本地验收附件。组管理员点击“验收通过”，或填写原因“退回继续工作”；退回后可补充再提交，历次验收内容和附件保留。自己派给自己的任务可填写结果后直接“确认完成”。完成以任务目标、验收要求为准；调研或探索得到有依据的否定判断也可以完成，AI 回答结束不等于任务完成。

组管理员可填写原因“取消任务”，表示不再继续，不计为完成。已完成和已取消任务保留在“全部状态”；不再从任务入口新建会话，但已有会话不会关闭或停止。派发内容发布后固定，需要纠正要求时可取消原任务并重新派发。

仅组管理员可以删除已完成、已取消的任务，二次确认后移入“已删除”，从双方正常列表移除。恢复会保留原来的结束状态、验收记录和附件。“已删除”内还可彻底删除，需要输入任务标题确认，不能恢复。删除任务不删除共享成果、本地成果、Session、对话和已经带入会话的文件；去重附件仍被其他任务引用时不会被回收。任务按项目、当前角色和修订号检查，跨组、已撤权或过期请求会被后端拒绝。

本地联调和 Linux 共享空间都支持任务。Linux 服务器需要在本次新版管理端的用户管理页点击“更新服务端功能”，以安装新版文件操作器；仅更新用户端不足以启用新的服务端操作。任务不会通过聊天、邮件或外部消息渠道发送，成员通过工作台读取。

## 打开会话生成的文件

会话回复中的本地文件链接现在可以点击，支持 Windows 路径、带空格的路径、`file:` 链接及行号。页面显示文本或图片预览、完整路径、“复制路径”和“打开所在文件夹”；PDF、Office 等格式可通过系统应用打开。脚本和程序不通过这个入口执行。

会话右上角“⋯ → 会话文件”汇总当前会话记录、修改或提到且仍在本机的文件，旧会话中的 Markdown 文件链接也可识别。它按实际文件路径读取，不会自动下载、上传或把临时环境中的文件复制到本机；文件被移动或删除时会明确提示。模型只描述生成成功但没有提供路径、也没有文件变更记录的文件，无法从会话中自动定位。

## 用户首次进入

1. 每次打开用户版都会先显示登录窗口。首次填写团队服务器地址、SSH 端口、成员账号和密码；之后会自动回填地址、端口和账号，但密码不会保存，仍需重新输入并登录。登录时无需填写代码目录。
2. 首次进入每个项目时可选填“代码目录”，也可以选择“暂不设置”。两种选择都会记住，之后进入不再提示；目录按账号、项目保存在本机，不同项目可以使用不同路径。Linux 共享项目路径由登录账号的权限决定；本地联调共享区由启动器预置。
3. 登录后，左侧按工作组显示有权限的项目。一个账号加入多个组时，各组分别展示；没有加入任何组时不会出现项目工作台。在“设置 → 项目设置”中可修改或清空本项目的代码目录，普通成员也可修改自己的本机目录；变更仅用于后续新建会话，已有会话继续使用原路径。
4. 本机能直接访问 Codex/Cursor 时保持“通过管理端访问 Codex 和 Cursor”关闭。只有本机没有外网通路时才开启并粘贴管理员提供的接入码；模型账号仍在本机 CLI 中登录。
5. 在左侧当前项目下新建会话，自动绑定该项目并使用记住的代码目录，无需再次选择项目或填写路径。项目未设置代码目录时，每个会话自动使用独立的调研目录。创建时选择 Codex 或 Cursor、模型和执行权限；已经登录 CLI 时会显示实际账号，登录入口不可重复点击。

需要同时使用不同成员账号时，可以再次启动用户版：程序会打开尚未打开的已有账号数据；已有账号窗口全部打开后，再次启动只会唤回现有窗口，不会进入空账号窗口。确实要增加新账号时点击右上角 **新建账号窗口**。各窗口分别登录、保存会话和连接共享空间，一个窗口切换账号、断线或退出不会改变其他窗口的登录身份。

左侧“项目/文件”区域与“本地会话”之间有可拖动的横向分隔条。上下拖动可调整两块区域的高度，方向键可微调，双击恢复默认比例；项目和文件过多时在各自区域内滚动，不再挤压会话列表。每个多开窗口独立保存自己的比例，在一个账号窗口拖动不会带动其他窗口。

左侧统一通过“项目成果库”进入，页内用“团队 / 个人”切换。团队页默认只显示与当前账号个人库有差异的共享成果，个人页显示当前账号保存的成果；返回入口时保留当前窗口上次选择的范围。离线时从入口进入个人页，团队页提示连接账号。查看动态结果会定位到团队页，查看个人处理结果会定位到个人页。

团队条目可以直接点击“存入个人成果库”。这是保留团队原件、保存个人副本的操作，不会从其他成员的团队库移除。比对按共享来源、修订、文件校验值和正文进行，不靠标题相似度合并不同来源；本地别名和换行形式不影响比对。差异原因显示在条目上：尚未存入、团队版本有变化或个人内容不同。

自己整理后上传的成果同样参与比对：上传成功后保留个人整理条目与上传文件的对应关系，正文和团队版本一致时不再显示为未存入。旧版本已上传的成果会在启动时根据整理记录和已完成的上传记录补齐关联，无需再存一份；不会仅凭标题相同隐藏其他来源的成果。关联会随个人成果同步，删除整理任务不会删除已保存的关联。

| 团队与个人库的当前状态 | 团队差异列表与存入行为 |
| --- | --- |
| 团队存在，个人没有此来源的副本 | 显示，可存入个人库 |
| 个人已有相同来源、版本和正文 | 隐藏；反复存入复用已有副本 |
| 个人副本移入历史 | 仍算已保留，相同内容继续隐藏 |
| 个人副本删除，团队仍存在 | 重新显示，可以再次存入；不受动态已处理状态影响 |
| 团队更新，个人保留旧版 | 显示“团队版本有变化”；明确存入后更新未手工改写的副本 |
| 个人改写了正文 | 显示“个人内容不同”；再次存入会另存团队版本，保留个人改写 |
| 团队删除，个人仍保留 | 团队页不显示，个人副本和已有会话引用继续保留 |
| 团队和个人都删除 | 两边都不显示；团队重新发布后按实际保留情况重新比对 |

同一来源有多个个人副本时，只要其中一个未删除的副本与团队当前版本一致，就不再提示重复存入。个人变更会更新当前差异列表；团队变更可点击“刷新”查看，页面可见且没有编辑或存入操作时每 30 秒自动刷新。存入时再次核对版本，远端已更新或删除会要求刷新，不会采用用户尚未查看的新版本。个人成果按原有规则随同一账号同步；普通文件的“存入”保存说明和来源，文件及附件仍通过下载入口获取。

最左侧的“动态”记录公共区的上传、更新、移除和合并，展示来源项目、会话、版本、时间及个人处理记录。顶部用“待处理 / 已处理 / 全部”切换，类型下拉菜单筛选上传、更新、移除和合并。“已处理”包含个人处理及自己的自动归档项。列表只保留查看入口和处理状态操作，具体处理记录默认折叠。查看结果或关闭提醒不会标记处理；存入个人成果库、加入会话、保留/删除个人副本后，会记录处理时间、目标名称和实际采用的成果版本。相同目标及版本的重复操作去重，使用旧引用不会处理新版本动态。自己的操作自动归档时说明原因；旧记录没有保存处理方式时会明确标注。

在“查看结果”的详情页点击“存入个人成果库”，保存到当前账号的“个人成果库”，随账号同步，本机保留离线缓存，编辑或删除项目结论不会影响团队共享区。无需保存的动态可直接“标记已处理”，也可“多选处理”；标记只改变个人动态状态。需要重新关注时点“设为待处理”，动态回到自己的待处理列表并重新计入待处理数量；原有处理记录、已存成果及会话引用仍保留，也不会恢复已移除的共享成果。其他团队成员看不到你的处理状态；处理状态随同一账号同步，冲突时采用时间更晚的选择。处理过的动态仍可进入结果页存入本地库或加入其他会话；返回动态会保留原来的状态和类型筛选。共享成果被移除时，已处理或有处理历史的记录保留，并标明原成果已不可用；项目结论和会话引用继续保留，由用户自行决定删除个人副本。动态可批量删除，确认删除你的动态记录，处理状态随账号同步，不影响共享成果、项目结论或会话；同一修订不再出现，新修订仍会通知。“查看结果”只打开对应单条当前成果，刷新不会跳到全部成果。

“从共享区移除”会删除团队成果条目及其对应的共享正文或文件，影响有权访问该项目的所有成员。普通成员只能移除自己尚未由管理员接管的提交，组管理员可以移除本组项目的共享成果；服务端再次核对权限和版本。已存入个人成果库的副本、整理记录、原 Session、已有会话引用和增量进度都保留。其他成员的客户端下次同步发现移除后，会生成移除动态；可在移除详情中另行选择保留或删除自己的本地副本。“设为待处理”不能撤销移除，移除合并成果也不会恢复先前被合并的原成果。

“个人成果库”按当前账号和项目组织，包含项目结论、项目标准、方法探索、问题与风险、改进建议。本机保留缓存并随账号同步，Session 和对话仍只保存在本机。每条展示标题、内容和更新时间，来源详情默认收起。来源可以是本地会话整理、共享区内容、项目结论处理或手工记录，不只显示共享区同步内容；本地整理完成后，当前勾选的候选项会自动进入“个人成果库”，不需要先上传。可以手工新建或编辑，也可点击“设置本地别名”保存、修改或清除易读名称。列表、详情、结论推荐和新加入会话的引用名称优先显示别名，同时保留原名；别名不修改原始内容、版本和已有会话快照，重启后仍然保留。暂时不用的结论可“移入历史”，它将不再推荐给新会话，但仍保留并可随时恢复使用。“删除成果”是独立操作：确认后从“个人成果库”和历史列表中移除，不能通过“恢复使用”找回；共享区内容和已有会话引用保持不变。使用中的结论和历史结论都可删除。点击“批量删除成果”可多选或全选当前列表，确认框会列出所选名称；未显示的历史结论不会被一并选中，切换历史显示会清空勾选。项目结论用于阅读和加入会话，不提供下载；共享区中的普通文件和轨迹仍可下载。

管理员在共享区删除或合并来源后，项目结论不会自动删除或移入历史。“共享区已移除”动态里的“查看移除详情”允许保留全部，或明确勾选要删除的条目；默认不勾选。含多个来源的结论会列出提醒和来源，只有明确勾选才从“个人成果库”移除；已有会话的引用快照继续保留。保留与删除的选择在重启后仍生效，删除标记用于防止旧整理草稿重新生成已移除的条目。

两个成果库的区别是可见范围和维护责任：“团队成果库”供项目成员共享，由成员提交、组管理员统一维护；普通成员可修改自己尚未由管理员接管的提交。“个人成果库”是个人保存和使用的成果，由当前账号自己维护，同账号设备间同步。个人整理、改写或删除不会改动团队原文，需明确上传才会发布到团队。这使个人工作中的成果与团队共享版本可以各自保留。

新会话第一次提问时，工作台会列出少量可能有帮助的项目结论。只有用户勾选的内容才会带入会话，也可以不带入直接发送。需要处理已有结论时，先直接勾选 1 至 20 条，再点击“处理选中的 N 条成果”，填写处理要求后点击“生成预处理结果”。支持提炼、对比、改写、生成行动建议或合并；只选一条也可以。留空时默认提炼要点、去除重复并保留分歧。处理期间显示“正在按要求处理”，完成后可修改结果标题和正文；最终确认保存为新结论后，所选原结论才会移入历史。

也可以在结论详情点击“加入会话”，勾选同项目的一个或多个工作会话。已加入的显示勾选且不可取消，关闭的会话不可新增；加入时冻结当时版本，下次提问自动带入，不改动正在运行的任务。结论后来被编辑或移入历史，不会改写已加入会话的快照；同一原生上下文已经接收过的内容不会重复发送。

正常关闭再打开后，本地会话、输入草稿、未处理及历史动态、已关闭的提示、整理任务、本地名称、结论及其历史状态、会话引用快照都会保留；关闭动态提示不等于已读。进行中的 AI 任务和传输会标为中断或可重试，不会在重启后假装仍在运行。远端条目被删除时，未处理的旧通知替换为删除动态；已经处理的历史仍保留，并标明原成果已不可用。

普通成员不需要填写或查看 SSH 指纹。本机第一次连接某个服务器地址和端口时，只需确认地址正确；这份服务器身份信任由本机所有用户端窗口共享，换成员账号不会重复询问，即使密码随后输错也不会重复询问。账号、会话和草稿仍按窗口隔离。正常登录页不显示身份校验说明或技术信息。服务器身份发生变化时，客户端停止登录，并在错误旁显示“重新确认”。需要更换服务器时直接修改地址或端口。

管理员调整成员所属组或项目组管理员身份后，用户点击左侧“刷新工作组与项目”即可加载最新身份。Linux 服务器为使新系统组权限立即生效而断开旧连接时，当前运行中的用户版会使用本次登录的内存凭据恢复连接；自动恢复失败则打开登录窗口，要求重新输入密码。密码仍不落盘。传输任务中途断网或变更身份的安全恢复另见 [待修复问题](待修复问题.md)，不能把身份刷新等同于文件传输已经成功。

所有项目成员都通过“团队成果库”阅读和引用共享成果。“团队”表示项目成员共享，不再按“未操作 / 已操作”或“待整理 / 已整理”区分。团队和个人页统一使用“全部类别”，只从当前库内成果标题开头已有的【类别】生成选项和数量，包括自定义类别、多个类别；无类别内容归入“未分类”。筛选不会列出项目预设但库内不存在的类别，设置本地别名不会改变类别。关键词搜索不会增删类别选项。团队库存在多种内容形式时，另显示“全部内容形式”区分文字成果、共享文件和会话轨迹。可结合关键词筛选，结果数量显示“显示 N / 共 M 条”，点击“清除筛选”恢复；切换筛选会清空多选，防止误操作隐藏条目。

团队页默认仅显示与个人库有差异的成果；组管理员可勾选“包含个人库已有成果”显示团队全部原件，取消勾选恢复差异列表；该选项只改变列表范围，不编辑、整理或导入任何内容。条目提供“编辑成果”和“保存修改”，操作权限仍由服务端校验。组管理员可编辑说明、替换文件，或在二次确认后从共享区移除。多条文字成果可“多选语义合并”，选择工作会话的模型环境生成结果，审阅修改后确认；保存时再次校验来源修订，全部一致才保存并归档原文。文件区中的旧文件可先预览，再点击“加入团队成果库”。文字成果不提供下载，普通文件、附件和轨迹保留下载入口。“使用说明”按存入、删除个人副本、团队更新和查看全部分项展示，默认折叠；左侧“成果整理”集中展示针对对话的整理任务、进度和待确认结果。

## 修改项目设置

选择左侧项目后，打开“设置 → 项目设置”。项目背景、项目目标、验收标准、范围与非目标、交付物与里程碑、现有资料与入口、约束与风险、协作约定均对应 `项目说明.md` 的同名章节。项目组管理员点击“保存项目设置”后生成新版本，并同步刷新共享项目根目录中的 `项目说明.md`；普通成员可查看但不能修改。

## 日常会话

- 每个会话固定绑定创建时的项目和工作目录。模型与执行权限可在会话中调整；切换左侧项目不会改变已有会话。
- 会话标题旁的铅笔按钮可以重命名会话。名称保存在当前账号窗口；之后从该会话上传的成果和轨迹会携带这个来源会话名，其他成员在公共成果和团队动态中看到重命名后的名称。历史上传内容不会被静默改写。
- 输入框按 `Enter` 发送，`Shift+Enter` 换行。多个会话的输入、对话和阶段摘要分别保存。
- 启动、运行或等待授权时可停止任务，顶部显示“已停止”；即使还在检测登录，停止后也不会继续发送。会话记录、引用和未发送输入保留，下一次发送由你决定。重启后，未完成的任务显示中断原因，原有错误继续保留；先检查已有结果再继续。
- 输入框底部可查看或修改当前会话的模型与执行权限，也可为下一条消息选择 Skill 或插件。选择后会在输入框上方显示标签，发送成功后自动清空；切换会话、关闭窗口或发送失败时保留未发送选择。
- Codex 的 Skill 和已安装插件分别按原生 `$skill` 与 `@plugin` 提及发送；Cursor 的 Skill 按原生 `/skill` 调用，每条消息显式选择一个，已配置的 MCP 工具显示在插件区。插件安装、登录、启停和权限仍由 Codex/Cursor 自己管理。
- “AI 参考内容”展示已被当前 AI 对话接收的结论和参考文件，标为“已带入”，并提供阶段摘要入口。发送后这些资料不再留在输入框上方；未接收或发送失败的资料继续作为待带入引用展示。项目说明有新版本时由用户决定是否更新当前会话使用的快照。
- “阶段摘要”是 AI 在本机维护的阶段性目标、发现、证据和待办，供后续对话及整理成果参考。它不会直接上传；用户通常只需查看，发现遗漏时再更正。

## 整理和上传成果

1. 在工作会话右上角点击“整理成果”。工作台先复制当时的对话、阶段摘要和所选资料，整理任务只读取这份冻结副本；原会话可以继续对话，不会改变本次结果。
2. 点击左侧“整理任务”先进入任务列表，列表展示任务标题、来源会话、项目、任务类型（增量或全量）、创建/完成时间、结果数量及当前状态；点击一项后才进入整理结果详情：
   - **正在整理**：可返回原会话继续工作，后台整理不会停止；需要终止时点击“停止整理”。
   - **整理失败**：页面说明影响和恢复方式；点击“重试”。此时上传位置显示“尚未确定”。
   - **已整理好，请确认后上传**：查看结果、上传位置和可选信息，再决定是否上传。
3. 页面顶部始终提供“返回‘会话名’”。较长的已完成结果底部也提供返回入口。返回不会上传内容。
4. “仓库与代码版本（可选）”用于补充 GitHub 仓库链接，或记录当前分支、commit 和未提交改动状态。记录 Git 状态不会上传代码。
5. 模型先合并同主题内容，再按个人组合判断一个主类别，每次最多 5 条、允许 0 条，不逐类别凑数。本机依赖、安装、登录、联网等环境故障不整理。标题采用 `【类别】 简短主题`；正文最多三段、通常 150—250 字，证据详情默认收起，必要验证限制留在正文。用户可在“设置 → 整理分类组合”选择预设或创建自己的组合，也可在上传前纠正类别、修改成果名称；上传后名称修改仅作用于本地别名。旧成果与已有 Session 引用不批量改写。整理结果与整理记录独立保存：删除整理记录不删除成果、共享内容、原 Session 或增量进度，已保存/上传的记录也可删除。
   在“成果整理”列表点击“批量删除记录”，可逐条勾选或全选当前列表，每次最多 100 条；超过时全选入口改为“选择前 100 条”。确认框列出所选记录，正在整理的任务会先停止。部分记录删除失败时，已成功的记录不会回退，保留失败项及原因供重试；正在保存或提交上传的记录需稍后再删除。已提交的上传包及传输重试记录保留。
   左侧“待确认”只统计仍需确认的整理结果；已确认无需保留的空结果、已提交的成果和已保存的合并结果不再计入，即使这些整理记录仍留在列表中。
6. “给团队的补充（可选）”只用于人工补充或更正 AI 整理的内容；保存成功后不常驻提示，失败时才显示重试入口。
7. 类别与目录的映射由程序固定，不能输入任意远端路径。模型按选定组合区分项目结论、标准、需求、设计、探索、验证等类别；手工填写使用相同的类别选择，不调用模型。上传不重新分类，团队成员也不会按自己的组合改写你的共享类别。改进建议不会直接修改项目标准。
8. 点击“确认上传 N 项”后，每项生成独立成果包并进入传输队列，界面逐项显示状态。上传完成后，各项旁边提供“查看上传结果”，可直接跳到公共成果中的对应条目。成果包仅包含该项说明、分类字段、冻结快照标识、可选仓库链接和可选 Git 状态，不包含业务代码、完整对话或参考文件。

会话页的“整理成果”会优先打开该会话最新的未提交任务；从左侧进入“整理任务”时始终先显示完整任务列表，再由用户选择详情。

“传输记录”区分等待上传、上传中、已完成和未完成。网络或本地保存失败时会显示原因；重试从零显示本次进度，并复用原上传目标。已经传到远端但本机未能保存成功记录的任务也需核对或重试，不会直接显示完成。只有成功传输的缓存可清理，原会话、原文件和传输记录保留。

已完成任务可以点击“再次整理”选择范围和本次类别；分类组合与首次整理一样可直接调整。在“调整分类组合”的顶部下拉菜单选择“新建组合…”可创建可复用组合，选择“临时组合（仅本次，不保存）”则只用于这次整理、不修改项目默认分类。已保存的组合在“设置 → 整理分类组合”编辑，展开“管理我的组合”删除未使用的组合。空结果会说明原因，因已有成果而省略时可打开对应成果核对；点击“确认本次无需保留”保存此结果，不创建空成果、不上传。**增量整理**只把上次快照之后新增的会话消息作为本次成果来源，当前阶段摘要和参考资料只用于理解上下文；**全量整理**重新读取发起时的全部会话消息、阶段摘要和参考资料。两者都会生成一条新任务，原任务及已上传内容不覆盖；上次整理后没有新增消息时，增量选项会置灰。

## 轨迹上传

- “轨迹上传”与成果上传分开操作，默认由用户手动确认。
- 轨迹写入当前项目的 `trajectories/账号/`；同组成员可读取已经主动上传的轨迹。
- 轨迹只覆盖工作台采集到的对话和工具事件，不包含不可访问的隐藏推理，也不等同于厂商完整数据库。

## 常见情况

- **当前执行权限限制任务**：在输入框内打开权限选项，查看 Codex 或 Cursor 的原生权限名称及可能影响，再修改权限。修改不会自动重放任务。
- **本机不能访问 Codex/Cursor**：登录团队共享空间时勾选“通过管理端访问 Codex 和 Cursor”，粘贴接入码后登录。工作台会为其启动本机回环代理，并只把本工作台启动的 CLI 进程接入该代理；浏览器和其他程序不受影响。管理员更新接入码后需重新粘贴。
- **本机可以直接访问外网**：保持管理端出口关闭。此时不会创建本机代理，也不会改变 CLI 的网络环境。
- **找不到 Skill 或插件**：先在对应 Codex/Cursor 中安装或启用，再点击能力菜单的刷新。Cursor 插件只有在提供可调用 Skill 或已配置 MCP 工具时才会出现在会话选择中。
- **整理中离开页面**：返回原会话即可，完成后侧栏显示“待确认”并弹出一次提醒；打开整理结果后提醒自动清除。
- **原会话在整理后新增内容**：结果页显示新增消息数；点击“再次整理”后可选只整理新增消息，或基于当前全部内容重新整理。
- **网络中断**：整理结果留在本机，补充内容不会丢失；恢复网络或 CLI 后重试。
- **断网后继续工作**：工作台顶部显示“离线工作中”，本地会话与草稿可继续使用，没有时间限制；上传、公共成果等共享读写需要连接服务器，重新连接时核验权限。
- **团队内容变化**：用户端连接共享空间且窗口可见时，每 15 秒检查一次有权限项目。其他成员上传、更新、删除或合并内容后会出现提示，并持久进入最左侧“动态”；上传、更新和合并可直接查看结果，删除保留题目、项目和检测时间。首次启用此能力会补提示最近 24 小时内每个项目最新的 5 条他人变更，后续同一修订只记录一次。
- **操作提示**：普通顶部提示条几秒后自动消失；队友成果提示保留到查看或关闭。页面内标红的错误信息保留到你处理或重试。
- **没有仓库链接**：方向性判断、结果性结论和方案建议仍可上传，不要求关联代码仓库。
- **关闭会话**：保留对话、未发送输入、阶段摘要和原生会话 ID；重新打开后由用户决定下一步。

成果整理的最新分类边界、个人分类组合、最多 5 条与本机环境排除规则，以及自派任务和任务视角，见 [个人成果分类与任务入口](result-classification.md)。整理记录删除与增量进度的独立关系见 [整理生命周期分析](preparation-lifecycle-audit.md)。

各流程的状态图、可见信息和编辑/删除边界见 [工作流状态与操作边界](workflow-states.md)。更详细的身份与权限边界见 [身份与协作说明](identity-content.md)，CLI 权限见 [CLI 权限与人工授权](cli-permissions.md)。

AI 整理统一面向没有读过原会话的成员写作：标题说明对象，正文先讲结论或当前判断，再给必要依据、限制和有依据的下一步；保留关键数字、单位、未验证事项和分歧。新输出若将 JSON、整段代码或转义文本直接当作正文，会提示重新整理。会话成果、团队合并、个人成果处理和阶段摘要采用同一可读性要求。成果预览按完整句子截取；合并和个人预处理默认显示排版后的正文，点击“编辑内容”再修改。来源编号和追溯记录放在来源详情中。

登录用户端后，“新建工作会话”中可以调整“通过管理端访问 Codex 和 Cursor”；已有会话可从输入框下方的“本机网络 · 登录 / 管理端出口 · 登录”打开同一设置。修改后点击“应用并重新检测”，依次检查管理端出口、CLI 程序、当前工作目录的登录状态、可用模型与额度；无需退出团队账号。出口设置由当前账号窗口的 Codex 和 Cursor 共用，不影响其他账号窗口。运行中的任务保留，待任务结束或自行停止后才能切换出口；仅重新检测可在任务运行期间进行。出口不通与登录状态分别展示，检测失败不会显示旧模型列表为最新结果。接入码保存后可复用，仅更换出口或接入码时需要重新粘贴。
