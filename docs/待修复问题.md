# 待修复问题

这里记录已经确认、但尚未安排在当前改动中修复或实现的问题。完成实现并通过验收后，应将对应条目移出本清单，并在相关验收文档中记录结果。

## 用户端交接文件传输中断后的恢复

- **状态**：待修复。
- **场景**：用户端正在上传或下载交接文件时发生断网，或者管理员在传输期间修改该用户的组成员、组管理员、启停或密码身份，导致现有 SSH/SFTP 连接被断开。
- **当前风险**：身份刷新与工作组重连不能代表传输任务已经安全恢复。任务可能停留在失败或状态不明确阶段；不能假定远端文件完整，也不能在未核对回执、目标路径和哈希时直接续传或重复提交。
- **后续修复要求**：明确区分未开始、部分传输、服务器已接收但客户端未收到回执等状态；重连后重新校验当前身份、原任务绑定账号、项目权限、远端临时文件和内容哈希；只有校验一致时才允许续传或安全重试，否则保留失败记录并要求用户重新发起。
- **验收重点**：分别覆盖上传与下载、普通断网、管理员调整组/角色、停用账号、修改密码、回执丢失和应用重启；确认不会把文件传到其他账号或项目，不会把部分文件当作成功成果，也不会因重试产生重复交接文件。

## 从 Session 当前节点派生 Subsession

- **状态**：待实现。
- **目标**：允许用户从任意工作 Session 的当前上下文创建一个 Subsession，用于并行探索不同方案，而不需要重新描述此前背景。
- **继承边界**：创建时冻结父 Session 截至该节点已经确认的对话、工具结果、项目资料、阶段摘要、所选参考文件和项目绑定，形成子会话的上下文快照。创建动作之后父 Session 与 Subsession 新增的消息、输入和资料互不自动同步。
- **独立状态**：Subsession 必须拥有独立的原生会话标识、运行状态、输入草稿、授权请求、阶段摘要、成果整理和上传任务；不能让父子会话共用一个可变运行时，也不能因关闭、停止或重试其中一个而影响另一个。
- **关系展示**：会话列表需要展示父子层级和派生点，父会话可查看其 Subsession，子会话可返回来源节点；父会话关闭或应用重启后，已经创建的 Subsession 仍可独立恢复。
- **验收重点**：覆盖从空闲、长对话和包含参考资料的 Session 派生；同一节点创建多个 Subsession；父子分别继续对话、切换模型或权限、停止和重开；验证上下文只继承到派生点，不串改输入、消息、授权、成果或上传目标，也不重复执行父会话已经产生副作用的工具操作。

## 共享工作区上传信息的来源与接收对象

- **状态**：待实现。
- **目标**：每一条上传到共享工作区的信息都必须携带并展示“来自哪里”和“发送给谁”，不能只显示内容本身。
- **来源信息**：至少记录上传账号、来源 Session 或本地成果；由公共成果再次整理产生时，还要保留原公共成果及其版本，避免只剩一段无法追溯的文字。
- **接收对象**：明确记录目标工作组和项目；如果产品支持定向发送给成员，还要记录成员账号。不能用本地界面当前选中的项目反推历史接收对象。
- **展示位置**：上传确认、传输记录、公共成果详情和相关动态使用同一组来源/接收信息；历史记录中的值按上传时快照展示，后续重命名不覆盖历史。
- **验收重点**：覆盖 Session 整理上传、手工填写上传、本地结论整理、公共成果二次整理、文件上传、失败重试和应用重启；确认跨组、跨项目以及多人账号窗口不会串用来源或接收对象。
